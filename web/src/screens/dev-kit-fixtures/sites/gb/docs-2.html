Cadencedo

Recurring jobs without a crontab

Cadencedo runs small recurring jobs on one machine and tells you when one of them fails. It is a friendlier alternative to a crontab you have to keep in your head.

Quick start

shell
$ cadencedo add backup 'every day at 03:00' 'tar czf notes.tgz notes'
cadencedo list
Output
backup   every day at 03:00   last run: ok (4 s)

What it does

  • Schedules written in plain words
  • A log for every run
  • One line of output per job, so failures stand out

Installation

Cadencedo is a single executable plus a small background process that checks the schedule once a minute.

  1. Download the archive that matches your system.
  2. Unpack it and copy the executable to a directory on your PATH.
  3. Start the background process with your system's service manager.
shellLinux
tar xf cadencedo-0.8-linux-amd64.tar.gz
sudo mv cadencedo /usr/local/bin/
cadencedo --version
If the version number is printed, the installation worked.

Usage

Add a job

A job has a name, a schedule and a command. Schedules are written in plain words.

cadencedo add backup 'every day at 03:00' 'tar czf notes.tgz notes'
cadencedo add tidy 'every monday' 'rm -r tmp/old'

See what ran

The list command shows every job with the result of its last run. The history command shows the runs of one job with their duration and output.

cadencedo list
cadencedo history backup

Pause and resume

Pausing keeps the job and its history but stops it from running. Useful while you move house or restore a backup.

cadencedo pause backup
cadencedo resume backup

Options

Option Description
--dir Where jobs and logs are kept. Default is a folder in your home.
--quiet Print only failures.
--limit How many runs history shows. Default 10.
--json Machine readable output.
--now Run a job right away as well as on schedule.

Frequently asked questions

Does it need to run as a service?

Yes, a small background process checks the schedule once a minute. The install page shows what to start.

What happens if the computer is off?

A job that was due while the machine was off runs once when it starts again.

Can jobs depend on each other?

Not yet. Chain the commands in a single job for now.
