# Страница подписки: «Мои устройства» и «Добавить устройство» — один вход, один список

Задание: люди не понимают, почему «Добавить устройство» создаёт только ключ AmneziaVPN, а Happ и kl!ck подключаются в другом блоке под карточкой. Этот документ — как это устроено сейчас, почему путает, и как устроено после. Код — `web/src/sub/*`; вид и тон — по `design/subpage-v2/` (токены, компоненты), ничего нового в палитре и шрифтах.

## 1. Как было и почему путало

Возвращающийся посетитель (приложение уже забрало подписку или есть ключи) видел сверху вниз:

1. Карточка «Мои устройства» (счётчик «занято 5 из 10»): строка «Приложения по ссылке · в сети · обновлялись 8 часов назад», строки ключей AmneziaVPN (у каждой на компьютере четыре текстовые кнопки в ряд: «Показать ключ», «Переименовать», «Заменить ключ», «Удалить»), внизу «+ Добавить устройство» с подписью «Ключ выдаётся на каждое устройство отдельно».
2. **Под карточкой** отдельный свёрнутый блок «+ Подключить ещё устройство — Устройство, приложение — и одно нажатие». Внутри — три шага (устройство → приложение → как), и именно тут подключаются Happ и kl!ck.

Три причины путаницы:

- **Два входа с одним смыслом.** «Добавить устройство» и «Подключить ещё устройство» — почти одно и то же слово, а делают разное, и стоят в разных местах страницы.
- **Список врёт про то, что можно добавить.** Строка «Приложения по ссылке» живёт в одном списке с ключами, но добавить в этот список можно только ключ. Человек нажимает «Добавить устройство» на телефоне, чтобы подключить kl!ck, получает форму про «ключ» и «профиль».
- **Нет ответа на главный вопрос «чем подключаться».** Страница сразу задаёт вопросы про платформу и вариант подключения, но не объясняет, что бывает два способа (по ссылке — для приложений; ключом — для роутеров и AmneziaVPN) и чем они различаются по местам лимита.

Кроме того, у ссылки и ключей разные правила по месту, а страница об этом молчит: все приложения по ссылке делят **одно** место, каждый ключ занимает **своё**.

## 2. Новое устройство страницы

Одна карточка «Мои устройства» со **списком** и **одной кнопкой «Добавить устройство»**. Кнопка открывает **шторку** (на телефоне — снизу, на компьютере — окно по центру: тот же `<dialog>`, что уже держит ключи). В шторке первый вопрос — «Как оно будет подключаться?», дальше две ветки. Отдельного блока «Подключить ещё устройство» больше нет.

```
Страница (возвращающийся посетитель)        Первый визит
  статус                                      статус
  серверы                                     «Подключите VPN» — три шага (как было)
  Мои устройства  ← список + «Добавить»       серверы
  помощь                                      Мои устройства  ← список + «Добавить»
                                              помощь
```

Первый визит не меняется: наверху по-прежнему мастер из трёх шагов — это онбординг, а не «ещё одно устройство» (решения v2, п. 1). Меняется только то, где живёт «ещё одно устройство»: оно перешло внутрь «Добавить устройство».

### 2.1. Шторка «Добавить устройство» — шаг 1, выбор способа

Показывается, когда у человека есть **оба** способа. Если способ один — выбор пропускается (ссылка → сразу ветка «по ссылке»; ключ → сразу форма «Новое устройство», как сейчас).

```
┌──────────────────────────────────────┐
│ ─ ─                                  │
│ [+] Добавить устройство           ✕  │
│     Как оно будет подключаться?      │
│                                      │
│ ┌──────────────────────────────────┐ │
│ │ [🔗] Через приложение  Рекомендуем│ │
│ │ Подписка в приложении: одно      │ │
│ │ нажатие, все серверы сразу,      │ │
│ │ обновляется сама.  [kl!ck] [Happ]│ │
│ │ □ Новых мест не занимает       › │ │
│ └──────────────────────────────────┘ │
│ ┌──────────────────────────────────┐ │
│ │ [🔑] Ключом AmneziaVPN           │ │
│ │ Для роутера и приложения         │ │
│ │ AmneziaVPN. Отдельный ключ на    │ │
│ │ каждое устройство.               │ │
│ │ ■ Занимает одно место · ещё 5  › │ │
│ └──────────────────────────────────┘ │
└──────────────────────────────────────┘
```

- Две крупные кнопки-карточки (вся карточка — кнопка, цель ≥ 44 px, на телефоне ≈ 120 px высоты). Первая — рекомендуемая и первая по фокусу.
- Названия приложений — чипы под описанием, из настроек (страница не хардкодит бренды): приложения по ссылке для выбранной платформы, до трёх.
- Строка про место со значком-квадратом (небесная — ссылка, мятная — ключ): **заполненный квадрат — занимает место, пустой — не занимает**; ответ на «сколько места это займёт» стоит в самом выборе.
  - Ссылка, которая уже в списке: «Новых мест не занимает — приложения делят одно».
  - Ссылка, к которой ещё никто не подключался: «Занимает одно место — общее для всех приложений».
  - Ключ: «Занимает одно место · свободно ещё N» (при безлимитном — «Занимает одно место»).

**Важная поправка к исходному предложению.** Ссылка **не бесплатна**: все приложения по ссылке делят одно место, и оно занимается, когда первое приложение забрало подписку (в `access/sub.go` это «неявное устройство»; оно входит в `devices_used`). Лимит применяется только к созданию ключа, подписку по ссылке он не блокирует. Поэтому текст «не занимает отдельного места» верен только для второго и следующих приложений, и страница говорит именно так.

### 2.2. Ветка «Через приложение»

Содержимое бывшего блока «Подключить ещё устройство», целиком, но только про приложения по ссылке:

1. **Ваше устройство** — платформа (плитки на телефоне, «таблетки» на компьютере; определяется по браузеру; «Это не ваш телефон? Вернуть iPhone»).
2. **Приложение** — рекомендуемое крупно, остальные приложения по ссылке под «Другие приложения». Ключевые приложения (AmneziaVPN) сюда не попадают — они в ветке «Ключом».
3. **Как подключиться** — «Установите …», «Добавить одним нажатием», «Не открывается? Скопировать», «Включите VPN в …». Платформа без приложений по ссылке — прежнее «Приложений для … пока нет» и кнопка «Скопировать ссылку».
4. **Подключить другое устройство** — QR-код этой страницы (если включено «QR для второго устройства»): на телефоне свёрнутая строка, на компьютере сразу виден.

Шапка: стрелка «назад» (если был выбор), плитка, название выбранного способа («Через приложение»; у человека только со ссылкой — «Подключить приложение»), строка «Все серверы сразу — подписка обновляется сама», крестик. Шапка липкая: при прокрутке крестик всегда на месте.

В шторке шаг 3 всегда показывает шаги, а не «Готово — приложение получило подписку»: человек пришёл добавить ещё одно устройство, а «Готово» относилось к этому, уже подключённому.

### 2.3. Ветка «Ключом AmneziaVPN»

Прежняя форма «Новое устройство» (платформа, название, вариант подключения → «Создать ключ» → ключ), без изменений, плюс стрелка «назад» в шапке, если был выбор. Лимит, ошибки (`device_limit`, `too_many_requests`, …) и «ключ можно показать снова» — как были.

### 2.4. Что в шторке, когда способ недоступен

Недоступная карточка не прячется (человек должен понять почему) и не кнопка, а спокойная пунктирная карточка с причиной и, где можно, «Написать»:

| Причина | Текст в карточке «Ключом …» |
|---|---|
| Все места заняты | «Все места заняты. Удалите устройство, которым больше не пользуетесь, или напишите — добавим место.» + «Написать» |
| Ключи выдаёт владелец (самообслуживание выключено) | «Ключи AmneziaVPN выдаёт владелец — напишите, для какого устройства нужен.» + «Написать» |
| Нет подходящего профиля | «Сервер ещё настраивается — напишите администратору.» + «Написать» |
| Предпросмотр владельца (нет адреса вызовов) | «В предпросмотре ключи не создаются.» |

Ветка «Через приложение» при этом остаётся рабочей: лимит мест её не блокирует.

## 3. Список устройств

Один список, и в нём видно всё, что занимает место.

```
Мои устройства                          ▮▮▮▮▮▯▯▯▯▯  5 из 10
Ключ — одно место на устройство, приложения по ссылке — одно на всех
┌────────────────────────────────────────────┐
│ [🔗] Приложения по ссылке                  │
│      ● в сети · обновлялись 8 часов назад  │
│      Все приложения по ссылке — одно место │
├────────────────────────────────────────────┤
│ [📱] iPhone                                │
│      iPhone · подключалось 12 минут назад  │
│ [  👁 Показать ключ                 ] [⋯]  │
├────────────────────────────────────────────┤
│ [💻] Router                                │
│      ● нужен новый ключ                    │
│ [  ⟳ Получить новый ключ            ] [⋯]  │
├────────────────────────────────────────────┤
│ [ + Добавить устройство ]                  │
│      Свободно ещё 5 мест                   │
└────────────────────────────────────────────┘
```

### 3.1. Анатомия строки

- **Плитка** слева: ссылка — небесная, ключ — мятная (тон называет способ, не состояние).
- **Название** (`.dev-n`, до двух строк, переносится по словам) и **строка состояния** (`.dev-m`): платформа · «в сети» / «подключалось N назад» / «ещё не подключалось». Состояние — всегда цвет + точка + слово.
- **Одно главное действие** — кнопка: «Показать ключ» (вторичная), «Получить новый ключ» (акцентная, если ключ устарел). Рядом — **«⋯»** (44 × 44, на телефоне 48): «Переименовать», «Заменить ключ», «Удалить» (красное). У строки приложений по ссылке действий нет: она рассказывает, что ссылка в деле; подключать новое приложение — через «Добавить устройство».
- Один и тот же блок действий на телефоне и на компьютере (раньше на компьютере было четыре текстовые кнопки, на телефоне — кнопка с «⋯»). На компьютере он справа в строке, на телефоне — под названием, главная кнопка на всю ширину.
- **Подтверждения остаются в строке**: «Удалить «…»?» (красная кнопка, «Отмена» — спокойная, `alertdialog`), «Заменить ключ «…»?» с пояснением, что старый перестанет работать сразу и нового нужно добавить в приложение заново. Переименование — поле в строке.
- **Меню «⋯»**: `role=menu`, фокус уходит на первый пункт, стрелки вверх/вниз/Home/End двигают по пунктам, Esc и клик мимо закрывают, фокус возвращается на «⋯».

### 3.2. Что занимает место — как это видно

- Счётчик в заголовке («5 из 10», сегменты) — как и был; под заголовком одна строка-подсказка: «Ключ — одно место на устройство, приложения по ссылке — одно на всех» (только когда у человека есть лимит).
- В списке столько строк, сколько занято мест: строка «Приложения по ссылке» — одно место, каждый ключ — одно.
- В строке приложений по ссылке — «Все приложения по ссылке — одно место».
- Под кнопкой «Добавить устройство»: «Свободно ещё N мест»; при полном лимите — предупреждающее «Все места заняты».
- В шторке — чип у каждого способа (п. 2.1).

## 4. Состояния

| Состояние | Список | Кнопка «Добавить устройство» |
|---|---|---|
| Обычное, места есть | ссылка + ключи | открывает выбор способа |
| Мало мест (осталось 1–2) | счётчик в тоне предупреждения при заполнении | как обычно, «Свободно ещё одно место» |
| Лимит достигнут | счётчик «Занято 10 из 10» (предупреждение) | **доступна**, если есть ветка «по ссылке»; в шторке ключ недоступен с причиной. Если способ только ключ — кнопка выключена, под ней прежняя плашка и «Написать» |
| Самообслуживание выключено (владелец выдаёт ключи) | строки ключей без кнопок | есть ссылка → открывает шторку, ключ с причиной «выдаёт владелец». Только ключи → прежняя карточка «Попросите ключ» + «Написать» |
| Предпросмотр владельца (нет адреса вызовов) | строки без кнопок | есть ссылка → шторка (ветка по ссылке работает, ключ — «в предпросмотре не создаются»). Только ключи → кнопки нет, как было |
| Подписка не активна (закончилась, трафик, отключена) | строки видны, ключ не показать и не выдать; переименовать и удалить можно; плашка с причиной | выключена, подпись «Подписка сейчас не активна» (`aria-describedby`) |
| Ключ устарел («нужен новый ключ», в том числе из-за смены DNS) | карточка «Нужен новый ключ» над серверами и метка в строке | главная кнопка строки — «Получить новый ключ» |
| Нет ни ссылки, ни ключей | карточки нет | — |
| Пока ни одного ключа, есть только ссылка | одна строка «Приложения по ссылке» | → сразу ветка «по ссылке» (выбирать не из чего) |
| Пока ни одного ключа, ключи единственный способ | прежняя строка «Ключи AmneziaVPN — пока ни одного» | → сразу форма «Новое устройство» |

Пароль страницы, предпросмотр владельца, `show_qr`, язык RU/EN и тема работают как раньше: они не затронуты (пароль — отдельный экран, остальное — те же данные страницы).

## 5. Телефон (390 px) — главное

- Одна колонка 358 px полезной ширины, никакого горизонтального скролла. Шторка снизу: её шапка липкая, содержимое прокручивается (`max-height: 100dvh − 24px`), закрывается крестиком, Esc или касанием подложки.
- Выбор способа — две карточки друг под другом, всё читается без прокрутки на экране 390 × 844.
- Строка ключа: название и состояние сверху, кнопка «Показать ключ» на всю ширину с «⋯» справа — как в макетах v2 (`devices-01-row-actions`).
- Ветка «по ссылке» на телефоне идёт сверху вниз: плитки платформ (5 × 70 px), приложение, шаги, свёрнутый «Подключить другое устройство». Длинные названия приложений и устройств переносятся.
- Цель касания везде ≥ 44 px; кнопка «⋯» не прячется под длинным названием.

## 6. Фокус, доступность, безопасность

- Страница пересобирается при каждом изменении и возвращает фокус по `data-k`. Ключи остаются уникальными: кнопка в списке — `dev-add` (раньше `amz-add`, он же стоял в шаге мастера на первом визите — дубль), мастер — `amz-add`, шторка — с префиксом `add-` (`add-way-link`, `add-way-key`, `add-back`, `add-plat-*`, `add-app-*`, `add-link-add`, `add-qr-row`, …); блок действий строки один на оба размера: `amz-show-<id>`, `amz-renew-<id>`, `amz-more-<id>`, `amz-m-ren-<id>`, `amz-m-rot-<id>`, `amz-m-del-<id>`.
- Шторка — тот же `<dialog>` с `showModal()`: страница позади инертна, Esc закрывает, фокус возвращается на «Добавить устройство» (`dev-add`). При открытии фокус на первой карточке выбора.
- Недоступные способы — не `disabled`-кнопки без объяснения, а карточки с причиной (экранный читатель читает причину).
- CSP не затронута: один встроенный скрипт, никаких внешних ресурсов; всё, что только для разработки (`?case=`, `&sheet=`, `&menu=`), — под `import.meta.env.DEV` и в сборку не попадает.
- Тексты на «вы» (RU) и на «you» (EN), без названий приложений в словаре — они приходят из настроек.

## 7. Что осталось как было

Мастер первого визита; серверы и DNS (в том числе «Обновите ключи на N устройствах»); карточка «Нужен новый ключ»; шторка с ключом (QR, файл, `vpn://`); переименование, замена ключа и удаление с подтверждением; пароль страницы; предпросмотр владельца; тема и язык; сообщения об ошибках самообслуживания. Данные страницы (`MgData`) не менялись — серверная часть нетронута.

## 8. Открытые вопросы владельцу

- Мастер первого визита по-прежнему показывает ключевые приложения в одном списке со ссылочными (как в v2). Его тоже можно перестроить на тот же вопрос «как подключать», если после этой правки останутся жалобы.
- «Для роутера» в описании ключа — общий; конкретные названия роутеров в словарь не пишем.

## 9. Как посмотреть и проверить

- Сборка для разработки: `cd web; pnpm exec vite -c vite.sub.config.ts`, затем `/sub.html?case=<имя>&as=ios|android|windows|macos&theme=light|dark&lang=ru|en`. Новые образцы данных (выдуманные): `devices-rich` (ссылка в сети + 4 ключа, 5 из 10), `devices-near` (одно место осталось), `devices-full` (лимит), `preview` (предпросмотр владельца); остальные — прежние (`amnezia-off`, `stale-dns`, `expired`, `happ`, `keys-only`, …).
- Только для разработки (под `import.meta.env.DEV`, в `web/dist/sub.html` их нет): `&sheet=pick|link|key` открывает шторку, `&menu=<id>` — меню строки, `&ask=remove:<id>|rotate:<id>` — вопрос в строке.
- Снимки (выдуманные данные, 390 и 1280 px, светлая и тёмная тема): `design/screens/subpage-devices/{phone,desktop}-{dark,light}-<состояние>.png`. В репозиторий они не кладутся (≈9 МБ, как и снимки v2).
- Тесты: `web/src/sub/add.test.ts` (шторка, ветки, недоступные способы, уникальность `data-k` на всех образцах), обновлены `amz.test.ts`, `connect.test.ts`, `sub.test.ts`.
