# Пагинация длинных списков и страница «Обновления»

Заметки к двум правкам админки (`web/`). Скриншоты на выдуманных данных — в `design/screens/`; их делает
`web/src/screens/dev-kit-redesign.tsx` (страница `/dev-kit` при `pnpm dev`).

## 1. Пагинация

### Обзор списков

| Список | Откуда данные | Ограничен? | Что сделано |
|---|---|---|---|
| Здоровье → Алерты → «История · 7 дней» | `ListAlerts.history`, окно до 30 дней, не больше 200 строк, приходит целиком | да (200) | страницы на клиенте, 20/50/100, `?page=&size=` |
| Пользователи | `ListUsers`, keyset по имени (`page_token`), в ответе `counts` по фильтрам | нет | нумерованные страницы; итог = счётчик выбранного фильтра; **аддитивное** поле `offset` в `ListUsersRequest` (proto + store + тест), 25/50/100 |
| Настройки → Аудит | `ListAudit`, курсор `before_id` / `next_before_id`, без итога | нет | курсорный пейджер Новее / Старее, 25/50/100, `?before=&size=` |
| Нода → События | `ListEvents`, `before_id` + `has_more`, фильтры на сервере | нет | тот же курсорный пейджер под карточками дней |
| Интеграции → «Недавние решения» (план/одобрения MCP) | `ListApprovals.history_limit` (было 30, показывалось 8 + «Показать ещё») | да | страницы по 10 на клиенте; панель теперь просит последние 100 (максимум 200), иначе листать нечего |
| Настройки → Бэкапы → «Последние бэкапы» | `ListBackups`, целиком, число зависит от срока хранения (при «без удаления» — не ограничено) | условно | страницы по 10 на клиенте |
| Обзор → события | `eventLimit: 6` | да (6) | не трогаем: это превью |
| Токены API (старые) | живые + свёрнутый список отозванных | малый | не трогаем: уже свёрнут |
| Сессии, ноды, профили, группы, DNS-пресеты, правила подписок | настройки/справочники, десятки строк | малые | не трогаем (правила ещё и переставляются порядком) |
| Задачи установки нод, события установки (`ListNodeProvisions*`) | в админке не показываются списком: опрос одного задания по `after_id` во время установки | — | нет списка — нечего листать |
| Доступ к серверам нод | по одной строке на ноду | малый | не трогаем |

Изменение API одно: `ListUsersRequest.offset` (uint32 = 6, максимум 100000). Старые клиенты и MCP-инструмент
`users_search` работают как раньше (`page_token` не тронут, `offset` по умолчанию 0).

### Курсорные списки: Новее / Старее, а не «Показать ещё»

Журнал читают сверху вниз и редко глубже пары страниц. «Показать ещё» растит страницу без предела (DOM, прокрутка),
не помнит место после перезагрузки и ломает «назад». Пейджер держит место в URL (`?before=`), страница ограничена,
ссылку можно отправить. Цена: у курсора нет «назад» из коробки. Путь назад (`pagerTrail`) лежит в `state` записи
истории: «Новее» возвращает ровно на ту страницу, откуда пришли, и после перезагрузки, и через «назад» браузера.
Страница, открытая по ссылке, пути не знает: тогда кнопка честно называется «К новым» и ведёт на самую новую.
Номер страницы и «Записи 51–100» показываются, только если путь начинается с первой страницы; иначе «37 записей».

### Компонент

Один: `web/src/components/ui/pagination.tsx` (`Pagination` для числа известного размера, `CursorPagination` для журнала),
логика и URL — `web/src/lib/paging.ts` (`usePaging`, `useCursorPaging`, `validatePaging`, `pageItems`).

```
┌──────────────────────────────────────────────────────────────────────┐
│ …строки…                                                             │
├──────────────────────────────────────────────────────────────────────┤  hairline, внутри карточки списка
│ Показано 21–40 из 137        [ 20 на странице ▾]  ‹ 1 … 4 5 6 … 7 ›  │  широкий экран
└──────────────────────────────────────────────────────────────────────┘
телефон:  «Показано 21–40 из 137»  [20 на странице ▾]
          [‹ Назад]      3 из 7      [Вперёд ›]       (кнопки 40 px, делят строку)
журнал:   «Записи 51–100»  [50 на странице ▾]  [‹ Новее]  Страница 2  [Старее ›]
```

- Всегда ровно 7 слотов (1, 2, 3, 4, 5, …, N → 1, …, p−1, p, p+1, …, N → 1, …, N−4 … N): ширина пейджера не прыгает.
- Текущая страница — `bg-accent-soft` + `border-accent-line`, как выбранный чип фильтра; остальные — тихие. Стрелки — квадраты 32 px с границей.
- `nav` с `aria-label` (по умолчанию «Страницы», в списках — имя списка), `aria-current="page"` у текущей,
  `aria-label="Страница 3"`, у недоступных стрелок настоящий `disabled`, сводка в `aria-live="polite"`, `aria-busy` пока грузится следующая.
- Список короче самого малого размера страницы — пейджера нет. Размер выше числа строк — остаётся сводка и выбор размера.
- Без прыжка при загрузке: серверные списки идут через `placeholderData: keepPreviousData` — старые строки стоят
  (приглушены, `aria-busy`), пока приходит следующая страница. Смена страницы прокручивает карточку к первой строке, если её верх ушёл вверх.
- Состояние в URL: `?page=3&size=50` (числовые), `?before=1234&size=50` (журналы). Страница 1 и размер по умолчанию в URL не пишутся.
  Страница в клиентских списках зажимается в `1..последняя` (строк могло убавиться); смена фильтра/поиска/размера возвращает на первую.
  Валидаторы маршрутов (`/health`, `/users`, `/nodes/$id` вкладка events, `/settings/$section`, `/integrations`) пропускают только корректные значения.
- Строки RU/EN — `pager.*` в `web/src/i18n/en.ts` / `ru.ts`.

Ограничение: в списке «Пользователи» фильтр и поиск живут в состоянии, не в URL (так было), поэтому после перезагрузки
страница откроется в «Все». Аудит и события: смена фильтра сбрасывает курсор.

## 2. Страница «Обновления»

### Что не работало

- Полоски во всю ширину у каждой ноды почти ничего не говорили.
- Действия в строке: «Обновить» (контур) над «Откатить» (без обводки) — разный вес, нестабильный порядок.
- Самое частое («довести все ноды до новой версии») нигде не было кнопкой: только по одной ноде.
- Длинные абзацы (описание пакета, «Эта панель», подсказки в шапке, плашка «обновить вручную» повторяла шапку).
- Обновление самой панели и пакет были в самом низу.
- Столбцы таблицы разной ширины.

### Раскладка (сверху вниз, по важности)

1. **Верхняя карточка** — «где флот и что делать»: «2 из 4 нод на v0.1.24»; полоса — отрезок на ноду, цвет по состоянию
   (актуальна / можно обновить / обновляется / внимание / вручную / не в сети) и легенда счётчиков. Одна главная кнопка
   **«Обновить N нод»** (только владельцу, при доверенном пакете и без идущей раскатки). Во время раскатки вместо неё
   Пауза / Продолжить / Отменить, а полоса показывает шаги раскатки. Остальные состояния (нет пакета, не прошёл проверку,
   нужен ручной шаг, требует внимания) — как раньше, но короче.
   В нижней строке карточки — **Пакет релиза**: вердикт проверки подписи, версия · дата сборки · срок, «Перечитать папку»,
   «Подробности» (файлы, причина отказа, шаги). Свёрнуто, пока пакет доверенный; раскрывается само, если пакета нет или он не прошёл проверку.
2. **Раскатка** — идущая стоит сразу под карточкой: этап слева (Канарейка / Пачка N), справа фишки нод
   («nl1 · обновлена · v0.1.24», «de1 · проверка…», «fi1 · ждёт»); причины сбоя — одной строкой под этапом. Законченная и хорошая
   сворачивается в строку «Последняя раскатка · Готово · Показать этапы» и уходит под список нод; закончившаяся плохо остаётся раскрытой.
3. **Эта панель** — одна строка: версия, дата, состояние, «Проверить GitHub». Вышел подписанный релиз — карточка в акценте и в ней
   **«Обновить панель»**. Ключ, SHA-256 и длинное пояснение — в «Подробностях»; панель без systemd раскрывает шаги сама.
4. **Ноды** — одна таблица с фиксированными колонками (Нода / Версия / Состояние / Последнее обновление / действия).
   «Последнее обновление» в одну строку («v0.1.22 → v0.1.23 · 9 ч назад»), причина — только при откате/сбое. В строке
   одна основная кнопка («Обновить», либо «Расписание», если оно назначено) и меню «⋯» с «Запланировать…» и «Откатить…».
   Откат по-прежнему подтверждается окном с версией, к которой вернётся нода. На телефоне — карточки, меню рядом с состоянием.

«Обновить N нод» открывает окно: все обновляемые ноды с галочками, канарейка названа (меньше всего людей онлайн, как у панели),
фраза про 5 минут и пачки, предупреждение про перезапуск и откат. Вызов — тот же `StartRollout`: закреплён за показанным пакетом,
со step-up. Раньше пакетной кнопки не было сознательно (тесты это утверждали); теперь она есть по просьбе владельца, но через явное окно.

### Что убрано или сокращено

Плашка «С пометкой “Обновить вручную”» (дублировала шапку), длинные тексты шапки и пакета (остались, но в «Подробностях»),
нумерованные кружки этапов и линейки на всю ширину. Все возможности сохранены: этапы, канарейка, расписание, откат, проверки подписи, step-up.

### Оставлено владельцу

- Расписание «всей раскатки» одним временем: в API есть только расписание по ноде (`ScheduleNodeUpdate`), раскатка с канарейкой
  по времени потребовала бы нового вызова. Сейчас: «Запланировать…» в меню строки.
- Размер пачки в окне раскатки не выбирается (по умолчанию панели: 1, при ≥5 нод — 2).
