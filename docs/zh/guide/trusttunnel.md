TrustTunnel 是一种运行在普通 HTTPS（HTTP/2，也可按需启用 HTTP/3）之内并使用真实证书的 VPN。对外部观察者来说，节点的这个端口就是一个网站。用户通过**官方 TrustTunnel 应用**连接，各个平台和路由器都有；也可以用 Mistgate 应用。服务器端是节点 Agent 内部 Mistgate 自己的引擎，节点上没有别人的程序。本页列出 TrustTunnel 协议配置的设置，以及用户如何获得密钥；协议配置如何创建并部署到节点，见[协议配置](profiles.md)。

> **注意：** TrustTunnel 是**实验性**功能。它在 Mistgate 中是新加入的，尚未在实际环境中得到验证；面板在选择协议的位置会注明它是实验性的。设置和行为之后仍可能变化。Cloudflare 版本中没有它。

## 它是什么，不是什么

它是完整的 VPN（TCP 和 UDP 流量、DNS），在 iOS、Android、Windows、macOS、Linux 和路由器上都有自己的应用。应用通过 `tt://` 链接或二维码导入服务器。这些应用列在 <https://github.com/TrustTunnel/TrustTunnel> 的 README 的 Clients 一节中：App Store（iOS 和 macOS）、Google Play（Android），以及适用于 Linux、macOS、Windows 和路由器的客户端。

它做不到的事：

- **它不保证能通过其他协议通不过的封锁。** 在测试台上，HTTP/2 上的数据流在最初几 KB 之后就冻结了，与其他任何 TCP 数据流在“16 KB 后冻结”规则下的表现相同；而 HTTP/3（UDP）同时可以通过。所以 HTTP/2 与 TCP 上的 VLESS 一样容易受影响，HTTP/3 则是在 UDP 未被封锁的地方绕过该规则的办法。
- **它不能躲过流量分析。** 隧道是 TLS 套 TLS，细心的观察者能把它与真实网站区分开。真实证书和端口上的真实网站，只让端口乍看起来普通，并不改变里面流量的样子。
- **绿色的检查不能证明它对你的用户有效。** 面板从自己的服务器检查，位于任何国家之外。在做出承诺之前，请在重要的网络上试一试。

把它当作又一种连接方式，主要面向官方应用和路由器，与 Hysteria2、VLESS 并存（[协议配置](profiles.md)）。

## 它需要什么

- **域名和公共证书**，用于官方应用的 `tt://` 链接。应用按通常方式校验服务器证书，所以节点需要一个域名和对应的 Let's Encrypt 证书。没有域名时只有 Mistgate 应用能连接（见[自签名证书](#自签名证书)）。
- **一个 TCP 端口**，默认 443：可以是空闲的，也可以按名称与另一个服务共用（[一个 443，多个服务共用](shared-port.md)），承载 HTTP/2。
- **一个编号相同的空闲 UDP 端口用于 HTTP/3**（如果启用 HTTP/3）。UDP 443 通常被 Hysteria2 占用，所以 HTTP/3 **默认关闭**。只有 Agent 足够新的节点才会启动它；面板不会把该协议配置下发给较旧的 Agent，服务器显示为未启动。

## 设置

编辑器把设置放在**基础**和**高级**下。关键设置会改变用户已有的链接，所以保存前编辑器会先询问（请参阅[协议配置](profiles.md)）。

| 设置 | 默认值 | 关键 | 作用 |
|:--|:--|:--|:--|
| **端口** | 443 | 是 | HTTP/2 使用的 TCP 端口，1 到 65535。启用 HTTP/3 时，UDP 使用相同的编号。 |
| **HTTP/3** | 关 | 是 | 同时在同一端口监听 UDP。`tt://` 链接始终是 HTTP/2；HTTP/3 供 Mistgate 应用使用。 |
| **SNI 覆盖** | 留空 | 是 | 证书名称。留空表示节点地址，此时该地址必须是域名。 |
| **证书** | Let's Encrypt | 是 | **Let's Encrypt** 或**自签名（固定指纹）**。见下文。 |
| **出口** | 直连 | 是 | **直连**或 **WARP**：节点如何访问用户打开的网站（[WARP](warp.md)）。 |

在 SNI 覆盖中请填你自己的域名，不要填别人的名称：应用会按这个名称校验证书，而 Let's Encrypt 只为你自己的域名签发；别人的名称配自签名证书会暴露节点。挑选邻居的名称只用于 VLESS 协议配置的 REALITY 目标，见 [VLESS](vless.md#查找节点附近的站点)。

TrustTunnel 的 HTTP/2 使用 TCP 端口；当每个服务都有自己的名称（其**域名 (SNI)**）、且其中一个展示节点自己的站点时，VLESS 或 MTProto 可以放在同一端口上与它并排：见[一个 443，多个服务共用](shared-port.md)。HTTP/3 属于 UDP，永远不共用。Hysteria2 在 TCP 443 上显示的内置站点会让位给 TrustTunnel，无论端口是否共用：面板会用 `hy2_site_taken` 警告（“该 TCP 端口上的 Hysteria2 站点已让位给 TrustTunnel”），该站点的证书继续续期，Hysteria2 本身不受影响。

## 添加协议配置

1. 打开**协议配置**，点击**新建协议配置**。选择 **TrustTunnel** 卡片（卡片上注明是实验性的），表单随即打开。
2. 设置**端口**；只有节点的 UDP 端口空闲时才启用 **HTTP/3**。**证书**保持 **Let's Encrypt**。
3. 给协议配置起个名称，部署到节点，并添加到分组。用户只有通过分组才能获得 TrustTunnel，且该分组需要在用户可使用的节点上带有该协议配置。
4. **创建协议配置**。

只有 IP 地址的节点会被 `acme_needs_domain` 拒绝：请为该节点上的协议配置输入域名，或选择**自签名（固定指纹）**。

## 自签名证书

选择**自签名（固定指纹）**时，节点自己生成证书，Mistgate 应用按指纹校验它。官方应用做不到这一点，所以这样的服务器**不会生成 `tt://` 链接**：在用户的列表里，它那一行显示“需要带公共证书的域名”。适用于没有域名、只服务 Mistgate 应用的节点。

## 把 TrustTunnel 给用户

**TrustTunnel** 是用户应用开关之一，位于用户表单和用户卡片中，默认关闭。

- 用户处于活动状态时，打开开关会立即生成用户的密钥。否则，或密钥被撤销后，卡片上有按钮**签发密钥**。
- 密钥是用户的一台设备，**占用设备上限中的一个名额**，与 AmneziaVPN 密钥相同，与 Telegram 密钥不同。达到上限时，签发会因设备上限错误被拒绝（见[用户与分组](users-and-groups.md#设备和设备上限)）。已禁用的用户也不会获得密钥。
- 用户被禁用、已过期或超出配额时，密钥处于**暂停**状态：链接失效，随用户的访问权限恢复而恢复。
- 关闭开关会撤销密钥。
- **任何 `tt://` 链接都不会进入订阅。** Happ、Mihomo 等应用读不了它。链接来自用户自己的页面和管理后台。Mistgate 应用会自动获得路径（[客户端应用](client-apps.md#各应用会收到什么)）。

## 用户在哪里找到链接

- **用户自己的页面。** **TrustTunnel** 区块：每个合适的服务器一条 `tt://` 链接、一个二维码和**复制链接**。用户安装 TrustTunnel 应用，扫描二维码或打开链接，服务器就出现在应用里。参见[用户页面](user-page.md#telegram-代理)。
- **管理后台。** 在用户卡片上，**TrustTunnel** 区块列出同样的链接，附二维码、**复制**，以及按钮**签发密钥**和**撤销密钥**。

链接带有用户在节点上的名称和密码，所以链接就是密钥：谁拿到它，谁就能使用这个 VPN。请像对待密码一样对待它。链接始终是 HTTP/2。

## 撤销密钥

**撤销密钥**会收回密钥。链接失效，节点在下一次更新时丢弃该凭据，设备上限中的名额重新空出，开关保持打开。**签发密钥**会生成新的；用户在应用里添加新链接。链接泄露时使用。

## 陌生人在端口上看到什么

端口的应答与普通 HTTPS 网站一样：`GET` 返回节点的伪装站点（[自有伪装站点](decoy-site.md)），与 Hysteria2 和 VLESS 上的相同。没有正确密码的隧道请求会得到该站点的 404 页面。错误密码和不存在的用户得到完全相同的应答，所以探测者无法得知哪些名称存在。

## 中转、流量与限制

- **中转。** [中转](relays.md)只通过 **HTTP/2** 转发 TrustTunnel 服务器：它的孪生项只有 TCP。经中转的 `tt://` 链接会标注“经 RU”（中转所在国家），并且和所有链接一样是 HTTP/2。
- **流量和速度。** 流量按用户和设备统计，用户卡片上的速度限制与其他协议一样有效。
- **禁用用户**会在几秒内关闭其连接，不影响其他任何人。

## 尚未实现

- **隧道内的 ping 和 ICMP。** 都不可用。
- **基于 HTTP/1.1 的隧道。** 没有；应用使用 HTTP/2 或 HTTP/3。
- **经中转的 HTTP/3**，以及 `tt://` 链接中的 HTTP/3。
- **`tt://` 链接中的自签名证书。** 需要域名和公共证书。
- **Cloudflare 版本。** 那里不提供 TrustTunnel。
