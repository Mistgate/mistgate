title: 用户与分组
description: 如何创建和管理用户（配额、有效期、流量、设备和访问权限）、分组的作用，以及如何在分组间移动用户。
---

用户是获得访问权限的人。每个用户属于一个分组，分组决定他们可以使用哪些协议配置。此外，每个用户都有自己的限制（流量配额、有效期、设备上限）、应用开关和可用节点选择。**用户**部分包含两个标签页：**用户**和**分组**。

## 用户可以获得什么

满足以下所有条件时，用户才能使用一台服务器：

- 用户处于有效状态（未停用、有效期未结束、未超出流量配额）；
- 协议配置属于该用户所在的分组；
- 协议配置部署在用户可以使用的节点上（所有节点，或专门为该用户选择的节点）；
- 该节点上的协议配置已启用，且状态为运行中或启动中；
- 用户开启的某个应用开关允许使用此协议。

这些设置发生任何更改后，都会立即下发到节点。

## 两种连接方式

| | 通过订阅链接 | 通过 AmneziaWG 密钥 |
|:--|:--|:--|
| 应用 | 订阅类应用（Happ 和其他读取分享链接的应用、基于 mihomo 内核的应用） | AmneziaVPN 和 AmneziaWG 应用 |
| 协议 | Hysteria2（基于 mihomo 内核的应用也支持 AmneziaWG） | AmneziaWG |
| 用户需要添加什么 | 每台设备使用一个链接 | 每台设备使用独立密钥 |
| 更新方式 | 应用会自行刷新链接 | 手动重新导入密钥 |
| 用户上的开关 | 按订阅类应用名称显示的开关（「Happ」或在订阅设置中指定的应用名称） | **AmneziaVPN** |

这两种方式会并列显示在用户页面上。至少要开启一个开关。参见[订阅](subscriptions.md)、[AmneziaWG](amneziawg.md) 和 [用户页面](user-page.md)。

## 用户标签页

页眉会显示用户人数和在线人数。列表上方有：

- **名称或分组**：按用户名称或分组名称搜索；
- **全部**、**当前在线**、**即将到期**（7 天内）、**超出配额**和**超出设备上限**标签，每个标签旁都会显示数量。**超出设备上限**只在有人超出上限时显示（或在它被选中时显示）：把[设备上限](subscriptions.md#订阅类应用的设备上限)从**仅计数**切换到**限制**之前，先看这个列表。

| 列 | 显示内容 |
|:--|:--|
| **名称** | 用户名称；如果用户暂时无法使用任何内容（分组中的协议配置未部署到任何节点，或没有协议配置符合已开启的应用和所选节点），则显示**无访问权限**。 |
| **状态** | **有效**、**已过期**、**超出配额**、**设备上限**或**已停用**。 |
| **应用** | 用户过去 7 天实际使用的应用：**Happ**、**Amnezia** 或 **两者**。 |
| **分组** | 用户所属分组。 |
| **设备** | 已使用设备数和设备上限：上限已满时为琥珀色，用户超出上限时为红色（「6/5」）。 |
| **流量** | 当前周期已用流量，以及与配额对比的进度条。 |
| **有效期** | 剩余天数；∞ 表示永不过期。 |
| **最后在线** | 在线时显示「现在」，否则显示距离上次在线的时间。 |
| **节点** | 最近一次连接所在的节点。 |

**设备上限**不是单独的状态：它表示用户仍处于有效状态，但设备数已达到上限。已停用的用户始终显示**已停用**；之后依次显示**已过期**和**超出配额**。

列表按页显示，每页 50 个用户（也可请求每页 25 或 100 个）：卡片下方会显示「显示第 51–100 条，共 137 条」，以及页码按钮和每页行数。筛选或搜索会对各自的结果分页；页码会保存在地址中。

### 批量操作

勾选列表中的用户（或当前页的所有用户）后，会出现操作栏：「已选择：3」。

- **续期 30 天**会从今天和当前有效期结束日期中较晚的日期起，为每个用户延长 30 天。没有有效期的用户会被跳过：延长操作会给他们设置有效期。
- **停用**会立即停止这些用户的访问。消息中会显示**撤销**，持续几秒。
- **取消**会清除所选用户。

API 还支持在一次调用中启用、删除多个用户并重置他们的流量。参见 [API](../reference/api.md)。

## 创建用户

打开**新建用户**后会显示表单：

| 字段 | 默认值 | 说明 |
|:--|:--|:--|
| **名称** | | 必填，不能重复（不区分大小写），最多 64 个字符。 |
| **分组** | 如果存在「所有人」分组则选中它，否则选中第一个分组 | 下方的**可获得**会说明此分组的用户能获得什么：订阅链接和 AmneziaVPN 密钥，以及部署这些内容的节点数。如果用户将无法获得任何内容，会显示红色提示。**编辑分组**会打开该分组。 |
| **流量配额** | 100 GB | 每次调整 10 GB；设为 0 表示**不限**。下方提示会说明周期。 |
| **重置周期** | **每月** | **每天**、**每周**、**每月**或**从不**。参见[配额周期](#配额周期)。 |
| **有效期** | 30 天 | 每次调整 5 天；设为 0 表示永不过期。之后访问会暂停。 |
| **设备** | 5 | 范围为 1–100，表示可连接的设备数。 |
| **订阅中的应用** | 分组提供的应用 | 订阅类应用开关和 **AmneziaVPN**。在你更改之前，开关会遵循分组设置：如果分组无法提供某种连接方式，该开关默认关闭，并在下方说明原因。 |
| **所有节点** | 开启 | 新节点会自动加入。关闭后需要勾选节点；之后新增的节点不会自动加入。 |
| **更多** | 折叠 | **DNS**：用户自己的预设，留空时继承（参见[DNS](dns.md)）。**限速**：**每用户限速**和**每设备限速**，默认都不限速（参见[限制](#限制)）。 |

如果还没有分组，表单会直接显示分组表单。点击**创建**后会创建用户并打开链接窗口；系统会复制链接（如果页面需要密码，也会复制页面密码），供你发送给用户。如果用户暂时无法使用任何内容，链接发送前窗口会说明原因。

GB 采用十进制单位：100 GB 等于 100,000,000,000 字节。

## 用户卡片

页眉显示名称、状态、应用、分组和有效期（「截至 10 月 12 日 · 14 天」），以及三个按钮：**停用**（或**启用**）、**续期 30 天**（没有有效期的用户无法使用此按钮）和**订阅链接**。

下方的信息条会说明访问受限的原因，并提供快速解决方法：

| 原因 | 信息条 | 按钮 |
|:--|:--|:--|
| 有效期已结束 | 「有效期已于 3 天前结束，访问已暂停。」 | **续期 30 天** |
| 流量配额已用完 | 「100 GB 的流量配额已用完，访问已暂停；配额重置或你调高配额后即可恢复」 | **+50 GB** |
| 设备上限 | 「已达设备上限（5），新设备无法连接」 | **+1 台设备** |

在**仅计数**模式下不会拒绝任何设备，所以不显示这条信息条。超出上限的用户会在**设备**标题下看到一行浅色文字：「目前设备上限只计数：超出上限的应用仍可连接」，并附有**上限模式**链接。

### 流量

显示当前周期的已用流量与配额、重置周期（「每周重置」）和下次重置时间（按你的时区）、过去 14 天的图表，以及各节点和协议的流量。

### 设备

标题显示已使用设备数和设备上限（「3 / 5」）：上限已满时为琥珀色，用户超出上限时为红色。面板按设备计数，每台设备占一个名额；设备是什么、如何出现，参见[设备和设备上限](#设备和设备上限)。卡片分为以下几部分：

- **订阅类应用**：每个提供设备 ID 的应用占一行。这一行显示名称（设备型号，或你起的名称）和一行浅色文字：「在线」及其连接的服务器（「de1, nl1」），或应用上次获取链接是多久以前。把鼠标移到这一行上，可以看到系统和应用及其版本（「iOS 18.1 · Happ 3.4.2」）；**⋯** 菜单还会显示设备出现的时间、设备的累计流量和指纹。同一台设备同时连接两台服务器，说明它的配置被复制到了其他设备；这一行在悬停时会这样提示。
- **未提供设备 ID 的应用**：所有不提供设备 ID 的订阅类应用（Hiddify、v2rayNG 之类，或关闭了 HWID 的 Happ）共用一行，也共用一个名额。在**严格**模式下没有这个名额，这些应用无法连接。
- **AmneziaVPN 密钥**：每台设备占一行，显示平台、协议配置和最近连接时间；提供**显示密钥**，菜单中有**删除**…。**添加设备**会生成新密钥。**已过时**标记表示设备需要重新获取配置。参见[AmneziaWG](amneziawg.md)。
- **已拉黑（N）**：折叠显示，见下文。

订阅类应用的 **⋯** 菜单：

- **重命名**…：自定义名称，显示在这里和用户页面上。
- **删除**…：应用断开连接，密钥随即失效，名额空出。如果应用再次获取链接且有空余名额，它会作为新设备回来，并获得新密钥。
- **拉黑**…：与**删除**…相同，并且在你解除拉黑之前，这个设备 ID 无法再次注册，即使应用再次获取链接也一样。该用户的其他设备不受影响。只有提供设备 ID 的应用可以拉黑；共用名额和 AmneziaVPN 密钥不能拉黑。设备 ID 由应用自己报告：报告其他 ID 的应用算作新设备，会像其他设备一样占用空余名额。如果链接被转给了别人，请拉黑对方的设备，并同时**生成新链接**。

**已拉黑（N）**列出被拉黑的设备。**解除拉黑**会让该设备重新可用；它在下次更新订阅时获得新密钥。共用名额的菜单里有**断开连接**…：这些应用会立即断开，并在下次更新时重新连接。

AmneziaVPN 密钥上的**删除**会断开该设备，并从所有节点移除它的密钥。

### 订阅页面

**订阅页面上显示的名称**：用户页面向用户问候时使用的名称，最多 64 个字符。留空时使用账户名称；字段下方会显示问候语（「页面问候语：…」）。**保存名称**会保存此名称。任何获得链接的人都会看到这个名称；其他用户设置不会因此改变。参见[用户页面](user-page.md)。

### 页面上选择的 DNS

用户在自己的页面上选择 DNS 后（参见**页面上的 DNS 选择**），此部分会列出他们为订阅类应用做的选择以及在各服务器上的选择（所有管理员均可只读查看）。不再提供的选择会注明改用哪个 DNS。**重置**会移除所有选择，恢复常规 DNS 规则（用户自己的预设、分组预设、订阅类应用列表的默认预设或节点默认预设、实例预设）。所有者和协作者可以重置；操作会以 `user_dns_choices_reset` 写入审计日志。关闭此选项不会移除已有选择：这些选择会继续生效，直到你在此处重置。参见[DNS](dns.md)。

### 限制

| 设置 | 步长和范围 |
|:--|:--|
| **流量配额** | 每次调整 10 GB，范围为 0–10000 GB；设为 0 表示**不限**。 |
| **重置周期** | **每天**、**每周**、**每月**或**从不**；选择后立即保存。如果通过 API 或 MCP 为用户设置了 30 天滚动周期，还会显示**每 30 天**。 |
| **有效期** | 每次调整 5 天，最多 3650 天；∞ 表示**永久**。在 ∞ 上选择「−」会设为 30 天。 |
| **设备** | 每次调整 1 台，范围为 1–100 台。 |
| **每用户限速** | 每次调整 5 Mbit/s，范围为 0–10000 Mbit/s；设为 0 表示**不限**。该用户所有设备在同一节点上合计。实验性功能。 |
| **每设备限速** | 步长相同。每台设备单独计算。实验性功能。 |

停止点击后，更改会立即保存。

限速对 Hysteria2 和 VLESS 生效。AmneziaWG 两种限速都不应用。

- **每用户限速**是该用户所有设备在**同一节点**上的合计。同时连接两个节点的用户最多可以得到两倍的限速，因为节点之间不做协调。这就是原来的单一限速：设备有各自的密钥之前，所有应用共用一个凭据，所以它本来就是按用户限速。
- **每设备限速**限制每台设备。
- 两种限速可以同时设置。每个字节都要通过两道限速，所以设备的速度取自己的限速和用户限速剩余部分中较小的一个。
- 共享用户限速需要报告 `user-rate-limit/1` 的 Agent。使用旧版 Agent 的节点会把每台设备限制在两种限速中较小的一个，节点的**设置**标签页会对此作出提示，直到 Agent 更新（参见[节点](nodes.md#agent-版本和状态漂移)）。

### 访问权限

- **分组**：选择另一个分组后，服务器会先计算更改并显示结果：「Alice 将失去：『AWG 3.1』（2 个 AmneziaVPN 密钥将停止工作）」、「可获得：…」。点击**更改分组**确认。一个 AmneziaVPN 密钥只属于一个协议配置；用户失去该协议配置后，相关密钥会停止工作。
- 分组提供的协议配置按两种连接方式列出，每个都链接到其页面。
- **DNS**：用户自己的预设；留空时使用分组或默认预设。下方会说明适用的预设及其来源。
- 应用开关。
- **所有节点**或逐节点勾选框。没有适用协议配置的节点会显示为灰色；「仅 Hysteria2」表示该节点只有一种协议。点击节点名称会打开其**协议配置**标签页，可在那里设置端口和域名。

### 危险区域

- **重置流量**会将当前周期的已用流量设为零。周期及其结束时间不会改变，历史记录会保留；因配额受限的用户可以重新连接。此计数无法恢复。
- **删除用户**会永久移除该用户：从所有节点删除其密钥、断开其连接、停用链接并删除其流量历史。输入名称以确认。

## 配额周期

配额在 UTC 00:00 重新开始计算：每天、每周一或每月 1 日。选择**从不**时，流量在整个有效期内累计，只能通过**重置流量**清零。新用户默认每月重置，也可以选择其他周期；API 和 MCP 还可以设置 30 天滚动周期。卡片会显示周期和下次重置时间。周期结束时，已用流量会重新从零开始，因配额受限的用户会自动恢复访问。

## 设备和设备上限

每台设备占用一个名额。

- 提供设备 ID（HWID）的订阅类应用，每个 ID 算一台设备。哪些应用会提供：[客户端应用](client-apps.md#哪些应用会发送设备-id)。
- 所有不提供设备 ID 的订阅类应用共用一个名额，即**未提供设备 ID 的应用**。
- 每个 AmneziaVPN 密钥占用一台设备。

### 设备如何出现

- 应用第一次获取订阅时会创建设备，每个设备 ID 一台。打开用户页面、管理后台的预览和创建用户都不会创建设备：新用户在应用获取链接之前显示「0 / 5」，第一次连接要等几秒，直到节点收到新密钥。
- 每台设备都有自己的密钥（Hysteria2、VLESS 和 Mihomo 中的 AmneziaWG）、自己的在线状态和自己的流量。复制到其他设备的配置会继续可用，直到你删除或拉黑这台设备；但它会被看出来（同一台设备同时出现在两台服务器上），而且移除它不会影响该用户的其他设备。
- 设备 ID 本身不会保存：面板只保存它的哈希，并混入用户信息，所以同一部手机出现在两个订阅里时不会被关联起来。卡片显示哈希的前六个字符作为指纹，用来区分两部相同的手机。
- 升级时无需任何人重新连接。第一个提供设备 ID 的应用会接管该用户原来的共用设备，并保留它的密钥。其他提供 ID 的应用在下次更新时获得各自的密钥。不提供 ID 的应用继续使用共用名额。

### 设备上限和模式

设备上限已满时会发生什么，取决于**订阅 → 下发规则 → 订阅类应用的设备上限**中的模式：**仅计数**、**限制**或**严格**。参见[订阅](subscriptions.md#订阅类应用的设备上限)。简单说：**仅计数**不拒绝任何人，**限制**拒绝超出上限的新设备，**严格**还会拒绝不提供设备 ID 的应用。

- 静默满 30 天的订阅类设备，会在需要名额时把名额让给新的、提供设备 ID 的应用。只有**限制**和**严格**模式会这样做。AmneziaVPN 密钥永远不会被顶替。系统会写入事件「新设备顶替了闲置 30 天的设备」。
- 设备上限已满时，你和用户都无法创建新密钥。提高设备上限，或删除用户不再使用的设备。
- 你删除的设备在 90 天后会从数据库中清理。被拉黑的设备会保留，以保证拉黑有效。
- 被拒绝的应用会收到原因：参见[设备被拒绝时应用会显示什么](subscriptions.md#设备被拒绝时应用会显示什么)。

开启**页面上的设备**后，用户也可以在自己的页面上删除和重命名自己的设备；参见[用户页面](user-page.md#我的设备)。拉黑只有所有者和协作者可以操作。

## 分组标签页

分组是一组用户可以获得的协议配置。每个分组显示为一张卡片，包含分组名称、成员人数（链接到筛选后的用户列表）、两种连接方式对应的协议配置及其部署节点数，以及分组自己的 DNS 预设（如果已设置）。卡片上有**编辑**和**删除**操作。

如果还没有任何分组，标签页会提供**创建包含全部协议配置的**「所有人」和**新建分组**。

### 创建和编辑分组

- **名称**，最多 64 个字符。
- **分组包含的协议配置**：新建分组时默认勾选所有协议配置；取消勾选不应提供给该分组的配置。
- **更多** → **DNS**：分组的 DNS 预设；留空时使用实例默认预设。

编辑分组会更改该分组所有成员的访问权限（「此分组有 3 个用户；更改将应用于所有人」）。从有成员的分组中移除协议配置前，会先显示他们将失去的内容，包括哪些 AmneziaVPN 密钥会停止工作；按钮会变为「从 3 人处收回」。

也可以从协议配置页面将配置添加到分组（**加入分组**）。

### 在分组间移动用户

- 移动单个用户：用户卡片 → **访问权限** → **分组**，并查看用户将失去和获得的内容。
- 移动某个分组中的所有用户：删除分组并移动其成员（见下文）。列表不支持批量更改分组。

### 删除分组

- 空分组会立即删除：协议配置保留，只删除分组。
- 删除有成员的分组时，系统会询问要将成员移到哪里（「此分组有 3 人。要将他们移到哪里？」）；如果存在「所有人」分组，则默认选中。点击**移动 3 人并删除**即可一步完成移动和删除。
- 如果没有其他分组，就没有可移动的目标：先创建另一个分组。

## 谁可以执行哪些操作

所有管理员都可以查看用户和分组。所有者和协作者可以创建、更改和删除用户及分组，可以发放链接和密钥，可以为用户和分组选取 DNS 预设，也可以重置用户在页面上选择的 DNS。只有所有者可以选择节点向用户提供哪些预设。参见[安全](../operations/security.md)。
