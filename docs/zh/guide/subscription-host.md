---
title: 家中 NAT 后的面板（订阅主机）
description: "没有公网地址的面板：一个节点在子域名上承载订阅地址，并通过面板主动建立的隧道把请求转发给面板。"
---

面板需要公网地址做两件事：用户从它获取订阅，每个代理连接它以保持联系。放在家中、位于路由器 NAT 或运营商 CGNAT 之后的面板没有这样的地址。**订阅主机**解决了这个问题：你的某个节点在子域名（例如 `sub.example.com`）上承载订阅地址，并把请求转发给面板。

连接由面板自己建立：它连接主机的 443 端口并保持一条加密隧道，因此外部无需访问你的家庭网络。子域名的 TLS 在面板中终止，证书及其密钥都在面板上。节点只转发加密字节，不保存任何订阅、令牌或密钥。管理后台永远不经过主机：它留在面板自己的地址或本地监听地址上。设计见 `design/adr/0018-panel-behind-nat.md`。

仅限 VPS 版。Cloudflare 版本身已有公网地址，不显示此卡片。

## 要求

- **主机的 443 端口属于节点自己的网站**。可选以下之一：
  - 一个 Hysteria2 配置，其网站在 TCP 443 上；
  - 一个以节点自身为目标的 VLESS REALITY 配置（节点自己的网站，使用 PROXY protocol）；
  - 空闲的 443 端口，由代理在其上运行自己的网站。

  以他人网站为目标的 REALITY 配置会被拒绝，提示 *其上的 REALITY 配置已将 443 端口用于其他网站*。
- **所有代理都支持新的连接方式**。所有节点的代理都必须支持 `ws-link/1` 和 `panel-link/1`。如果有节点不支持，面板会拒绝启用，并列出这些节点，标注 *请更新代理*。请先更新它们（[更新](../operations/updates.md)）。
- **DNS 记录**。子域名的 A 记录指向节点地址；如果节点有 IPv6，还需要 AAAA 记录。启用前面板会检查这些记录。
- 主机节点必须在线，且未退役。

## 在家中新装面板

1. 不带 `--public-url` 安装面板，把管理后台放在本地监听地址上：

   ```sh
   mistgate setup --admin-listen 127.0.0.1:8081
   ```

   在这台机器上或通过 SSH 隧道打开 `http://localhost:8081/`。其余步骤见[安装面板](../getting-started/install-panel.md)。
2. 为子域名创建 A 记录（节点有 IPv6 时再加 AAAA），指向将成为第一个节点的服务器。
3. 打开 **节点 → 添加节点**，通过 SSH 安装节点（[通过 SSH 安装节点](../getting-started/ssh-install.md)）。在填写节点信息的步骤中勾选 **此节点作为订阅主机** 并填写 **子域名**。

   在此之前，节点无法连到 NAT 后的面板，因此面板直接在 SSH 会话中为它注册。节点上线后，面板会把订阅地址迁移到该子域名。如果记录尚未指向该节点，安装会因 DNS 错误而停止。**仍然继续** 会跳过检查继续安装，例如在 DNS 经过代理时。

## 在已运行的面板上启用

打开 **设置 → 域名** 中的 **订阅主机** 卡片：

1. 选择 **节点** 并填写 **子域名**。
2. **检查记录** 显示域名当前解析到的地址和应解析到的地址。
3. 点击 **启用**。如果记录没有指向该节点，面板会拒绝并提供 **仍然保存**。只有在确认记录无误时才使用，例如在 DNS 代理之后。

面板在运行中切换，无需重启。代理通过当前连接收到新的连接地址。每个代理在通过新地址成功连接之前，会保留旧地址。之后 **订阅链接基础地址** 一行会标注 *经由订阅主机*。

主机开启期间，卡片显示域名、节点、隧道状态（*隧道正常* 或 *隧道中断*，以及从何时起）和 CAA 记录。隧道持续中断时，面板会记录事件 `sub_host_tunnel_down`，恢复后记录 `sub_host_tunnel_up`。

面板的隧道看起来就像 Chrome 打开该子域名；节点通过一个携带面板时间的标记识别它，只有与自身时钟相差不超过两分钟时才接受。如果节点有响应但未识别面板，卡片会显示这一状态而不是 *隧道中断*，面板记录 `sub_host_tunnel_not_recognised`：请确认面板和节点都开启了时间同步（`timedatectl set-ntp true`），并且节点上的 agent 是最新版本。通过 SSH 安装主机时，面板会在开启主机前核对服务器时钟与面板时钟。

## CAA 记录

卡片会显示一条 CAA 记录，它只允许此面板的证书账户为该域名签发证书。请在 DNS 中发布它。其下一行说明 DNS 中是否已有该记录：*已在 DNS 中发布*、*尚未在 DNS 中*、*面板拥有证书账户后才会显示* 或 *无法检查 DNS*。

## 迁移到其他节点

迁移和关闭都分两个阶段，每次都由你自己完成。

1. 在 **迁移到其他节点** 中选择节点，点击 **开始迁移**。新节点获得自己的隧道，卡片同时显示两条隧道。
2. 把域名的 A（及 AAAA）记录改为新节点的地址。卡片会显示记录当前指向哪里。
3. 记录指向新节点且其隧道正常后，点击 **完成**。**取消** 会放弃迁移，主机留在当前节点。

## 关闭

1. 在 **面板恢复使用的地址** 中填写 `https://主机[:端口]`。如果面板没有自己的公网地址，请留空。
2. 点击 **关闭**。面板回到该地址，代理把连接迁移过去。
3. 卡片列出 **尚未切换到新地址** 的节点。列表为空时点击 **完成**。如果有节点一直没有切换，面板会询问是否仍要完成。这些节点在获得面板新地址之前会与面板失联（见[离线的节点](#离线的节点)）。**取消** 会保持主机开启。

## 把公网面板搬回家

1. 在公网面板上按上文启用订阅主机，让用户和代理改用子域名。
2. 等到没有节点再使用面板自己的地址，此时一切都经由子域名。
3. 做一次[加密备份](../operations/backups.md)。
4. 在家中用 `mistgate backup restore` 把它恢复到新的数据目录（[备份](../operations/backups.md)）。
5. 把管理后台移到本地监听地址，然后用同样的参数启动面板：

   ```sh
   mistgate admin-address --admin-listen 127.0.0.1:8081 --data-dir NEW-DIR
   ```

6. 停止旧面板。家中的面板连接主机，节点通过隧道连到它。

Passkey 绑定管理后台的地址，在新地址上不再可用。请用密码和身份验证器代码登录，然后重新添加 Passkey（[安全](../operations/security.md)）。

## 离线的节点

地址变更时离线的节点没有收到新的连接地址。在该节点上运行：

```sh
mistgate-node set-panel --link-url wss://sub.example.com/<secret-prefix>/
systemctl restart mistgate-node
```

代理会轮流尝试新地址和当前地址，一旦通过新地址建立会话就保留它（[CLI](../reference/cli.md)）。

## MCP

管理员权限的令牌可用 `subscription_host_get` 读取状态，并通过 `subscription_host_set`、`subscription_host_move`（`start`、`finish`、`cancel`）和 `subscription_host_disable` 更改主机。每次更改都是一个计划，由所有者在重新验证后批准。对于第一个主机，`node_install` 接受 `subscription_host_domain` 和 `skip_dns_check`。见 [MCP](../reference/mcp.md)。
