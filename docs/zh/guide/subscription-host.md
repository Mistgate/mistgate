---
title: 在家中 NAT 后运行面板（订阅主机）
description: "无需公网地址运行面板：由一个节点在子域名上提供订阅地址和 agent 链接，面板主动向它建立桥接。"
---

面板需要公网地址做两件事：用户从这里获取订阅，每个 agent 连接这里建立链接。放在家里、位于路由器 NAT 或运营商 CGNAT 之后的面板没有这样的地址。**订阅主机**解决了这个问题：由你的某个节点提供一个子域名，例如 `sub.example.com`，并把它的连接交给面板。

连接由面板主动建立：面板像浏览器一样访问主机 443 端口上的自有站点，并保持几条 HTTP/2 连接，因此无需任何连接进入你的家庭网络。子域名的 TLS 在面板终止，证书和私钥都在面板上。节点只转发加密字节，不保存任何订阅、令牌或密钥。管理页面从不经过主机：它仍在面板自己的地址或本地监听地址上。设计见 `design/adr/0018-panel-behind-nat.md`。

仅限 VPS 版。Cloudflare 版本身已有公网地址，不显示此卡片。

## 前提条件

- **主机的 443 端口属于节点自己的站点。** 以下之一：
  - TCP 443 上有提供自有站点的配置：带 TLS 的 VLESS、目标为节点自身的 VLESS REALITY、TrustTunnel，或带伪装站点的 MTProto；
  - 443 上没有任何配置：此时填写**站点名称**，即另一个指向该节点的名称。agent 会在那里自己提供一个站点并为其获取证书（在 Let's Encrypt 签发之前为自签名证书）。

  以下情况会被拒绝：443 上目标为他人站点的 REALITY 配置、TCP 443 上的 Hysteria2 站点、443 上无法共享端口的配置，以及本身响应该子域名的配置。面板会说明原因；节点上的配置继续运行。
- **所有 agent 都支持链接。** 所有节点的 agent 都必须具备 `ws-link/1` 和 `panel-link/1`。只要有节点缺少它们，面板就会拒绝，并列出这些节点，标注*请更新 agent*（[更新](../operations/updates.md)）。 只有通过链接注册的节点才声明 `panel-link/1`；mTLS 节点不会自动迁移。
- **DNS 记录。** 子域名的 A 记录指向节点地址；节点有 IPv6 时还需 AAAA 记录；如填写了站点名称，它也需要同样的记录。面板在启用前会检查这些记录；**检查记录**会显示它们当前解析到哪里。
- 主机节点必须在线且未退役。

## 在家中的新面板

1. 不使用 `--public-url` 设置面板，并把管理页面放在本地监听地址上：

   ```sh
   mistgate setup --admin-listen 127.0.0.1:8081
   ```

   在这台机器上或通过 SSH 隧道打开 `http://localhost:8081/`。其余步骤见[安装面板](../getting-started/install-panel.md)。
2. 为子域名和节点站点的另一个名称创建 A（和 AAAA）记录，都指向将成为第一个节点的服务器。
3. 进入**节点 → 添加节点**，通过 SSH 安装节点（[通过 SSH 安装节点](../getting-started/ssh-install.md)）。在服务器步骤中勾选**此节点作为订阅主机**，并填写**子域名**和**站点名称**。

   节点此时还连不到 NAT 后的面板，因此服务器检查会把面板标为不可达但不会中止，面板会在 SSH 会话内直接为节点注册：节点生成密钥，面板签发证书，角色和链接地址通过标准输入发送给节点，而不是放在命令行中。如果记录未指向该服务器，安装会因 DNS 错误而停止；**仍然继续**会跳过检查继续，例如在 DNS 代理之后。如果角色启用后安装失败，面板会再次关闭该角色。

4. 节点连接后，从向导的最后一步打开**设置 → 域名**。使用显示的值添加 [CAA 记录](#caa-记录)，等待订阅主机就绪后再创建订阅链接。

## 在已有面板上启用

打开**设置 → 域名**中的**订阅主机**卡片：

1. 选择**节点**并填写**子域名**；如果节点 443 上没有配置提供自有站点，再填写**站点名称**。节点地址为主机名时，会自动填为站点名称，可以修改。
2. **检查记录**显示这些名称当前解析到的地址以及应解析到的地址。
3. **启用**。如果记录未指向该节点，面板会拒绝并提供**仍然启用**。只有在确认记录无误时才使用，例如在 DNS 代理之后。

## 就绪

在主机**就绪**之前什么都不会切换。在此之前，卡片会列出各个步骤，并在每一步完成时打勾：

1. 节点在线。
2. 节点已接受角色（不合适的角色会说明原因，此时节点上不会安装任何内容）。
3. 节点站点已有公共证书。
4. 面板到节点的桥接已连通。
5. 面板已有该子域名的证书（Let's Encrypt，经由主机签发；桥接连通后面板会自行申请）。
6. DNS 中已有仅允许此面板为子域名签发证书的 CAA 记录（见 [CAA 记录](#caa-记录)），或所有者选择不使用它继续。

全部满足后，面板记录 `sub_host_ready` 事件，并在运行中切换，无需重启：**订阅链接的基础地址**变为该子域名（*经由订阅主机*），agent 通过当前链接收到新的链接地址，并在经由新地址的会话成功之前保留旧地址，新节点也通过子域名的链接注册。之后即使失去就绪状态，也不会切换回去。

主机开启期间，卡片显示域名、站点名称、节点、桥接状态（*桥接已连通*或*桥接中断*及原因，以及起始时间）和 CAA 记录。桥接持续中断时面板记录 `sub_host_tunnel_down`，恢复后记录 `sub_host_tunnel_up`。

访问者看到的情况：面板无法接收的子域名连接（没有桥接，或主机已满）会转到节点自己的站点，而不会被重置。主机同时最多放行 400 人，在承载量达到约四分之三后，每个地址 16 人（IPv6 地址按 /64 计算）、每个网络 64 人（IPv4 /24 或 IPv6 /48），并为 agent 链接保留余量。超出限制的连接会最多等待两秒空位，然后才转到节点的站点。

## CAA 记录

子域名指向主机，因此接管该节点的人可以为它签发自己的证书并读取经由它的订阅。只有写明此面板证书账户的 CAA 记录才能阻止这一点。面板拥有账户后（首次申请子域名证书时创建），卡片会显示该记录；请在 DNS 中发布它。下方一行说明 DNS 中是否已有：*已在 DNS 中发布*、*尚未在 DNS 中*、*面板拥有证书账户后显示*或*无法在 DNS 中检查*。记录发布之前，主机不会就绪。

如果 DNS 提供商无法发布 CAA 记录，**不使用 CAA 继续**可在重新登录后让主机在没有它的情况下就绪。面板会记入审计、写入警告事件 `sub_host_caa_waived` 并在卡片上显示。该选择只对此子域名和此证书账户有效：新的子域名或新的账户会再次询问。通过 MCP 为计划 `subscription_host_caa_waive`。

该记录写明面板的证书账户。恢复或迁移时未带上 `acme` 目录的面板会得到新账户：此时 Let's Encrypt 会拒绝续期子域名证书，直到你把记录换成卡片上显示的那条。

## 主机上的配置

当某节点是主机时，面板会拒绝使其不再合适的配置更改（`sub_host_inbound_unfit`）：443 上借用他人站点的 REALITY 配置、443 上的 Hysteria2 站点、占用该子域名的配置，或在没有站点名称时关闭或删除 443 上唯一的站点。请把该端口留给节点自己的站点，或先迁移主机。

如果配置了**站点名称**，即使 443 上的某个配置启动失败，代理也会保留自己的站点供桥接使用。正常运行且使用同一名称的配置仍然会接收匹配的连接。

## 迁移到另一个节点

迁移和关闭都分两个阶段进行，每个阶段都由你自己完成。

1. 在**迁移到另一个节点**中选择节点（需要时填写它的**站点名称**），然后点击**开始迁移**。面板会同时连接两个节点，卡片显示两条桥接。
2. 把子域名的 A（和 AAAA）记录改为新节点的地址。卡片会显示记录当前指向哪里。
3. 记录指向新节点且新节点能够承载该子域名（在线、角色运行中、站点已有公共证书、面板到它的桥接已连通）后点击**完成**。如有任何一项尚未满足，面板会说明缺少什么并询问是否仍然完成。**取消**会放弃迁移，主机保留在当前节点上。

## 关闭

从未就绪的主机会立即关闭：没有任何内容迁移到它，面板保留原地址。

1. 在**面板要回到的地址**中填写 `https://host[:port]`。只有在面板将没有公网地址时才留空：面板会先确认，因为此时它不会发放订阅链接，节点也无法连到它。
2. 点击**关闭**。面板回到该地址，agent 会把链接迁移过去。
3. 卡片列出**尚未切换到新地址**的节点。列表为空时点击**完成**。如果仍有节点停留在旧地址，面板会询问是否仍然完成。这些节点在获得新地址之前会失去面板（见[离线节点](#离线节点)）。**取消**会保持主机开启。

## 把公网面板搬回家

1. 在公网面板上按上述方法启用订阅主机并等待就绪，让用户和 agent 使用该子域名。
2. 等到没有节点再使用面板自己的地址。
3. 创建一份[加密备份](../operations/backups.md)。
4. 在家中用 `mistgate backup restore` 将其恢复到新的数据目录（[在新面板上恢复](../operations/backups.md#在新面板上恢复)）。
5. 使用 [`mistgate admin-address`](../reference/cli.md#mistgate-admin-address) 把管理页面移到本地监听地址，然后启动面板：

   ```sh
   mistgate admin-address --admin-listen 127.0.0.1:8081 --data-dir NEW-DIR
   ```

6. 停止旧面板。家中的面板会连接主机，节点通过子域名连到它。

通行密钥（passkey）绑定在管理页面地址上，因此在新地址上无法使用。请用密码和验证器代码登录，然后重新添加通行密钥（[安全](../operations/security.md)）。

## 离线节点

地址变更期间离线的节点没有收到新的链接地址。在该节点上运行：

```sh
mistgate-node set-panel --link-url wss://sub.example.com/<secret-prefix>/
systemctl restart mistgate-node
```

agent 会轮流尝试新地址和当前地址，并在经由新地址的会话成功后保留新地址（[CLI](../reference/cli.md#mistgate-node-set-panel)）。

## 只能通过链接连到面板的 agent

有了主机之后，agent 只能通过子域名上的 WebSocket 链接连到面板。它们仍保留自更新和按网络统计：具备 `link-fetch/1` 的 agent 会凭其链接会话的令牌，通过链接下载更新文件和网络表。没有它的 agent 无法从 NAT 后的面板更新；请在切换前先更新它（[更新](../operations/updates.md)）。

## MCP

Admin 档的令牌用 `subscription_host_get` 读取状态，通过 `subscription_host_set`、`subscription_host_move`（`start`、`finish`、`cancel`）和 `subscription_host_disable` 更改主机。每项更改都是一个计划，需由所有者重新登录后批准；任何工具都不会显示桥接路径或链接前缀。`node_install` 为第一个主机接受 `subscription_host_domain`、`site_name` 和 `skip_dns_check`。见 [MCP](../reference/mcp.md)。

## 已知限制

- 主机是订阅和链接的单点；需要关停该节点时，请先把主机迁移到另一个节点。
- 桥接无法隐藏的特征：从面板地址到节点 443 的一到四条长连接、每 15 秒一次心跳、大约每小时一条新连接。故障期间访问子域名的人会看到节点为另一个名称签发的证书。
- 面板的子域名证书经由主机续期：主机停机时间足够长时，证书会过期。
- Hysteria2 站点暂时无法与主机共用 TCP 443。
