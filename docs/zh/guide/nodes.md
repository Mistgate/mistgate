节点是运行 Mistgate Agent（`mistgate-node`）的服务器。面板会告诉 Agent 要运行哪些协议配置，Agent 会报告自身状态、流量和主机信息。本页按标签页介绍**节点**部分和节点页面。要连接新服务器，请参阅[添加节点](../getting-started/add-node.md)。

## 节点列表

页眉显示节点数、在线人数和有问题的节点数（「3 个节点 · 12 人在线 · 1 个有问题」）。**添加节点**会打开通过 SSH 安装节点的对话框，或生成手动安装命令：请参阅[添加节点](../getting-started/add-node.md)。

表格上方有：

- 状态标签：**全部**、**有问题**和**正常**，每项都显示数量；
- **全部协议**：只显示运行某一种协议配置的节点；
- **所有国家**：只显示某个国家的节点。

| 列 | 显示内容 |
|:--|:--|
| **节点** | 状态圆点、名称、位置（或国家）和服务商。下方显示状态原因或状态名称。 |
| **地址** | 客户端连接所用的域名或 IP。 |
| **协议** | 节点上协议配置所用的协议。 |
| **在线** | 当前连接的人数。 |
| **今日** | 从 00:00 UTC 起的流量。 |
| **CPU** | 最近一次 CPU 读数。 |
| **运行时间** | Agent 报告的主机运行时间。 |

在手机上，表格会变成每个节点一张卡片，显示相同的信息。列表每 10 秒刷新一次。列表中不显示已退役的节点。

如果正常节点上的 Agent 版本早于面板附带的版本，节点会显示 **正常 · Agent 版本过旧** 和当前版本；该行链接到**更新**。请参阅[更新](../operations/updates.md)。

## 节点状态

| 状态 | 含义 | 操作 |
|:--|:--|:--|
| **等待安装** | 已生成安装命令，但 Agent 尚未连接。此行会显示命令还能使用多久，或说明命令已过期。 | 在服务器上运行命令，或在节点页面生成新命令（**新安装命令**）。 |
| **正常** | Agent 已连接，且没有问题。 | 无需操作。 |
| **需要关注** | Agent 已连接，但节点上没有已启用的协议配置（用户无法获得该节点）、节点状态与面板不一致，或服务器时钟与面板不一致。 | 阅读名称下方的说明。添加协议配置、重启协议配置，或校准时钟。 |
| **部分正常** | 部分协议配置启动失败，其余协议配置仍在运行。 | 打开节点上的**协议配置**，查看每个启动失败的协议配置下方的错误。 |
| **故障** | 所有已启用的协议配置均启动失败，或诊断中的主机检查失败。 | 打开**协议配置**或**诊断**。 |
| **无法连接** | 无法连接到 Agent，且主机在 10 分钟内没有恢复连接。 | 在服务商处检查服务器，然后通过 SSH 重启 Agent（横幅会显示命令）。 |
| **主机闪断** | 连接中断不到 10 分钟，或恢复后启动时间未变。这不会计为问题。 | 通常无需操作：短暂中断来自服务商。 |
| **无流量** | Agent 已连接，但客户端视角检测失败：客户端无法连通。 | 如果横幅能判断原因，会显示被封锁的 UDP 端口、证书或出口等信息。重启协议配置或更换端口。 |
| **更新中** | 正在更新 Agent。 | 请等待。如果更新后检查失败，系统会自动回滚。 |
| **已退役** | 节点已从集群退役。 | 无需操作。 |

问题状态包括红色状态和**需要关注**，但不包括时钟警告：时钟警告会显示，但不会计入问题数量。这些数量会显示在节点列表页眉、概览页和菜单中。

## 节点页面

页眉显示国家代码、名称、状态；如果节点有 WARP 账户，还会显示 WARP 标签（WARP 正常运行时，标签显示 Cloudflare 数据中心，并链接到 WARP 卡片）。名称下方显示位置、服务商、地址、Agent 版本；有较新版本时还会显示**Agent 版本过旧**。

右侧有两个按钮：

- **重启协议配置**会重启此节点上的所有协议配置。对话框会说明有多少人会断开几秒；他们会自动重新连接。Agent 未连接或节点上没有协议配置时，此按钮不可用。
- **诊断**会打开**诊断**标签页。

页眉下方的横幅会说明当前状态以及相应的操作：

| 状态 | 横幅 |
|:--|:--|
| 无法连接 | 显示「节点已无响应……」、上次收到响应的时间，以及可复制的命令。 |
| 无流量 | 显示「在线但无流量」、健康检查给出的原因，以及**重启协议配置**和**立即检测**。 |
| 主机闪断 | 显示「主机发生闪断」，并提供**知道了**。 |
| 更新中 | 显示「Agent 正在更新」。 |
| 等待安装 | 显示「正在等待 Agent」，并提供**新安装命令**。 |
| 已退役 | 显示「此节点已退役」。 |
| 没有协议配置 | 显示「……上还没有协议配置，用户无法使用该节点」，并提供**添加协议配置**。 |
| 协议配置启动失败 | 显示协议配置名称、原因说明和**打开协议配置**。 |

「无法连接」横幅中的命令需要通过 SSH 在节点上运行：

```sh
systemctl restart mistgate-node && journalctl -u mistgate-node -n 50 --no-pager
```

页面有七个标签页，每个回答一个问题：**概览**（一切正常吗？）、**入口**（用户如何访问这个节点？）、**协议配置**（这里运行着什么？）、**出口**（用户流量从哪里出去？）、**历史**（发生过什么？）、**诊断**（主机上哪里有问题？）和**服务器**（这是一台什么机器？）。**入口**标签页带有红色角标，显示我们这一侧出问题的入口数量（中转故障、端口无响应）；国家层面的封锁不计入，那是一条告警，并使入口显示为琥珀色。**协议配置**标签页显示启动失败的协议配置数量；**诊断**标签页显示需要关注的检查项数量。已退役的节点保留**概览**、**历史**和**服务器**。为旧版本标签页（**用户**、**日志**、**运行记录**、**事件**、**设置**）创建的链接和书签会打开它们迁移后的位置。

### 概览

- **CPU**、**RAM**、**DISK**、**NETWORK**：最近一次读数。CPU 条会用另一种颜色显示 softirq（网络中断）部分，并显示 vCPU 数量和负载。Agent 连接几秒后会收到读数；离线节点会保留最近一次读数，并显示离线时间。
- **流量 · 24 小时**：此节点每小时的流量。
- **入口**：单行的状态条，每个入口一个标签；点击标签会在**入口**标签页打开该入口，**全部入口 ›** 打开该标签页。
- **告警**：此节点未关闭的告警，按钮与运行状况页面上的按钮相同；还显示最近关闭的三条告警。**所有告警**会打开运行状况页面。没有告警时不显示此卡片。
- **客户端视角检测**：每个协议配置一行，显示延迟和出口 IP，或失败原因。点击一行可打开其 24 小时历史记录。**立即检测**会对该节点启动一轮检测。
- **当前在此节点上**：按协议显示当前连接人数，以及连接的用户、设备型号、协议和当前下载速度。默认显示六人；**全部 N 个**会就地展开其余的人。
- **今日排行**：自 00:00 UTC 起经此节点流量最多的用户，先显示五人；**全部 10 个**显示全部十人。

检查、告警和诊断的说明见[运行状况](../operations/health.md)。

### 入口

这个标签页把用户访问节点的所有途径画成一条“地铁线”。最上面是标签 **用户 · 俄罗斯**（[国家检测](../operations/reachability.md)所针对的国家），下面是一条竖线，每个入口一条支线，最下面是节点本身。入口有：

- **直连**：节点自己的地址和端口数量，下面有一行：「从俄罗斯：所有网络可访问」、「MTS、Tele2 无法访问」、「从俄罗斯无法访问」或「从俄罗斯：没有数据」。
- **经 msk1**：每个中转本节点的入口节点一条，显示服务器数量，以及一行说明用户在本节点无法访问的网络中能否访问该入口节点（「msk1 在 MTS 可以访问」）。只有所有者能看到这些入口。
- **IPv6 入口**：为网络封锁了节点 IPv4 地址的用户提供的额外服务器；所有者开启之前保持关闭（参见 [IPv6 入口](#ipv6-入口)）。服务器有 IPv6 时显示。目前入口需通过 MCP 开启，这一行也会这样提示；此页面上的卡片会在之后的版本中提供。
- **添加入口…**：虚线行，仅所有者可见。当直连在某些网络中无法访问时，它会变成琥珀色：「MTS 无法访问 — 添加绕行」。还没有其他入口时，它写着：「如果用户的网络访问不到这个节点，就给他们另一个入口：经其他节点，或通过 IPv6。」

在**入口节点**上，线的下方有一组**经 msk1 访问**，每个出口一行（「→ DE de1 · 2 个服务器」），然后是**中转其他节点…** 和一行页脚：被中转的流量会两次经过该服务器，因此在服务器的流量和负载中算两次。

每个入口有一个圆环：绿色表示正常且所有网络都能访问；半琥珀色表示正常，但国内部分地区访问不到；红色表示故障或被封锁；灰色空心表示已关闭。点击一个入口，详情会在右侧打开；在手机上，列表和详情轮流显示，**‹ 全部入口**返回列表。打开的入口记录在地址中（`?tab=ways&way=direct`、`ipv6`、`via:<入口节点 id>` 或 `out:<出口节点 id>`），因此链接或刷新页面会再次打开它；没有该参数时，会打开第一个有问题的入口，否则打开**直连**。方向键、**Home** 和 **End** 可以在列表中移动。旧链接 `?tab=profiles#ports` 会打开**入口** → **直连**。

#### 直连

「用户连接 203.0.113.7。」下面依次是[端口](#端口)区块，以及**从俄罗斯能否访问 de1**：国家检测的一行，以及封锁为部分封锁时按网络的明细。按钮：**检测端口**和链接**协议配置 ›**。没有协议配置时，会写「没有协议配置：用户无法连接」，并提供**添加协议配置**。国家检测还没有这个节点的数据时，会写「国家可达性检测还没有这个节点的数据。」，并给所有者一个链接**可达性页面的来源**。

#### 端口

**端口**区块位于**入口**标签页的**直连**入口中（以前在**协议配置**标签页）。**检测端口**会从一个已连接的集群节点（或可用时从面板主机）运行两项检查：UDP 可达性和 TCP 可达性。每行显示端口、检测结果、检测时间和来源，以及监听该端口的协议配置。

**UDP。** 检查会从一个已连接的集群节点（或可用时从面板主机）向此节点发送探测包，并询问 Agent 收到了多少个包。它只能说明从该发送端所在网络路径发出的 UDP 包能否送达。检测通过不代表所有客户端都能访问该端口；检测失败也可能由发送端、路由或基于来源的过滤造成。调查 UDP 可达性时，可将它作为一个观测点。

**TCP。** 检查会连接节点应当响应的每个 TCP 端口，并确认连接是否抵达 Mistgate 本身，而不是节点前方的其他服务器。节点有 ACME 证书名称时会检查端口 80：Agent 会准备一个一次性令牌，发送端再按 Let’s Encrypt 的方式请求该令牌。Hysteria2 站点端口和每个 VLESS TCP 端口都会针对预期名称执行 TLS 握手。REALITY 目标为其他站点的 VLESS 协议配置，会根据该目标的证书判断。

| 检测结果 | 含义 |
|:--|:--|
| **已连接到 Mistgate** | 连接已抵达此节点上的 Mistgate。 |
| **其他服务器有响应** | 其他对象作出了响应：会回复的服务商过滤器、代理，或节点前方的 Web 服务器。 |
| **节点上的其他程序占用** | 仅适用于端口 80：节点上的其他程序已监听此端口，因此 Mistgate 无法响应。 |
| **已关闭** | 连接被拒绝。 |
| **无响应（已过滤）** | 连接超时，通常表示防火墙丢弃了连接。 |

如果某行显示**未检查**和简短原因，表示无法探测该端口（Agent 版本过旧、发送端没有到节点的路由、另一项检查正在运行，或检查失败）。完全没有发送端可执行探测时，会保留上次保存的结果。从节点自身主机发送的检查无法证明服务商的过滤情况，因此面板会说明这一点，并且不保存结果。

在各行下方，会显示节点的 Let’s Encrypt 证书能否续期：

- **端口 80 已开放**：证书会通过端口 80 续期。
- **端口 80 已关闭，但 TCP 443 可响应 Let’s Encrypt**：证书会通过 443 上的 TLS 续期。需要有监听器在 443 上响应，例如 Hysteria2 站点，或 REALITY 目标为**本节点站点**的 VLESS 协议配置。
- **端口 80 已关闭，且 TCP 443 无法响应 Let’s Encrypt**：证书将无法继续续期。如果有 VLESS 协议配置使用其他站点占用 443，此行会显示其名称。在服务商处开放 TCP 80、将 VLESS 移到 8443，或将其 REALITY 目标改为**本节点站点**。

节点没有 ACME 证书名称，或无法探测端口 80 时，不会显示此行。端口 80 的检测结果也会决定 VLESS 协议配置暂停 Hysteria2 站点时所显示的证书提示：[在同一节点上运行 VLESS 和 Hysteria2](vless-and-hysteria2.md)。

在 VPS 安装中，面板每 6 小时会为每个在线且具备 `udpcheck` 能力、并有已启用入站的节点重复运行检测。检测到丢包或故障时，会立即再检查一次以确认结果；告警根据最近一次检测结果触发。同一计划任务也会刷新 TCP 行，但这些行不会单独触发告警。

#### 经其他节点

入口**经 msk1**写着：「用户连接 msk1，由它把流量原样转发给 de1。密钥不变。」**服务器**区块是中转行：协议配置、入口上的端口、转发到哪里、状态、两项检测（参见[中转](relays.md#工作方式)）、按钮**开启**、**关闭**、**立即检测**和**删除**，以及监控行（[监控](relays.md#监控)）。接着是**从俄罗斯能否访问 msk1**。按钮：**全部检查**、**添加服务器…** 和链接**打开 msk1 ›**。

在入口节点上，入口 **→ de1** 与此相同：该出口的中转行、**全部检查**、**添加服务器…** 和**打开 de1 ›**。

#### IPv6 入口

「为 IPv4 地址被封锁的用户额外提供的入口。与用户流量的 IPv6 出口不是一回事。」（参见[出口](#出口)。）

**作用。** 开启入口后，每个有权使用该节点的用户，在其应用显示的列表中，会在节点的每个服务器旁多得到一个服务器“<名称> · IPv6”（「🇩🇪 DE · Hysteria2 · IPv6」）。它连接服务器自己的某个 IPv6 地址（默认是服务器用于出站 IPv6 的那个），其余与原服务器相同：TLS 名称仍是节点的域名，REALITY 保留其目标和密钥，自签名证书保留其固定指纹，用户的凭据不变。不支持 IPv6 的应用会跳过它。主地址、它的 DNS 记录和证书都不受影响。用户会在下次刷新订阅时获得新的服务器（默认每 12 小时，参见[订阅](subscriptions.md)）。[中转](relays.md)的服务器保持原样，不会为 IPv6 再复制一份：顺序是节点的服务器、它的 IPv6 服务器，然后是中转的服务器。

**不涵盖的情况。** 用户经由 CDN 访问的服务器（他们连接的是 CDN 的地址）、证书签发给节点 IPv4 地址的服务器，以及静态 AmneziaWG 密钥（`.conf` 文件和 `vpn://` 密钥）：密钥保留签发时的地址且不会自行更新，改动它会悄无声息地使其失效。AmneziaWG 的 Mihomo 代理随订阅刷新，会得到 IPv6 服务器（参见 [AmneziaWG](amneziawg.md#通过订阅使用-amneziawg)）。通过 IPv6 的 AmneziaWG 每个数据包多 20 字节包头：MTU 为 IPv4 设得很紧的协议配置在这里可能发生分片；默认值 1420 留有余量。

**谁会得到。** 所有有权使用该节点的用户。面板不知道用户的网络，而不支持 IPv6 的应用根本不会选这个服务器，所以没有什么需要选择的。

**何时可用。** 面板需要节点的[诊断](#诊断)报告 IPv6 上行可用。无法开启时，面板会说明原因（MCP 中见 `node_get`）：`no_ipv6`（服务器没有全局 IPv6 地址）、`ipv6_broken`（有，但主机商那边出站 IPv6 不通，所以也不会有连接进来）、`agent_old`（IPv6 可用，但节点 Agent 没有列出服务器的固定地址：请更新它）、`not_checked`（诊断还没有报告）或 `main_is_ipv6`（节点的地址本身已经是 IPv6 地址）。地址是诊断为服务器上行列出的地址之一，默认是用于出站 IPv6 的那个（前提是它在其中；临时地址永远不会被选用）；不能自由输入，因为主机上没有的地址反正通不过检测。

**开启前先检测。** 面板从外部向该 IPv6 地址发送与**检测端口**相同的包：向节点的每个 UDP 服务器发送 UDP 数据报（由节点计数），向每个 TCP 服务器做 TLS 握手，由节点自己的证书、固定指纹或 REALITY 链证明应答的确实是这个节点。没有 IPv6 版本的服务器（经由 CDN，或证书签发给 IPv4 地址）不参与检测，端口 80 也不包含在内：Let’s Encrypt 通过 IPv4 验证主名称。发送端是集群中 IPv6 可用的另一个节点（最多两个，顺序与**检测端口**相同）；只有没有任何节点能发送、面板自己有 IPv6 且不在该节点的主机上时，才由面板自己发送。只有在其他节点和面板都完全无法发送时，Globalping（开启时）才会从任意位置的两个探测点连接一个 TLS 端口：这只说明该地址会应答连接，不说明应答的是这个节点，结果会注明*由 Globalping 验证*。没有任何一方能检测时，入口不会开启（`no_ipv6_verifier`）：没人能测试的地址绝不放行。发送端无法执行自己那部分，或者一部分能检测而另一部分没人能检测，检测同样失败。不超过 10 分钟的通过结果会被采用；否则开启入口时会运行一次检测。某个端口的应答不是节点本身，检测即失败，且不会有任何变化。该检测不会向主地址的**端口**结果写入任何内容。

**关闭**会让下一次订阅不再包含这些服务器；通过其中一个连接的用户会改选其他服务器。关闭始终可用，节点的 IPv6 坏了也一样。

**告警。** 入口开启期间，Globalping 的 IPv6 轮次会测量入口的地址，IPv6 上的封锁会为该节点单独触发一条告警，只计入口开启之后的轮次（参见 [IPv6](../operations/reachability.md#ipv6)）；没有入口时，IPv6 仅作信息。

在这个版本中，入口只能通过 MCP 开启和关闭；节点页面上的卡片会在之后的版本中提供。只有所有者可以检测或更改入口。API 会拒绝令牌；MCP 工具有 `node_ipv6_check`（读取）以及 `node_ipv6_plan` / `node_ipv6_apply`，后两者需等待所有者批准（[MCP](../reference/mcp.md)）。审计日志记录 `node.ipv6_check` 和 `node.ipv6_entry`（开启或关闭，附地址）。

#### 添加入口

仅所有者可用。**添加入口…** 会打开对话框「为 de1 添加入口」（`?tab=ways&add=1`）：

1. 节点无法访问时，对话框这样开头：「从俄罗斯，de1 在 MTS 无法访问。给这些用户另一条路 — 节点和密钥都不变。」选择**经其他节点**（「用户连接他们网络能访问的节点，由它把流量原样转发给 de1。」，并附最佳提示：「推荐 msk1：MTS 可以访问」），或**IPv6 入口**（目前为灰色：入口需通过 MCP 开启）。
2. **经哪个节点**：先是**推荐：MTS 可以访问**，然后是**其他节点**。每个节点显示国家代码、用户能否访问它，以及在 TSPU 探测从它运行的情况下，它能否连到本节点。已经在中转本节点服务器的节点会写「已转发 de1 的 2 个服务器」。
3. 中转对话框，范围限于本节点的服务器：勾选服务器，入口上的端口（自动），**仅检测**或**检测并开启**，然后是进度和每个服务器的结果。**返回**回到第 2 步。

这套机制在对话框和[中转](relays.md)中仍叫**中转**；“入口”是你在节点页面上要找的东西。

#### 谁能看到什么

所有者能看到全部入口。协作者只能以只读方式看到**直连**和 **IPv6 入口**：没有中转入口，也没有**添加入口…**。

### 协议配置

节点上的每个协议配置占一行。名称链接到协议配置页面；下方显示所用协议。

Hysteria2 行显示：

- **端口**：此节点使用的 UDP 端口；
- **域名（SNI）**：证书中的服务器名称；
- **证书**：到期日期（剩余不足 14 天时显示琥珀色，不足 3 天时显示红色）、**自签名，已固定指纹**，或**无：协议配置未运行**。

AmneziaWG 行显示**端口**、**后端**（内核或用户态及其版本）、**出口**（**直连**或**WARP**）和**设备**（「5 · 2 个在线」），以及显示最近一次握手的状态行。

每个协议配置的**端口**单元格里有一个小圆点，显示最近一次端口检测的结果：正常、丢包或无响应。点击它会打开**入口** → **直连**，[端口](#端口)区块和**检测端口**就在那里。

每个协议配置下方的 **24 小时** 行显示节点统计到的连接尝试：连接次数、**立即断开**（已连接，随后在几秒内冻结或断开：TSPU 冻结就是这样）、**密钥被拒绝**（密钥已到期；已移除或已更换的密钥节点不再认识，计入未知密钥）；Hysteria2 显示已开始但始终未完成认证的握手比例（不含面板自身的检查），AmneziaWG 显示多少台设备始终未完成握手，以及未知密钥（扫描器也会发送）。使用 v0.1.57 及以上版本的 Agent 时，Hysteria2 协议配置还会显示有多少连接**冻结**（节点持续发送却没有任何回应：TSPU 冻结就是这样）、平均**延迟**和**丢包**；此时连接后立即断开不再标记为问题，因为大多是应用的短暂检测。只有计数，没有任何地址。如果节点的 Agent 尚不统计连接，会在协议配置列表上方提示一次：请更新 Agent。

右侧显示状态：**运行中**、**启动中**、**启动失败**或**已关闭**。协议配置启动失败时，系统会显示原因说明和 Agent 返回的错误文本。原因明确时，会显示相应按钮：**更换端口**（对话框中已预填一个空闲端口）、**设置域名**或**打开 WARP**。

每行有以下操作：

- **编辑**：只设置此节点的端口和**域名（SNI）**，以及**已启用**开关。关闭协议配置后，它仍保留在节点上，但会从订阅中移除。
- **重启**：只重启此协议配置。其连接会中断几秒。
- **移除**：从节点上移除此协议配置。对话框会说明受影响对象：下次更新订阅时将无法获得此节点的用户，或（对于 AmneziaWG）将停止工作的设备。若将协议配置重新放回同一节点，他们的密钥会恢复使用。如果有中转在转发该协议配置的服务器，对话框还会说明有几条中转会随之删除。

**添加协议配置**会打开将协议配置部署到此节点的对话框：请参阅[协议配置](profiles.md)。面板还没有任何协议配置时，对话框会提供创建 Hysteria2 协议配置并部署到此节点的选项，端口为 443（或第一个空闲端口）；另一个选项是**手动设置**。

### 出口

用户流量从哪里离开节点。从上到下：WARP 卡片、**用户流量**和**用户页面上的 DNS 选择**（宽屏时位于右侧）。WARP 详见 [WARP](warp.md)；节点页眉中的 WARP 标记和面板中每个**打开 WARP**按钮都会通向它的卡片。

**用户流量**包含三项设置和一个**保存**按钮，只提交更改过的内容；更改 BitTorrent 设置会重启节点上的 Hysteria2 协议配置。

**IPv6 出口**（旧版本中称为**客户端 IPv6**）默认开启（所有节点此前一直如此），只有所有者可以更改。它决定用户流量能否通过 IPv6 离开服务器，不影响用户连接节点的方式。如果服务商分配的 IPv6 地址位于与节点不同的国家，请关闭此选项：应用会按网站选择 IPv4 或 IPv6，因此用户可能随机显示为来自两个国家（IPv4 出口显示节点所在国家，IPv6 出口显示另一个国家，Google 或 YouTube 随后会显示错误的区域）。关闭后，若客户端 IPv6 流量会通过节点自身的上行链路离开，节点会返回 ICMPv6「管理上禁止」，而不是静默丢弃，使应用立即改用 IPv4，无需等待超时。不支持 nftables `reject` 操作的内核无法执行此操作：此时节点会静默丢弃 IPv6（应用可能等待超时；如果连规则都无法设置，则完全不会阻止 IPv6），并写入警告事件。隧道仍会正常工作。Agent 每 10 分钟重试一次；`reject` 恢复后会记录恢复事件。

- **AmneziaWG。** Agent 会在自身防火墙表（`mistgate_awg`）中添加一条 reject 规则；重新开启此设置时会将其移除。客户端配置不会更改：客户端 IPv6 地址和 `::/0` 路由仍保留在隧道中，因此用户的真实 IPv6 地址不会离开 VPN。发往隧道自身地址的 IPv6 不受影响。预设中的 IPv6 DNS 服务器也会被拒绝，因此设备会改用 IPv4 DNS 服务器。
- **Hysteria2。** 节点的直连出站连接只使用 IPv4；只有 IPv6 地址的域名将无法访问。已经打开的连接会继续使用原来的地址族；新连接会使用 IPv4。节点自身的名称解析（**此节点的 DNS 服务器**）保持原样。
- **经 WARP 出口不受影响。** WARP 出口属于 Cloudflare，而不是节点的上行链路，因此节点地址段的地理位置与此无关。

此设置需要报告 `client-ipv6/1` 的 Agent。旧版 Agent 会将开关显示为灰色，并提示「请更新此节点的 Agent，以关闭该设置」；面板不会向其发送该设置。重新开启 IPv6 始终有效。每次更改都会写入审计日志（`node.update`，其中的 `client_ipv6` 为开启或关闭）。

**拦截已识别的 BitTorrent 流量**默认关闭。开启后，节点会拦截其用户发起的明文 BitTorrent 流量（AmneziaWG 在内核中拦截，Hysteria2 在其引擎中拦截），并写入不含地址的 `torrent_attempt` 事件。此功能需要支持该功能的 Agent。请参阅[BT 下载拦截](torrent-protection.md)。

**此节点的 DNS 服务器**：**服务器自身的 DNS 解析器**（默认）、**Yandex DNS**或**Cloudflare + Google**；自定义 DNS 列表（最多 8 个 IP 地址，也可使用 `ip:port`）会显示为**自定义 DNS**，并可在此处编辑。节点及其 VPN 引擎使用这些服务器解析名称，也包括用户流量中的名称。选择**服务器自身的 DNS 解析器**时，节点会使用服务器当前的 DNS 设置。俄罗斯节点请选择 **Yandex DNS**，以便可靠解析 gosuslugi.ru 等俄罗斯服务。它们不是应用收到的 DNS 预设；诊断也会单独检查服务器自身的解析器：请参阅 [DNS](dns.md)。

**用户页面上的 DNS 选择**是节点的单独设置，不要与上述解析器混淆。所有者在此勾选用户可在此服务器页面上选择的 DNS 预设（顺序即为页面上的显示顺序），并指定此节点的默认项。只有所有者可以更改此设置；更改会写入审计日志（`node_dns_options`）。未提供预设的节点不会显示选择项。只有在**订阅** → **用户页面**中开启**页面上的 DNS 选择**时，此设置才会生效；它适用于 AmneziaWG 密钥和 Mihomo 配置中的 AmneziaWG 代理。请参阅 [DNS](dns.md)。

### 历史

节点上发生过什么，分为三部分，在标签页顶部切换：**事件**、**运行记录**和**日志**。所选部分保存在地址中，链接或刷新页面会再次打开它。

#### 事件

按日期分组的节点历史记录：连接、失去响应、恢复连接、添加协议配置、协议配置启动、启动失败和重启、应用设置、Agent 更新和回滚、证书续期、AmneziaWG 模块构建，以及识别出的 BitTorrent 尝试。相关事件会合并为一行。BitTorrent 事件会包含入站和协议，但不包含地址（客户端地址或目标地址）；只有节点能可靠识别用户时，面板才会添加用户名。

**全部**、**问题**、**协议配置**和**Agent**标签可筛选列表。**详情**会打开该行对应的原始事件，显示事件代码、准确时间、来源（**节点 Agent**、**面板**或**管理员操作**）和参数。事件按页显示，每页 50 条（也可请求 25 条或 100 条），按时间从新到旧排列；**较早**会返回更早的事件，**较新**会回到进入当前页前所在的页面。页码保存在地址中，因此刷新页面或复制链接后仍会保留。筛选结果在当前页为空时，**继续搜索**会转到更早的一页。

#### 运行记录

面板保存 7 天的节点警告和错误：即 Agent 及其引擎（Hysteria2、VLESS、AmneziaWG、xray、WARP）以**警告**和**错误**级别写入的内容。每一行是一小时内的一类记录：最近一次的时间、级别、来源、记录涉及的协议配置、出现次数（**×12**）、消息及其详情。客户端地址在节点上即被移除，并在面板中再次清理，因此所有管理员都可以查看运行记录；消息是引擎写入的模板，不含单个连接的具体值。

- **24 小时**或 **7 天**；**警告和错误**或**仅错误**。
- **搜索运行记录**在面板端搜索该时间范围内所有行的消息和详情。最多显示 200 行，最新的在前；超出时标签页会提示。

如果节点的 Agent 尚不发送运行记录，运行记录会提示：请更新 Agent。在 Cloudflare 版中没有实时日志，**日志**会引导到这里。同一运行记录也可在 MCP 中通过 `node_journal` 获取。

#### 日志

由面板转发的 Agent 及其引擎实时日志。首先显示最近 200 行，随后显示新写入的行；屏幕最多保留 1,000 行。

- **全部**、**信息**、**警告**、**错误**按级别筛选；**搜索日志**按文本筛选。
- **暂停**会冻结屏幕，后台仍会接收新行；**继续**会重新显示日志。
- **下载**会将已接收的内容保存为 `<node>-agent.log`。

Agent 已连接（**正常**或**无流量**）时，此部分可用。如果连接中断，系统会每 5 秒重新连接。只有所有者能查看日志，其中包含客户端地址。所有管理员都可以查看[运行记录](#运行记录)。

### 诊断

节点自身的主机检查分为**需要关注**、**已标记为正常**、**全部正常**和**未检查**，并列出面板可执行的修复和其余项目的手动步骤。**重新检查**会要求节点生成新报告。Agent 连接后约 30 秒会收到第一份报告；Agent 版本过旧而无法运行诊断时，会显示指向**更新**的链接。请参阅[运行状况](../operations/health.md)。

### 服务器

这是一台什么机器。宽屏时分两栏：左侧是一个表单（**节点**、**带宽**和 **Agent 连接**），末尾只有一个**保存**按钮，其下是 **Agent** 卡片；右侧是 **SSH 凭据**（通过 SSH 安装的节点）、**伪装站点**、**AmneziaWG 后端**和**主机**。**危险区域**位于最后。窄屏时按相同顺序排成一栏。

- **Agent**：版本；版本落后时显示 **Agent 版本过旧**并链接到[更新](../operations/updates.md)；旧版 Agent 不支持的功能（参见 [Agent 版本和状态漂移](#agent-版本和状态漂移)）；以及仅所有者可见的**新安装命令**，适用于证书丢失或服务器重装的情况：请参阅[添加节点](../getting-started/add-node.md)。
- **SSH 凭据**卡片显示已保存的 SSH 服务器和用户名；重新登录确认后，**显示密码**会显示密码。密码的保存和更改方式见[通过 SSH 安装节点](../getting-started/ssh-install.md)。
- **伪装站点**：节点向非客户端显示的内容；请参阅[自有伪装站点](decoy-site.md)。
- **AmneziaWG 后端**：节点运行 AmneziaWG 的方式；请参阅 [AmneziaWG](amneziawg.md)。
- **主机**：Agent 报告的主机名、操作系统、内核、架构、CPU、RAM、磁盘、虚拟化、IPv6、启动时间和引擎版本。

| 字段 | 作用 |
|:--|:--|
| **名称** | 使用 a–z、0–9 和连字符，长度为 2–24 个字符，且不能重复。 |
| **地址** | 客户端连接所用的域名或 IP，不含 `https://` 或端口。更改地址会更改所有订阅中的地址。 |
| **国家** | 两个字母的国家代码，或**未设置**。应用中的服务器名称会使用此值（{flag} {country}）；对于俄罗斯节点，诊断会检查 gosuslugi.ru 并提供 Yandex DNS。 |
| **位置** | 名称旁显示的自定义文本（「法兰克福」）。留空时显示国家名称。 |
| **服务商** | 供你辨识的主机服务商。 |
| **网络带宽** | 可选，单位为 Mbps：服务商提供的对称带宽上限。节点负载取 CPU 使用率和链路较繁忙方向相对带宽上限的占比两者中较高的一项；未填写带宽上限时只使用 CPU 负载（单核 VPS 通常会先耗尽 CPU）。Happ 中的服务器名称会以负载结尾（「 · 64％」），用户页面会显示负载等级：低、中或高（从 50% 和 80% 起）。不会显示实际速率，也不会显示在其他应用中，因为那些应用中的名称必须保持稳定。0 表示未知。**测速**可以填写此值：见下文。 |
| **备注** | 最多 500 个字符的自定义文本。 |
| **Agent 连接断开时间** | 30–600 秒，默认 90 秒。如果 Agent 静默时间更长，面板会关闭连接。节点会先变灰（**主机闪断**）；10 分钟没有联系后会变为**无法连接**。 |
| **等待命令结果** | 10–900 秒，默认 120 秒：面板等待命令结果的时长，超时后视为无响应。 |
| **Agent 拨号超时** | 5–120 秒，默认 15 秒：Agent 连接面板时的等待时长。 |

**保存**只会提交更改过的内容；**出口**标签页的表单单独保存自己的字段，两者不会互相覆盖。大多数设置无需重新连接即可生效。

#### 测量网络带宽

服务商通常不会说明实际带宽，虚拟服务器的网卡也不会报告套餐上限，因此节点可以测量自身到互联网的速度。所有者可在**网络带宽**旁点击**测速**。每次测量连续运行**三轮**，每轮间隔一秒，分别取每个方向的最快结果。每轮中，Agent 会通过 6 个并行连接从无需账户的公开测速服务器下载约 5 秒；忽略第一秒（TCP 仍在提速）；随后通过 4 个连接向同一服务器上传约 2 秒。Agent 按以下顺序选择服务器：

1. **最近的 Ookla（Speedtest.net）服务器。** 节点会查询公开的 Speedtest.net 服务器列表；列表根据节点自身地址地理定位，因此会返回节点附近（通常位于其服务商网络内）的服务器。Agent 会向每台服务器发送简短的 HTTPS 请求，选用延迟最低的服务器；如果它无法提供服务，则选用延迟第二低的服务器。测试会向该服务器发送 `GET /download?size=N` 和 `POST /upload` 请求。这些服务器通常比 Cloudflare 更近、速度更快，也更少受限制；有些国家会限制 Cloudflare。
2. 如果列表或其中的服务器没有响应，则使用 `speed.cloudflare.com`。Cloudflare 会限制同一地址的请求频率（HTTP 429），因此每轮间隔 3 秒；遇到 HTTP 429 时，按 `Retry-After` 最多等待 2 秒后继续，不会终止本轮；每个请求都会申请允许的最大数据量 50 MB。
3. 如果也无法连接 Cloudflare，则依次使用 `proof.ovh.net` 和 `cachefly.net` 上的文件（仅下载）。

整个测量约需 30 秒，最多传输 1.5 GB（每轮最多下载 400 MB、上传 100 MB），无论服务器状况如何，都会在 45 秒内结束。同一节点一次只能运行一项测量。

面板会显示「测得：940 Mbps ↓ · 870 ↑」，旁边有**使用 870**。它会将两个方向中**较慢的**速率四舍五入后填入字段（低于 100 时取 5 的倍数，低于 1,000 时取 10 的倍数，高于此值时取 50 的倍数）：VPN 节点需要双向转发每个字节，而服务商经常不限制入站流量，却会限制出站流量（1 Gbit/s 套餐中的节点可能测得下载 5,000 Mbps、上传 1,000 Mbps）；没有上传数据时则使用下载速率。新节点的首次测量会保存相同数值；只有点击**保存**后才会保存其他更改，测量本身不会自动覆盖你输入的数值。上传测试使用 Ookla 和 Cloudflare；如果节点改用 OVH 或 CacheFly，便不会测量上传速度。

**面板会说明各轮测量结果。** 数值下方会显示所用服务器（「经由 Ookla · MTS，莫斯科」表示 Ookla 服务器的赞助方和城市）以及成功轮数；全部成功时显示「3 轮中的最佳结果」。部分轮次失败时会说明失败情况和原因：「3 轮中有 1 轮成功：其他轮次失败，服务器限制了请求」。原因包括：服务器限制请求（HTTP 429）、未能及时响应、完全没有响应、返回错误代码，或剩余时间不足以开始测量。成功轮数越少，结果越不可靠，因为轮数较少时测出的最快值通常更低：请再次点击**测速**。

**节点上现有用户的流量也会计入。** 每轮计入的时间段内，Agent 还会读取节点主网络接口的字节计数器（节点负载读数也来自同一计数器）。每轮中，每个方向的估值取测速本身传输量和该时间段内整个网络接口传输量中的较大值，因此测速期间节点用户传输的数据也会计入带宽估值。若网络接口的传输量超过测速本身（并计入测速自身的协议开销），面板会添加「包含用户流量：35 Mbps ↓」。这部分已经包含在数值中，不会额外叠加。无法读取计数器时，只计算测速数据。

此数值是估算值，不是服务商的带宽上限：

- 这是三次短时测试，结果取决于节点到测速服务器的路由；这条路由可能比节点到用户的路由更慢或更快。
- 测量反映节点**当前**可用的带宽，用户会受到测速影响：在这 30 秒内，用户速度可能下降。
- 极快的链路（超过几 Gbit/s）会在一两秒内触及每轮下载 400 MB 的上限，因此结果只是下限。
- 结果会说明哪台服务器作出响应以及成功轮数。如果服务商说明了带宽上限，请使用服务商给出的数值。

只有所有者可以测速（API 会拒绝令牌和 MCP 请求），每次测量都会写入审计日志（`node.bandwidth_measure`）。节点需要运行此版本或更新版本的 Agent；Agent 版本过旧时，面板会显示「Agent 过旧」且不会发送请求；同时节点必须保持连接。节点必须能够通过出站 HTTPS 访问测速服务器：`www.speedtest.net`（服务器列表）和列表中的 Ookla 服务器（端口 8080），或备用服务器。

**新节点**会自动测量一次：Agent 首次在安装后连接约 45 秒后，如果**网络带宽**仍为 0，则执行测量。这是面板唯一会自动写入该字段的情况，且仅当字段为 0 时才会写入。结果会记录在节点事件（「首次启动时测得网络带宽」）和审计日志（`node.bandwidth_auto`）中。面板保存两个方向中较慢的速率，且只有同时测得上传速率时才会保存：如果仅下载测试有响应（测速服务器拒绝上传），则不会写入数值，并会生成警告事件（「首次测量未能……，没有上传数据」），因为链路下载快于上传时，仅使用下载结果会高估带宽。请点击**测速**并手动填写数值。Agent 版本过旧或测速失败的节点会被跳过且不显示消息：请自行点击**测速**或输入数值。

> **注意：** AmneziaVPN 密钥中保存着签发时使用的节点地址。更改**地址**后，此节点上的 AmneziaWG 协议配置设备会被标记为过时；使用密钥连接的用户必须重新导入密钥（从用户页面或用户卡片导入）。订阅类应用会在下次更新时获取新地址。[IPv6 入口](#ipv6-入口)绝不会改动这些密钥。

#### 重命名节点

更改**名称**并保存。节点名称会显示在面板和 AmneziaWG 配置文件名中；只有模板使用 `{node}` 时，它才会显示在应用的服务器名称中。默认模板使用国家和协议配置名称。请参阅[订阅](subscriptions.md)。

### 危险区域：退役节点

**从集群退役**会永久移除节点。对话框会列出后续影响：

- 用户的订阅中不再包含此节点；他们的链接保持不变；
- 节点证书会被吊销，其 Agent 会收到停止运行的指令；服务器上的文件会保留；
- 节点记录及其流量历史会保留在审计日志中。

输入节点名称以确认。之后，节点会从列表中消失；如果打开其页面，会显示「此节点已退役」。已退役的 Agent 无法再次连接。只有所有者可以退役节点。

通过 SSH 安装的节点退役后仍会保留**SSH 凭据**卡片：面板不再更改此服务器，但你仍可查看已保存的密码；**清除已保存的凭据**需要重新验证并确认两次，之后会永久删除凭据。如果保存的密码由面板生成，退役对话框会先发出警告，因为只有面板知道该密码。

如果节点处于离线状态，Agent 不会收到指令，并会继续为现有用户提供服务。此时面板会停留在节点页面，并显示「{name} 未收到指令」以及手动清理服务器所需的命令；这些命令与[添加节点](../getting-started/add-node.md)中「移除节点」部分相同。

没有其他删除节点的方式：退役即为移除。之后如需清理服务器，请以 root 身份运行：

```sh
systemctl disable --now mistgate-node
rm /etc/systemd/system/mistgate-node.service /usr/local/bin/mistgate-node
rm -r /var/lib/mistgate-node
```

这些路径是 `mistgate-node install` 的默认值；如果安装时使用了其他 `--bin` 或 `--state-dir` 值，请使用相应路径。

## Agent 版本和状态漂移

- **Agent 版本过旧。** 面板知道当前附带的最新 Agent 版本。运行旧版本的节点会在列表和页眉中标记为**Agent 版本过旧**。某些功能需要较新的 Agent，例如诊断、WARP 和自动构建 AmneziaWG 内核模块。请从[更新](../operations/updates.md)页面更新。
- **能力。** Agent 会列出自己支持的功能，面板只向列出该功能的 Agent 发送它。`user-rate-limit/1` 表示 Agent 能在节点上让同一用户的多台设备共享一个限速（Hysteria2 和 VLESS）。缺少它的 Agent 所在的节点，会把每台设备限制在用户限速和设备限速中较小的一个，节点**服务器**标签页的 **Agent** 卡片会对此作出提示：「此节点上的 Agent 无法在同一用户的多台设备之间共享限速……」。更新 Agent 后，用户限速才会生效。参见[用户和分组](users-and-groups.md#限制)。
- **状态漂移。** 面板会将完整的期望状态发送给每个节点，并比较期望状态与节点已应用状态的哈希值。两者不同时，面板会重新发送状态（事件为「节点状态与面板不一致，已重新发送」）。节点仍应用不同状态时，会显示**需要关注**和「节点状态与面板不一致」，并触发告警。请重启协议配置；如果问题再次出现，请查看节点日志。
- **时钟偏差。** 服务器时钟与面板不一致时，节点会显示相关提示。时钟错误会导致证书和握手失败；请在服务器上开启时间同步（`timedatectl set-ntp true`）。

## 谁可以执行哪些操作

所有管理员都可以查看节点。所有者和协作者可以更改节点设置（地址除外）并重启协议配置。只有所有者可以更改节点地址、通过 SSH 安装节点、生成安装命令、查看和清除已保存的 SSH 凭据、退役节点、查看日志、将协议配置部署到节点、关闭或开启**IPv6 出口**、检测和更改 **IPv6 入口**以及构建 AmneziaWG 内核模块；中转和**添加入口…** 也只有所有者可用（参见[入口](#入口)）。请参阅[安全](../operations/security.md)。
