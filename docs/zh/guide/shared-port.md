许多网络只放行 TCP 443。节点可以在这个端口上同时运行多个 TCP 服务：VLESS REALITY、基于 TLS 的 VLESS、TrustTunnel 和 MTProto。节点代理读取客户端在连接最初几个字节里请求的**名称**（SNI，即 TLS 握手中的主机名），再把连接交给占用该名称的服务。途中不解密任何内容，前端自己也不回应任何东西。本页说明谁可以共用端口、陌生访问者会看到什么、需要提前准备什么（每个服务一个名称和一条 DNS 记录），以及如何设置。

端口上只有一个服务时，一切照旧：只有当同一个 TCP 端口上有两个或更多服务时，代理才会额外启动这个监听器。

## 谁可以共用端口

| 服务 | 它响应的名称 | 在共用端口上 |
|:--|:--|:--|
| VLESS REALITY，节点自身站点 | 该服务器的**域名 (SNI)**，默认是节点的名称 | 可以。它展示节点自己的站点，所以可以成为默认服务 |
| VLESS REALITY，其他站点 | 该站点的名称（**服务器名称**，或目标的主机） | 可以，前提是另有服务展示节点自己的站点。使用该名称的访问者会看到别人的站点 |
| 基于 TLS 的 VLESS（XHTTP、WebSocket） | **域名 (SNI)**，在 CDN 之后还有 CDN 主机 | 可以。展示节点自己的站点 |
| TrustTunnel，HTTP/2 | **域名 (SNI)** | 可以。展示节点自己的站点 |
| MTProto，**本节点的名称** | 它的域名：节点的名称或**域名 (SNI)** | 可以。展示节点自己的伪装站点 |
| MTProto，**其他站点** | 该站点的域名 | 可以，前提是另有服务展示节点自己的站点。使用该名称的访问者会看到别人的站点 |
| Hysteria2，它在 TCP 上的 HTTPS 站点 | 无 | 不可以。站点仍会把自己的 TCP 端口让给任何 TCP 协议配置：[同一节点上的 VLESS 与 Hysteria2](vless-and-hysteria2.md) |
| Hysteria2、AmneziaWG、带 HTTP/3 的 TrustTunnel | 无（UDP） | 不可以。UDP 端口永远不共用：TrustTunnel 开启 HTTP/3 后与 Hysteria2 同占 UDP 443 仍会被拒绝 |

保存时面板会检查这些规则：

- **每个服务都有自己的名称。** 面板按名称精确比较，小写，末尾不带点。两个服务用同一个名称会被拒绝（`sni_taken`）。已关闭的协议配置也计算在内，这样以后启用它时不会破坏端口。名称必须是 ASCII 主机名，含一个点，没有 `*`，也不是 IP 地址：客户端从不会把 IP 地址放进 SNI。没有这样名称的服务（例如目标是 IP 地址、又没有**服务器名称**的使用其他站点的 REALITY）不能共用端口（`share_unsupported`）。
- **至少有一个服务展示节点自己的站点。** 在这样的服务里，id 最小的是**默认**服务：所有没有指明服务的访问者都交给它。两个都展示别人站点的服务不能共用端口（`share_needs_site`）。
- **只有 VLESS、TrustTunnel 和 MTProto 参与。** 中继的入口和桥不是端口上的服务：面板对它们的端口照旧处理。
- **代理必须声明 `tcp-share/1`。** 旧代理的情况见下面的“节点上会发生什么”。

## 访问者会看到什么

| 访问者发来的内容 | 谁来回应 |
|:--|:--|
| 某个服务的名称 | 该服务，就像它独占端口一样 |
| 没有名称（按 IP 地址探测），或没有任何服务占用的名称 | 默认服务，即节点自己的站点 |
| 不是 TLS（普通的 `http://` 请求、杂乱数据）、损坏的握手、超过 16 KiB 的握手 | 默认服务，连同已经收到的字节 |
| 未运行的服务的名称，或 5 秒内不接收连接的服务（它正在重启） | 默认服务 |
| 10 秒内没有收到完整的握手 | 连接被关闭 |

服务看到的是访问者的真实地址，而不是 `127.0.0.1`：连接在代理内部传递，不使用 PROXY 协议。

对于你自己的服务和你自己的名称，端口看上去就像一台带有多个站点的普通主机。展示别人站点的服务会带来两张面孔：使用其名称的访问者看到那个站点，没有名称的访问者看到默认服务的站点，尝试大量名称的人可以分辨出这两者。面板会就此警告（`share_two_faces`）。

## 名称、DNS 记录和证书

端口上的每个服务都需要一个指向节点的名称。面板会建议 `<单词>.<节点地址>`：从 `cdn`、`static`、`media`、`assets`、`files`、`img`、`edge`、`app` 中取第一个未被占用的，也就是一个普通网站的中性名称。以 IP 地址标识的节点没有建议：请填写你可控的域名。已有服务保留自己的名称，所以 `tg://` 链接和订阅不会变化。

面板在名称旁显示 DNS 记录，包含类型、名称和值，并带有**复制记录**按钮。请在域名的 DNS 托管处添加，**不要代理**（Cloudflare 上用灰色云朵）：

| 记录 | 适用情况 |
|:--|:--|
| `A` | 节点以 IPv4 地址标识：值就是该地址 |
| `CNAME` | 节点以主机名标识：值就是该名称。如果你的 DNS 在这里不接受 CNAME，请改用指向节点 IPv4 地址的 `A` 记录 |
| `AAAA` | 节点以 IPv6 地址标识 |

面板不会查询这条记录，也不会等待它：你添加记录，名称指向节点后，节点会自行向 Let's Encrypt 申请该名称的证书。在此之前，服务显示的是它自己页面上说明的“证书尚未签发”的状态。Let's Encrypt 既通过 TCP 443（TLS-ALPN-01）也通过 TCP 80 验证：针对某个服务名称的请求会交给该服务，针对节点任何其他名称的请求会交给默认服务，由它应答。只需要名称不经代理并指向节点。

每个新名称都意味着一张证书。Let's Encrypt 限制每个注册域名新签发的证书数量（约每周 50 张），并把每一张都写入公开的证书日志，所以请让名称保持中性且数量不多。

## 把一个服务并排放在另一个旁边

### 在管理后台

1. 在节点的**协议配置**标签页点击**添加协议配置**，或某台服务器的**编辑**，或在协议配置页面点击**部署到节点**。选择另一个服务已占用的端口（443）。
2. 面板会检查你的选择（见[协议配置](profiles.md)）。新服务通常从节点自己的名称开始，而这个名称已被第一个服务占用，所以面板会说名称已被占用（`sni_taken`）。如果端口可以共用，回答是：**与“Main”并排放在端口 443**，一个带建议名称的输入框和按钮**并排放在 443**，旁边还有**使用 8443**，即旧的出路。展示别人站点的服务没有可自行设置的名称，因此只会得到拒绝。名称空闲的服务根本不会被拒绝：对话框只是说明端口是共用的（第 3 步）。
3. **并排放在 443** 会把名称填入**域名 (SNI)** 字段，并重新检查。通过后（或者名称一开始就空闲），对话框会说明谁会重启（原本独占端口的服务；其已打开的连接会重新连接）、新服务响应哪个名称，并显示 DNS 记录。
4. 添加记录，然后点击**添加**或**保存**。

点击前可能出现的警告：`tcp_port_shared`（端口共用、谁是默认服务、谁会重启）和 `share_two_faces`。拒绝有 `sni_taken`、`share_needs_site`、`share_unsupported` 和 `share_agent_old`；对话框会逐一说明，并在有空闲端口时提供它。

### 通过 MCP

`profile_create` 和 `profile_deploy` 在 `port_overrides` 旁接受 `sni_overrides`，即“节点 id → 新服务器在该节点上使用的名称”的映射。只能指定已选中的节点，名称必须是带点的主机名，不能是 IP 地址。计划会显示端口、`sni` 和警告，与对话框做的检查相同；拒绝的形式是 `sni_taken: name=de1.example.com&node=de1&port=443&profile=Main&share=1&suggest=cdn.de1.example.com`，节点有域名时才有 `suggest`。计划不会写出 DNS 记录，也不会检查它：请告诉所有者需要添加哪条记录。应用需要所有者批准，与其他协议配置的更改一样。MCP 里没有工具可以设置已在节点上的某一台服务器的端口或**域名 (SNI)**；请在管理后台完成。见 [MCP](../reference/mcp.md)。

## 共用端口的卡片

当一个 TCP 端口上有两个或更多服务时，节点的**协议配置**标签页会出现 **TCP 443 为共用端口** 卡片。每个服务一行：协议配置、名称，以及它已获得的连接数；**默认**标记指出默认服务。各行下面是代理自启动以来的计数：

| 计数 | 统计的内容 |
|:--|:--|
| **已接受** | 端口接受的连接 |
| **转给默认服务** | 未带名称、名称未知、不是 TLS、握手损坏或过大的访问者，以及服务不可用的访问者 |
| **已拒绝** | 因服务未及时接收，或无处可送而关闭的连接 |
| **服务不可用** | 名称属于未运行的服务：访问者被转给了默认服务 |
| **沉默 10 秒** | 10 秒内没有发送任何数据而被关闭 |
| **被挤出** | 端口被淹没时，为腾出空间而丢弃的未完成握手 |

“已拒绝”“服务不可用”和“被挤出”大于零时会变黄。计数下面是访问者请求过、但没有服务占用的名称，最多五个最常见的（只有主机名，没有地址），以及代理最近一次上报的时间。代理随统计一起发送快照，面板在其构成变化时写入，最少每 5 分钟写一次，所以计数会滞后几分钟。代理尚未上报的端口，卡片会如实说明。

未完成握手的洪泛还会产生事件 `front_overloaded`，每个节点每小时最多一次。端口上的服务继续运行；代理会丢弃最旧的未完成连接。

## 节点上会发生什么

- **重启。** 端口变为共用或不再共用时，原本独占它的服务会重启：其已打开的连接会重新连接。当又一个服务加入已有两个或更多服务的端口时，只有新服务启动。当一个服务离开、只剩一个时，剩下的那个会重启。代理重启会重启所有服务，无论端口是否共用。访问重启中服务的访问者最多等待 5 秒，然后转到默认服务。
- **旧代理。** 没有 `tcp-share/1` 的代理不能共用端口。在节点的能力已知时，在该端口保存第二个服务会被拒绝（`share_agent_old`）。尚未上报过的节点不会被拒绝：部署时面板只向旧代理发送默认服务，其余服务保持未发送，并标记 `share_agent_old`。卡片会写**此节点暂时无法共用端口**，并提供**打开更新**按钮。更新之后它们会自行启动。
- **端口被其他程序占用。** 代理无法占用它，端口上的所有服务都不运行，卡片会写**节点无法占用端口 443**并附上错误。代理会自行重试。
- **名称后来冲突了。** 例如你改了节点的地址，由它生成的名称现在等于另一个服务的名称。其中一个保留该名称，另一个不会启动并显示 `sni_shadowed`。请为它设置专属名称。
- **服务失败。** 它的名称会转给默认服务，直到它再次运行；其他服务不受影响。

## 限制

- 名称按精确匹配。不支持通配符，一个名称也不能指向两个服务：不会构建 REALITY、再到 MTProto、再到站点这样的链条。
- 前端不按访问者地址限制：在中继、桥或移动网络之后，许多人共用一个地址。每个端口最多保留 1024 个未完成的握手，超出时丢弃最旧的，并且最多读取 16 KiB 的握手。
- 只以 IP 地址标识的节点不能共用端口：专属名称需要域名。
- UDP 不共用。Hysteria2 和 AmneziaWG 保留自己的 UDP 端口；TrustTunnel 的 HTTP/3 需要自己的 UDP 端口。
- 计数在代理重启时清零。
