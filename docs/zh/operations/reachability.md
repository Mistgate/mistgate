客户端视角检测从面板所在的服务器发出，而它不在你的用户所在的国家，看不到那里的封锁。因此由五个来源从某个国家境内（默认俄罗斯）检测：[Globalping](#globalping)、[封锁名单](#封锁名单)、[TSPU 探测](#tspu-探测)、[cheburcheck](#cheburcheck) 和 [bsbord](#bsbord)。每个来源都是独立的集成，**默认关闭**。面板把它们的结果[合并](#来源如何并入结论)为每个节点的一个结论，保留一周，并在节点无法访问时打开[告警](#告警)。[kl!ck 报告](#klck-报告)显示在它们旁边，不改变结论。

## 在管理后台中

**可达性**是菜单中单独的一个部分，紧跟在**运行状况**之后（手机上在**更多**里）。能打开运行状况的人都能打开它；来源和国家归所有者管理，更改来源时需要重新确认身份。

- **页头**：各来源检测所用的国家，所有者在这里选择。国家（默认 `RU`）是一项共享设置，所有来源都从它出发。封锁名单、TSPU 探测、cheburcheck 和 bsbord 只适用于俄罗斯。旁边的链接可直接跳到*节点*、*事件*和*来源*。
- **汇总**：可访问、TCP 被封锁、无法连接、在名录中（在封锁名单中，未经实测）和无数据的节点各有多少，颜色和标记与运行状况一致。所有来源都关闭时，这里会说明这一点，并指向来源。页面还会点出连你的任何节点都连不上的网络：这不会触发告警，因为该网络对所有节点一视同仁地切断。
- **节点**：每个节点当前的结论（提示与运行状况中相同），以及每个来源（Globalping、封锁名单、TSPU 探测、cheburcheck、自有探测点、bsbord）各一行：该来源当前的结论，以及最近 7 天结论的时间条。时间条由按结论着色的分段组成；悬停或聚焦某一段可查看它的结论和起止时间，也可以用方向键在时间条中移动。已关闭的来源会变暗，时间条为空。屏幕宽度小于 1280 像素时，每个节点变成一张卡片，时间条位于结论下方。Globalping 同时检测 IPv6 时，结论显示为 *IPv4* 和 *IPv6* 两个标签，Globalping 下还有一条 IPv6 时间条，见 [IPv6](#ipv6)。
- **最近事件**：最近 7 天的 `country_blocked` 告警（包括未关闭和已关闭的），每条都链接到**运行状况 → 告警**中的该告警。
- **来源**：[Globalping](#globalping)、[封锁名单](#封锁名单)、[TSPU 探测](#tspu-探测)、[cheburcheck](#cheburcheck)、[bsbord](#bsbord) 和 [kl!ck 报告](#klck-报告)的列表，每项注明它是什么（免费或付费）、从哪里检测（*仅限俄罗斯*或*任意国家*），并用一个词说明状态（*正常*、*已关闭*、*出错*、*待设置*）。选中一项即可打开：开关和状态，然后是分块的设置（*连接*、*检测*、*预算*）、发送内容与去向，以及*测试*和*断开连接*按钮。宽屏上列表固定在左侧，来源在右侧打开；较窄的屏幕上列表变成顶部的一组卡片；手机上点按即可打开来源，*全部来源*返回列表。可用方向键、Home 和 End 在列表中移动，Enter 打开。打开的来源记录在地址中（`?source=bsbord`），因此链接或刷新都会保留它；没有该参数时打开第一个已开启的来源，若都未开启则打开 Globalping。

**运行状况 → 检测**仍以最后一列「从俄罗斯访问」显示结论（手机上为每个节点下的一行），节点页面上也仍有一行。所有来源都关闭时它们不显示，它们的标题会链接到此部分。API 中的最近一周为 `CountryReachabilityService.GetReachabilityHistory`：最多 7 天，与 `GetChecks` 一样，所有角色和 API 令牌都可读取。

## Globalping

第一个来源请该国境内的探测点（优先家庭宽带和移动网络）对每个在线节点做 ICMP ping，并与其各个 TCP 端口建立连接，再比较结果。它使用免费的探测网络 [Globalping](https://globalping.io)。开启后，每个在线节点的 IPv4 地址会发送给 Globalping，不会发给其他任何人；IPv6 开关打开时（默认），IPv6 可用的节点的 IPv6 地址也会一并发送。

- **位置**：**可达性 → 来源**中的「Globalping」卡片。
- **设置**（仅所有者）：开关、间隔分钟数（默认 15，最少 10）、IPv6 开关（默认开启：IPv6 可用的节点还会按其 IPv6 地址单独测一轮，控制站点须能通过 IPv6 访问，因此没有 IPv6 的探测点不会被算作该节点不可达；两轮共用下面的额度，所以没有令牌时轮次会稍稀一些），以及可选的令牌（只写，可把免费额度从每小时 250 次提高到 500 次）。**测试**只读取 Globalping 的额度接口，不发送任何地址。**断开**会关闭集成并忘记令牌。
- **关闭就是关闭。** 集成关闭时不会开始任何一轮，也不会发送任何内容；正在进行的一轮会在你关闭时取消。已保存的结果保留 7 天，但 API 不再返回。
- **检测内容。** 每轮有三个探测点参与（预算不足时为两个），记其数量为 K。对俄罗斯，其中最多 K-1 个取自点名的运营商，另有一个随机的家庭或移动探测点，用来发现面板没有点名的网络。点名的运营商是 MTS、Beeline、MegaFon、Rostelecom、T2（Tele2）和 ER-Telecom，各按其 RIPE 组织名下的 AS 号识别。其他国家没有名单，探测点全部随机，与以前一样。每个节点会被 ping 地址，并对其已启用协议配置的每个 TCP 端口做 TCP ping（VLESS，以及 Hysteria2 的 HTTPS 网站）。只有 UDP 协议配置的节点只做 ICMP ping：Globalping 没有 UDP 测试。
- **选哪些运营商。** 每轮面板读取一次 Globalping 的在线探测点列表（`/v1/probes`：免费，不计入额度），为每个需要的运营商在其网络中挑一个家庭或移动探测点。顺序：先是最近一次 `partial` 轮中的无应答探测点（见下），在同一网络、同一城市再问一次；然后按轮换排运营商，从未问过的在先，其次是最久没问的。四个运营商在线时，每个至少每两轮问一次（K=3）或每四轮问一次（K=2），默认间隔下分别是 30 分钟和 1 小时。被再次询问的网络占用点名名额，所以某个网络持续无应答时，其余运营商轮换得更慢。运营商的探测点一旦被选中就算问过，即使它随后没有执行任何测试。
- **暂无探测点。** 在线没有家庭或移动探测点的运营商会在询问前被跳过，不花任何额度，并在该轮记为 `no_probe`：小运营商常常没有。若列表读取失败，该轮按有运营商之前的方式进行：一个随机位置，`no_probe` 为空。
- **对照。** 每轮同样的探测点还会对该国一个永远不会被封的大型网站（`RU` 为 `ya.ru`）的 TCP 443 发起连接；连不上的探测点本轮作废。有效探测点少于两个时，结论为 `unknown`。
- **节点结论。** `ok`：至少一半的有效探测点能建立 TCP 连接（没有 TCP 端口的节点则看 ICMP）。`tcp_blocked`：至少一半的探测点 ICMP 有应答，但所有探测点的 TCP 都不通：连接请求被丢弃，而地址本身没被封。`blocked`：什么都不通。`partial`：见下一条。`unknown`：探测点太少、触及额度、出错、超时，或结果互相矛盾、说明不了什么。
- **`partial` 与无应答探测点。** 一轮对某节点为 `partial`，条件是按多数本应是 `ok`（或结果矛盾），但有一个家庭或移动探测点从该节点什么也收不到，连 ping 也没有，而同一轮里它却能连到您的另一个节点，同时另有探测点连上了这个节点。这样的探测点对该节点是**无应答**（`dark`）的：只有一个网络被切断，其余网络都能看到它，而单看多数会判为 `ok`。只有探测点做完了该节点的全部测试，才算无应答：超时或探测点一侧的故障不会让它被判为无应答。`tcp_blocked`、`blocked` 和因探测点太少而得的 `unknown` 保持不变。
- **不会出现 `partial` 的情况。** 只有一个节点的集群永远不会得到它：没有其他东西能证明探测点本身可用。丢弃 ping 的网络不会让没有 TCP 端口的节点变成 `partial`：对这种节点，探测点只有靠 ping 连到另一个节点才算连通，而收不到 ping 应答的探测点不算无应答。回退到数据中心探测点的一轮（有效的家庭或移动探测点少于两个）也不会是 `partial`。K=2 时随机探测点可能与点名的撞在一起；该轮只剩一个探测点，会在任意网络（含数据中心）上重来，在 2026 年 10 月的探测点列表里，这类轮次约每六轮出现一次。K=3 可避免大部分。
- **预算。** 一轮消耗（1 次对照 + 每个节点 1 次加其 TCP 端口数）x 探测点数 个测试。若一小时内各轮会用掉额度的 80% 以上，探测点减为两个；仍然太多就拉长间隔（面板会在日志中记录一次）。触及额度时该轮为 `unknown`，下一轮等额度重置后再进行。点名的探测点包含在这些探测点之内，探测点列表又是免费的，所以公式保持不变。
- **两种版本。** VPS 面板每 30 秒查看是否到期；Cloudflare 版从每分钟一次的 cron 运行。

## 封锁名单

国家视角检测的第二个来源：面板把每个已启用节点的 IPv4 地址与公开的封锁地址名单比对。名单会下载到面板并在面板上比对，因此节点地址不会离开面板。它是一项独立的集成，**默认关闭**，并且只适用于俄罗斯：选择其他国家时，卡片会说明这一点，也不会下载任何内容。

- **位置**：**可达性 → 来源**中的「封锁名单」卡片。它的结论计入该部分中节点的结论、「从俄罗斯访问」列和节点页面上的那一行。
- **名单。** antifilter.download 的 [`ipsum.lst`](https://antifilter.download/list/ipsum.lst)，即汇总到 /24 网段的 RKN 封锁名录；主地址无响应时改用镜像 [antifilter.network](https://antifilter.network/download/ipsum.lst)。[`community.lst`](https://community.antifilter.download/list/community.lst)，社区发现被封锁的地址。[cdn-ip-ranges](https://github.com/123jjck/cdn-ip-ranges)，CDN 和托管商的地址段：只用来说明节点所在的网段（「Hetzner 网段（DE）」），从不给出结论。不检查 IPv6 地址。
- **时间安排。** 面板每 6 小时用条件请求更新一次名单（未变化的名单只返回 304），并重新比对所有节点；新节点会立即比对。名单只保存在内存中。若一个名单都没能下载，15 分钟后再试。**测试**会立即执行，并显示名单日期、前缀和 CDN 地址段的数量、有多少节点在名录中，以及是否用了镜像。**断开连接**会关闭此来源，同时删除已下载的名单和所有已保存的结果。
- **`listed` 从不打开告警。** 地址在名单中、且没有任何实测来源检测过的节点显示为 `listed`（黄色）：在名录中，未经实测。名录只说明地址被登记，不说明其流量被丢弃；仅凭名单，拥挤网段里的每个节点都会触发告警。Globalping 的实测结论总是优先，此时名单只在其提示中补充细节。
- **关闭就是关闭。** 此来源关闭时，不会按计划或因**测试**下载任何内容，运行状况页面也不会显示它的任何结果。已保存的结果会被隐藏，7 天后删除。

## TSPU 探测

国家视角检测的第三个来源，也是唯一一个用你自己的机器从该国境内测试节点 TCP 端口的来源。你在该国境内的一个节点（**探测节点**）先在自己的链路上找到国家级 DPI 设备（TSPU）的位置，然后向其他节点发送限制 TTL 的 TCP SYN 包：如果数据包在这台设备处悄无声息地消失，且它后面的路由器没有任何应答，该端口即被封锁。方法来自 [tspu-check](https://github.com/porutchik/tspu-check) 和 [cheburcheck](https://github.com/LowderPlay/cheburcheck)；节点 Agent 重新实现了它，没有使用二者的代码。它是一项独立的集成，**默认关闭**，并且只适用于俄罗斯：选择其他国家时，卡片会说明这一点，也不会发送任何内容。

- **位置**：**可达性 → 来源**中的「TSPU 探测」卡片。它的结论计入该部分中节点的结论、「从俄罗斯访问」列和节点页面上的那一行；提示里会写出探测节点和设备所在的跳数（`dpi_hop`）。
- **设置**（仅所有者；修改需要重新确认）：开关、**探测节点**和间隔（默认 120 分钟，最少 30）。选择列表中，所选国家的节点排在前面。节点在线、且其 Agent 声明了 `country-probe/1`，才能做探测节点；较旧的 Agent 需要先更新。未选择探测节点时不会运行任何内容。
- **数据中心视角。** 探测节点位于数据中心，看到的是它自己上行链路的过滤，而不是家庭宽带或移动网络用户看到的情况。它的结论带有 `dc_only` 置信度，Globalping 的家庭和移动探测点（`eyeball`）优先于它。
- **如何并入结论。** 对每个节点，最新一次运行视为实测结论：所有被测端口都被封锁，或部分被封锁而没有开放端口，为 `tcp_blocked`；只要有一个端口开放即为 `ok`。它与其他来源一起遵循[下面的规则](#来源如何并入结论)；探测节点在其中是路径类来源。超过三个间隔的运行不再计入。封锁名单仍然只提供细节。
- **发送什么。** 通过 Agent 连接向探测节点下发命令。探测节点再向你其他在线节点的地址（其已启用协议配置的 TCP 端口，443 优先；绝不会测自己）和该国两个固定地址发送 SYN 包：一个永远不会被封的对照地址（Yandex），和一个 TSPU 一定会丢弃的参照地址，用来定位设备。参照地址内置在面板中；某一个无法定位设备时，面板会换下一个，必要时三个都试。节点地址不会发送给任何第三方。
- **无需额外权限。** 探测只是一次限制 TTL 的普通 TCP 连接尝试，因此节点 Agent 保持其加固的服务配置：没有原始套接字，也没有 `CAP_NET_RAW`。它依赖内核把路由器的应答交给正在连接的套接字。这只在一种内核（Linux 6.6）上测试过；在较旧内核的节点上首次运行时请留意，如果内核不配合，结果会是 `no_dpi_hop` 或 `failed`。
- **仅测 TCP。** 不测 UDP。Hysteria2 或 AWG 节点按其其他协议配置的 TCP 端口来判断（VLESS、Hysteria2 的 HTTPS 网站）；只有 UDP 协议配置且没有网站的节点，不会从该来源得到结论。
- **时间安排。** 每个间隔，面板向探测节点连续下发几条命令（每条 6 到 8 组主机与端口；被封锁的一组会单独再测一次，所以一条命令可能要两分钟），并在每个应答到达时立即保存。最新保存的记录比间隔更早时才到下一次运行，因此重启面板不会触发运行。探测节点忙时，面板 5 分钟后再问；探测节点离线或 Agent 没有 `country-probe/1` 时，该轮跳过。**测试**会立即运行（每分钟最多一次，可能需要几分钟），并显示状态和每个节点的结论。
- **上次运行的状态。** `ok`。`control_failed`：对照地址在探测节点所在网络的设备之后被封，该方法在那里不适用，不给出任何结论。`no_dpi_hop`：无法定位设备，原因见卡片上的说明（见下一条）。`busy`。`failed`：无应答、Agent 太旧或连接中断。
- **无法定位设备时。** 面板会依次尝试全部三个参照地址，每次运行中每个最多问一次，因此一次什么都没定位到的运行只花三条命令。随后卡片说明查到的情况：
  - *探测节点的路径上没有 TSPU*（`reason` 为 `refs_pass`）：被封锁的地址有应答，说明从该网络可以正常打开被封锁的地址，没有可检测的内容。俄罗斯不少数据中心的路径上没有 TSPU。请换一个服务商不同的探测节点，或关闭探测。
  - *路径上的路由器没有应答*（`no_hops`）：探测节点出发的路由被隐藏，无法定位设备，该方法在这个网络中不适用。请换一个探测节点。
  - *未能在路径上找到 TSPU*：Agent 没有说明原因，例如早于此字段的 Agent。请更新 Agent 后再次运行**测试**。
- **关闭就是关闭。** 此来源关闭时，不会按计划或因**测试**发送任何命令，运行状况页面也不会显示它的任何结果。已保存的记录隐藏 7 天。**断开连接**会关闭此来源，并删除已保存的记录和设置（探测节点、间隔、上次运行）。
- **Cloudflare 版暂不支持。** 一次运行需要几分钟，而该版本的定时任务只有几秒，所以卡片会说明该来源在那里不可用，也不会运行任何内容（见[此版本暂不支持的功能](../getting-started/install-edge.md)）。

## cheburcheck

第四个来源请俄罗斯各地志愿者的探测点检查：到节点地址的连接能否通过国家级 DPI 设备（TSPU）。它使用免费网站 [cheburcheck](https://cheburcheck.ru)；方法与 [TSPU 探测](#tspu-探测)相同，只是从别人的网络出发。它是一项独立的集成，**默认关闭**，并且只适用于俄罗斯：选择其他国家时，卡片会说明这一点，也不会发送任何内容。

- **位置**：**可达性 → 来源**中的「cheburcheck」卡片。它的结论计入该部分中节点的结论、「从俄罗斯访问」列和节点行（「cheburcheck」和「自有探测点」两行）。
- **检测内容。** 每个探测点只检测一件事：发往节点 IPv4 地址 443 端口的 TCP SYN，能否越过该探测点链路上的 TSPU 设备。探测点的回答是 `ok`（越过了）、`tspu_block`（死在设备处）或 `uncertain`（未能定位设备：无结论）。端口始终是 443，与你的协议配置用什么端口无关。TSPU 对地址的封锁会丢弃所有端口，所以对任何节点，这都是「地址是否被封」的可靠检验。单个端口被封、VLESS 指纹被封或已建立连接被冻结，它都看不到；UDP（Hysteria2、AWG）上除地址之外的情况同样看不到。
- **不是端到端。** `ok` 表示 SYN 越过了设备，而不是节点作出了应答：设备后面紧挨着的一台路由器就够了，Agent 已停止的节点照样显示 `ok`。因此在结论中 cheburcheck 是*路径类来源*（[见下](#来源如何并入结论)）：它能显示封锁，但不能推翻其他来源端到端看到的完全封锁。
- **节点结论。** 依据回答 `ok` 或 `tspu_block` 的探测点：没有无应答的为 `ok`；一部分无应答、另一部分通过为 `partial`；全部无应答为 `tcp_blocked`（该来源只测 TCP，所以从不给出 `blocked`）。回答的探测点少于两个（自有探测点为少于一个）、该网站没有在线的探测点（`no_probe`），或网站未能及时完成（`timeout`）时为 `unknown`。
- **公共探测点与自有探测点。** *公共探测点*（默认开启）是该网站当前在线的全部志愿者探测点：家庭和移动网络、路由器以及少量托管服务，没有标注。网站无法筛选它们，所以面板自行按探测点对结果分组。*自有探测点*是可选的：你自己运行一个 cheburprobe，例如装在克里米亚朋友家的路由器上，并粘贴它的令牌；面板随后只问这一个探测点，网站也不会缓存它的结果。
- **设置**（仅所有者；任何更改都需要重新确认）：开关、公共探测点开关、公共探测点的间隔（默认 180 分钟，且不能更短：网站会重放它保存了 3 小时的结果，重放会被算作第二次测量）、自有探测点的令牌（只写，密封在面板的保险库中，之后不再显示）及其间隔（默认 60 分钟，30 分钟到 7 天）。**测试**读取网站的状态页，不发送任何地址。**断开**会关闭此来源，并删除令牌和所有已保存的结果。
- **发送什么、发给谁。** 发给 cheburcheck.ru 的只有每个在线节点的 IPv4 地址（作为检测目标），没有别的：没有端口、协议、节点名称，也没有用户。网站会保存**每次查询以及请求方的 IP 地址和 User-Agent**，而 User-Agent 中含有 Mistgate（`mistgate-panel`），所以网站能看出这些地址是同一个面板在检测的 Mistgate 节点。在 VPS 上请求方是面板自身的地址；在 Cloudflare 版上是与其他人共用的 Cloudflare 地址。自有探测点的令牌随探测请求发给 cheburcheck.ru，作为该探测点的凭据。开启时会先显示这些内容并请你同意。
- **时间安排与礼貌。** 每次调度只访问网站一次：面板选取最新记录超期最久的节点和类型（公共或自有），请求一次检测，并读取探测结果流最多 45 秒（Cloudflare 版为 35 秒）。两次访问之间至少相隔 30 秒（网站允许同一地址每分钟 5 次探测，面板最多用 2 次），所以六个节点、两种类型的一轮在 VPS 上约需 6 分钟。VPS 面板每 30 秒查看是否到期；Cloudflare 版从每分钟一次的 cron 运行，每分钟一次访问。
- **退避。** 遇到 `429`，面板等待 2 分钟，之后翻倍，最多 30 分钟，且不保存记录。网站关闭地址检测（`400`）时，卡片显示「网站暂停了地址检测」，面板 6 小时后再试。网站不认识自有探测点的令牌（`404`）时，自有探测点的运行会停止，直到你保存新令牌。已过期的检测会重新请求一次。超时之前收到的结果会保留。
- **来自网站的文本。** 探测点的地区、服务商和 AS 号来自网站；它们会被截断、去掉控制字符，并作为数据显示。
- **局限。** 它看到的是地址和过滤设备，视角是运行探测点的人所在的网络。志愿者探测点没有标注，个别还会误判设备，所以单个无应答的探测点说明不了多少：[告警](#告警)要求同一个探测点两次无应答，同时它能连到你的其他节点。
- **关闭就是关闭。** 来源关闭时不会发出任何检测。已保存的记录会被隐藏，7 天后删除。

## bsbord

第五个来源是付费的。[bsbord](https://bsbord.com) 在俄罗斯移动运营商的网络里（含克里米亚）放有 SIM 卡探测点，称为*单元*；面板请它们 ping 每个节点，并连接其一个 TCP 端口。它是唯一能看到克里米亚和运营商白名单之下的移动网络的来源。它是一项独立的集成，**默认关闭**，并且只适用于俄罗斯：选择其他国家时，卡片会说明这一点，也不会发送任何内容。

- **位置**：**可达性 → 来源**中的「bsbord」卡片；它在节点行中的那一行叫「bsbord」。
- **检测内容。** 对每个有 IPv4 地址和 TCP 端口的在线节点，你选的每个单元 ping 该地址并连接一个端口：优先是节点的 TLS 端点（VLESS 的 REALITY 端口或 Hysteria2 的 HTTPS 网站），没有则 443，再没有则其最小的 TCP 端口。校验 TLS 的单元要求该端口以 TLS 应答。没有 IPv4 地址或没有 TCP 端口的节点会被跳过，其来源行会写明原因（`no_ipv4`、`no_tcp_port`）。
- **单元。** 一个单元是某个地区的一家运营商，带或不带运营商白名单；它的键形如 `mts|krym|off`。你在卡片上按地区，从当前能检测的单元的实时列表中挑选；有两个预设可用，*全选克里米亚*（默认选择）和*每家运营商一个*。所选的键按原样保存，因此价格与你看到的一致。bsbord 不再列出的单元会作为已跳过返回，不会被重试。
- **节点结论。** 单元在 ICMP 或 TCP 通过时给出*可达*，在单元运行了而两者都失败时给出*无应答*。校验 TLS 证书的单元无法通过任何 REALITY 端口，因此它的 TCP 失败说明不了什么：只有当节点回应其他单元的 ping 却不回应它时，才算*无应答*，否则为*无明确结果*。白名单之下什么也没收到的单元是*白名单*，不算无应答：白名单对所有节点一视同仁地切断一切境外地址，所以它们单独列出；而确实连上了节点的，算作可达。没有运行、无法解析地址或报告出错的单元给出*无明确结果*。没有被计入的无应答单元时，该行为 `ok`；一部分无应答、另一部分可达为 `partial`；全部无应答为 `blocked`（bsbord 没有 `tcp_blocked`：ICMP 和 TCP 都失败了）；没有任何单元被计入为 `unknown`。ICMP 通过而 TCP 失败仍算*可达*，因为校验 TLS 证书的单元可能因此无法通过 REALITY 端口；TCP 和 TLS 的结果会保留并显示。
- **设置**（仅所有者；任何更改都需要重新确认）：开关、密钥（在你的 bsbord 账户中生成的 `bsk_live_` 密钥；只写，密封在保险库中，之后不再显示）、单元、间隔（默认 24 小时，1 到 24 小时）和每月上限。保存密钥和至少一个单元之前不会运行任何内容。**测试**读取你的账户和单元列表（套餐、余额、有多少单元可检测），不发送任何地址。**断开**会关闭此来源，取消进行中的一轮，并删除密钥和单元；本月的花费仍会计入，已保存的记录隐藏，7 天后删除。
- **发送什么、发给谁。** 发给 bsbord 的是每个在线节点的 IPv4 地址和一个 TCP 端口；它的 SIM 探测点会连接它们。密钥就是你的 bsbord 账户：持有密钥的人可以花掉你在那里的余额。开启时会先显示这些内容，然后显示一轮的价格和按该间隔计算的大约一个月的价格。查询价格是免费的，但节点地址此时已会发出，而在你看到价格之前，不会开始任何付费检测。
- **时间安排。** 每个间隔一轮，开启后一分钟内进行第一轮。同一时间只有一个付费请求，相隔至少一秒：一个请求最多放 10 个节点，节点更多就有更多请求，每次调度一个。每个付费请求之前，面板会为这个请求本身查询免费的价格（预览）。
- **费用。** bsbord 以点数计费，1 点数相当于 1 戈比（10,000 点数等于 100 ₽）；卡片以卢布显示。bsbord 不公布价格，每个请求由预览定价。2026 年 10 月，四个克里米亚单元检测一个节点为 80 点数，三个节点为 160：每多一个节点，每个单元约多 10 点数。六个节点、四个单元，每天一次，约为每天 280 点数、每月约 8,400（约 85 ₽）。价格由 bsbord 决定，可能变化。
- **每月上限**（默认 100 ₽，按 UTC 的日历月）用来止住花费：本月已花费加上下一个请求的价格会超过它时，请求不会发出，卡片显示「已达到每月上限」，直到下个月 1 日。提高上限，或在卡片上保存任何其他设置，下一轮就会重试（先免费查询价格）；如果上限仍然不够，会再次停止。卡片会显示已花费、为进行中的一轮预留的金额和剩余金额，并在每月估算高于上限时发出提醒。请求在收到结果时按其价格计入，再减去 bsbord 因通道中断退还的部分；进行中的请求预留其预览价格；丢失或被取消的请求，其价格仍计入。
- **重启安全。** 请求连同新的 Idempotency-Key 在发送之前先保存。超时（bsbord 可能需要几分钟；面板在 100 秒后断开连接，Cloudflare 版为 40 秒）、重启或面板更新之后，面板用同一个密钥重发同一个请求，bsbord 就按第一次的运行作答，只收一次费。23 小时没有结果的请求会被放弃（「一轮付费检测没有收到结果」），其价格仍计入。
- **卡片上的状态。** 「一轮检测进行中」；「已达到每月上限」；「bsbord 余额不足」（6 小时后重试，或在卡片上保存后立即重试）；「你的 bsbord 套餐不支持此功能」（更换套餐后在卡片上保存一次）；「bsbord 拒绝了此密钥」（保存新密钥）；「一轮付费检测没有收到结果」；「bsbord 要求降低频率」（面板按要求等待）；「bsbord 没有响应」（稍后重试）；「所选单元都无法检测」（其白名单模式已变化：请选择其他单元）；「没有可检测的节点」；「未选择任何单元」；「bsbord 拒绝了这一轮检测」；「这一轮检测已取消」（检测进行中设置发生了变化）。
- **局限。** 单元是你所选地区里的 SIM 卡：bsbord 看到的只是这些运营商在这些地方的情况，别无其他。因此它是局部来源：它的记录计入结论并触发部分告警，但它自己永远不会打开完整告警（[告警](#告警)）。它只测 ICMP 和 TCP，不测 UDP，也不测端口上的协议。单元会离线；列表和价格由 bsbord 决定。
- **两种版本。** VPS 面板每 30 秒查看一轮是否到期；Cloudflare 版从每分钟一次的 cron 运行，每次调度一个请求。

## kl!ck 报告

VPN 应用 [kl!ck](https://github.com/vbu00/klick)（Windows、macOS）带有一项服务器检查，由用户在其窗口中启动：它从用户自己的家庭或移动网络出发，针对订阅中的每台服务器区分 TSPU **冻结**（服务器有响应、延迟检测通过，但下载在 1–64 KB 后卡住）、TCP 被封、握手失败或无响应，并判断该网络的 DNS 是否说谎。如果用户在应用中开启了**发送到面板**，结果会发送到签发该订阅的面板。这是一个独立的来源，**默认关闭**，它从用户所在的地方观察，与页面上选择的国家无关。

- **位置**：**可达性 → 来源**中的「kl!ck 用户」卡片：开关、7 天内收到多少份报告以及最近一份的时间；每个节点有多少份报告检查过它、其中多少份出现冻结、TCP 被封或无法连接，并按运营商和地区分别统计。一份报告对一个节点只计一次，计入该节点任一服务器得到的每种结论。更改开关需要重新确认；**断开**会关闭该来源并删除所有已保存的报告。
- **应用如何得知。** 该来源开启时，每个发给应用的订阅响应都带有 `Probe-Report: 1`。没有它，kl!ck 不发送任何内容，也不显示开关。开关的变化会在一分钟内反映到订阅响应中。
- **收到什么。** `POST <订阅链接>/probe`，JSON。应用每 10 分钟最多发送一次；面板对每个订阅先接收两次，之后每 10 分钟一次（更早会得到带 `Retry-After` 的 `429`）。链接中的令牌是唯一的身份验证：未知链接得到伪装页面，与未知订阅链接相同。面板检查每个字段（版本、范围、已知取值），其他一律以 `400` 拒绝。它按主机和端口将每台服务器与该用户自己的订阅匹配；不在订阅中的服务器会被丢弃。响应为 `200 {"accepted":N}`，来源关闭时为 `403 probe_off`。
- **保存什么。** 保存 7 天：节点、协议类型和端口、结论和测量值，以及应用看到的网络（运营商、AS 号、国家、地区、网络类型；运营商和地区仅以纯文本保存：字母、数字和简单标点，因此不会保留任何链接、地址或标记）。不保存报告的来源地址（既不存储也不记入日志），也不保存用户或设备。
- **暂不计入结论。** 报告只显示在自己的卡片上，以及通过 MCP 工具 [`klick_reports`](../reference/mcp.md)（任何令牌配置文件均可）读取：不会改变节点的结论、时间轴或告警。

## 来源如何并入结论

每个节点的结论取自所有已开启来源各自最新的有效记录：`ok`、`partial`（部分网络无法连接它）、`tcp_blocked`（TCP 被切断而 ICMP 通过）、`blocked`、`listed` 或 `unknown`。

- **有效期。** 记录在比其来源实际间隔的三倍更新时才计入：Globalping 默认 45 分钟（其各轮的实际间隔，预算可能将其拉长），TSPU 探测 6 小时，公共 cheburcheck 9 小时，自有探测点 3 小时，bsbord 72 小时，均按你的设置。更早的记录被忽略。更新的 `unknown` 记录会让其来源退出结论：不会退回到该来源更早的结果，提示中会连同原因一起显示。
- **只要有可达的又有无应答的，就是 `partial`。** 来源给出 `ok` 或 `partial` 即为可达，给出 `partial`、`tcp_blocked` 或 `blocked` 即为无应答。没有无应答的来源时结论为 `ok`。没有可达的来源时，若有端到端检测的来源（Globalping、bsbord）给出 `blocked` 则为 `blocked`，否则为 `tcp_blocked`。
- **路径类来源。** TSPU 探测和 cheburcheck 只能说明 TSPU 放行了 SYN；设备后面的路由器可能替一个已经死掉的节点应答。因此，当端到端检测的来源看到完全封锁（`tcp_blocked` 或 `blocked`），而所有连上节点的来源都是路径类来源时，封锁仍是结论，置信度为 `conflict`，提示会写出各来源看到的结果。只要 Globalping 或 bsbord 连上了，同样的情形就变成 `partial`。
- **Globalping 与 TSPU 的三种情形改变了。** 以前二者只要不一致，就显示较差的结论并标为 `conflict`（「宁可误报也不漏报」）。这条规则早于 `partial`，而部分告警不算漏报。

  | Globalping | TSPU 探测 | 以前 | 现在 |
  |---|---|---|---|
  | `ok` | `tcp_blocked` | `tcp_blocked`、`conflict` | `partial`、`dc_only` |
  | `partial` | `tcp_blocked` | `tcp_blocked`、`conflict` | `partial`、`eyeball` |
  | `blocked` | `tcp_blocked` | `blocked`、`conflict` | `blocked`、`eyeball` |

  Globalping 那一轮有家庭或移动探测点时置信度为 `eyeball`，否则为 `dc_only`。不变的情形：Globalping 为 `tcp_blocked` 或 `blocked` 而 TSPU 探测为 `ok` 时，仍是该结论并标为 `conflict`；Globalping 为 `partial` 而 TSPU 探测为 `ok` 时，仍是 `partial`。
- **置信度。** `eyeball`：有从家庭或移动网络出发的来源参与（带这类探测点的 Globalping、cheburcheck、bsbord）；对 `partial`，无应答的记录中有这样的来源。`dc_only`：只有数据中心视角（TSPU 探测、来自数据中心的 Globalping）。`listed`：只有封锁名单。`conflict`：见路径类来源。
- **封锁名单**从不产生实测结论。只有在没有任何实测来源的有效记录时才会出现 `listed`，实测结论总是优先。
- **明细。** 凡是有网络无法连接节点的结论，其下方会列出**所有**参与来源的网络、单元和探测点，每项标明来源和结果的时间，分为「无法连接节点」「可以访问」「白名单模式（所有境外地址均被切断）」和「无明确结果」几组，组内再按地区和网络排列。地区名称是各来源自己的，不会合并。过长的列表会折叠（「还有 27 个」）。提示会写出每个来源的结果及原因。MCP 以 `vantages` 和 `source_verdicts` 给出同样的内容（[`checks_results`](../reference/mcp.md)）。

## 告警

告警 `country_blocked` 有两种，完整的和部分的，各自独立。

**完整：节点从该国无法访问。**

- **事件。** 每个已开启来源的每条记录（`unknown` 除外）算一个事件，从新到旧：Globalping 的一轮、TSPU 探测的一次运行、cheburcheck 或 bsbord 的一条记录。面板把每个事件与其他每个来源在当时最新的记录[合并](#来源如何并入结论)。两条记录只有在都有效时才配对：它们的时间间隔不能超过两个来源有效期中较短的那个。封锁名单从不计入。
- **自身结论过滤。** 事件只有在它自己的记录与方向一致时才计入。*坏*事件：它自己的记录为 `tcp_blocked` 或 `blocked`，合并后的结论也为 `tcp_blocked` 或 `blocked`。*正常*事件：它自己的记录为 `ok` 或 `partial`，合并后的结论也为 `ok` 或 `partial`。其他事件都会被跳过，就像 `unknown` 的轮次。只有 Globalping 时，这就是原来的两轮规则；它还避免了 TSPU 的 `ok` 运行让 Globalping 的 `tcp_blocked` 被重复计入第二次。
- **打开**：连续两个被计入的坏事件；**关闭**：连续两个正常事件。
- **全国性来源。** 对告警而言，完整结论会降为 `partial`，除非有全国性来源自己给出它：Globalping、公共 cheburcheck 或 TSPU 探测。局部来源只看到几个网络或地区，即你自己的 cheburcheck 探测点和 bsbord（比如只选克里米亚）。它们单独或一起，都只会触发部分告警。页面上，仅 bsbord 选克里米亚时仍可能显示 `blocked`；被压住的只有告警。
- **文本。** 告警及其 Telegram 消息会写明发现封锁的来源（`globalping`、`tspu`、`cheburcheck`、`cheburcheck_own`、`bsbord`）、置信度、无应答的网络（外部来源按网络命名，如 `MTS (Crimea, bsbord)`）以及 TSPU 探测看到被封锁的端口。标题为「节点从俄罗斯无法连接」。正文说明什么被切断（「TCP 被阻断」，Globalping 看到时还有「ICMP 仍可通过」；或「ICMP 和 TCP 都无法通过」），然后是「发现方：…」，`conflict` 时还有「各来源的结果不一致，此处显示较差的一项。」打开时一条消息，关闭时一条消息。

**部分：一个网络连不上节点而其他网络可以。** 同一类告警，主题为 `partial`，级别为警告。

- **观察。** 每条记录给它的每个网络、单元或探测点一次观察，记在键 `来源|网络` 之下：`globalping|AS8359`、`cheburcheck|probe:17`、`bsbord|mts|krym|off`、`tspu|<探测节点>`。键不跨来源：cheburcheck 的可达不会清除 bsbord 的无应答，反之亦然，因为越过设备的 SYN 说明不了 SIM 卡收到了什么。
  - *R*：它用自己来源的方式连上了节点（Globalping：连到节点端口的 TCP，没有端口则为 ICMP；TSPU 探测和 cheburcheck：SYN；bsbord：ICMP 或 TCP）。
  - *D*：它无应答，该条记录当时合并后的结论为 `partial`（完全封锁不能证明单个网络无应答），并且**它同时连上了你集群中的另一个节点**（跨节点规则）。「同时」的含义：Globalping 为同一轮；TSPU 探测和 bsbord 为同一次运行或同一个请求；cheburcheck 为一个间隔之内取得的另一个节点的记录。因此，一个连你的任何节点都连不上的网络不会触发告警，页面会点出它。只有一个节点的集群永远不会有部分告警。
  - 白名单之下的单元、没有明确结果的网络和 Globalping 的数据中心探测点不产生观察。
- **打开**：同一个键在最近两次观察中都是 D。没有询问该网络的轮次和每条 `unknown` 记录都不是观察，所以 Globalping 运营商的轮换或故障不会抹掉证据。**关闭**：没有任何键处于该状态时，通常是第一次出现 R 时。
- **多个来源。** 每个触发的键的网络都会列出，如 `MTS (AS8359, Novosibirsk)`、`MTS (Crimea, bsbord)` 或 `Rostelecom (AS12389, Moscow, cheburcheck)`；TSPU 探测按其节点命名，如 `de1 (tspu)`。这些键的来源也会写明。
- **保持不变**：告警中点名的某个来源的最新记录为 `unknown` 期间（达到上限、`429` 后的等待、网站无响应、Globalping 额度），因为故障不说明封锁已解除；以及节点未连接期间。若无应答的网络离开了某个来源，其记录移出该来源最近十条后，告警会自行结束。
- **完全封锁取代它。** 完整告警打开或保持打开时，部分告警以 `superseded` 结束，不发 Telegram 消息。完整告警关闭后，若上述规则成立，部分告警会再次打开。
- **Telegram。** 标题为「节点在俄罗斯的部分网络中无法连接」，正文为「位于MTS (AS8359, Novosibirsk)的探测点收不到它的响应，但能到达您的其他节点。」，随后是「发现方：…」。打开时一条消息，关闭时一条消息。网络列表变化只会更新已打开的告警，不发新消息；可像其他告警一样静音。

## IPv6

只有 Globalping 检测 IPv6。封锁名单、TSPU 探测、cheburcheck 和 bsbord 只看 IPv4 地址，kl!ck 报告不区分两者。

- **检测什么。** [Globalping 卡片](#globalping)上的 IPv6 开关开启时（默认开启），IPv6 可用的节点还会按其 IPv6 地址单独测一轮。这一轮的对照站点要通过 IPv6 访问（`RU` 为 `ya.ru`，其他国家为 `www.cloudflare.com`），因此只有支持 IPv6 的探测点参与，没有 IPv6 的探测点不会拖累节点的结果。IPv6 结论的判定方式与 IPv4 相同，只依据 IPv6 轮次，绝不改变 IPv4 的结论、时间条或告警。
- **用哪个地址。** 节点地址本身是 IPv6 地址时用它，否则用节点代理上报的默认 IPv6 路由的源地址。只有代理报告出站 IPv6 正常时才会检测：主机商不路由的地址会被误判为封锁。
- **管理后台中。** 结论标签标注 *IPv4*，后面跟着一个 *IPv6* 标签，颜色、图标和提示都相同。Globalping 那一行下面紧跟一条 *IPv6* 时间条，同样覆盖 7 天。IPv4 汇总下方有一行，统计 IPv4 受阻（部分网络、TCP 或全部）但 IPv6 仍可访问的节点数。开关关闭时，页面与以前一样。
- **没有 IPv6 结论。** 这样的节点在 IPv6 时间条的位置显示一行灰色说明，给出原因：
  - `no_ipv6`：「服务器没有 IPv6」（没有全局 IPv6 地址）。
  - `ipv6_broken`：「服务器有 IPv6 地址，但主机商那边的 IPv6 不通」。出站 IPv6 不通，因此不检测该节点。
  - `agent_old`：「节点代理版本过旧，无法上报 IPv6，请更新」。
  - `not_checked`：代理尚未上报，或尚未进行过 IPv6 轮次。
  - `no_probes`：Globalping 目前在该国没有支持 IPv6 的探测点。因其他原因（`rate_limited`、`source_error`、`timeout`、`too_few_probes`）失败的轮次也以同样方式显示。
- **额度。** 对同样的节点，IPv6 轮次的消耗与 IPv4 轮次相同：（1 次对照 + 每个被检测节点 1 次 + 其 TCP 端口数）× 探测点数。六个节点、每个两个 TCP 端口，IPv4 每个探测点需要 19 次测试；其中两个节点有 IPv6，再加 7 次。两种轮次轮流进行，共用同一份[额度](#globalping)，所以没有令牌时轮次会稍稀一些。关闭 IPv6 即可让 IPv4 轮次保持原样。
- **告警。** IPv4 的 `country_blocked` 告警带有参数 `ipv6`：`open`、`partial`、`blocked` 或 `unknown`，即最新一轮 IPv6 检测对该节点的结论。为 `open` 时，告警会加上「通过 IPv6，从那里可以访问该节点。」（Telegram 中为「通过 IPv6 可以访问。」）；参数变化不会发送新消息。针对 IPv6 本身的告警（主题 `ipv6` 和 `ipv6/partial`，参数 `family=6`，管理后台中带 *IPv6* 标签）只为 [IPv6 入口](../guide/nodes.md#ipv6-入口)已开启的节点发出：其上的用户依赖它。它们的打开和关闭方式与 IPv4 告警相同，需连续两轮。对其他任何节点，IPv6 只显示在本页和 `ipv6` 参数中。对带入口的节点，当 IPv6 检测轮次能访问到它时，其 IPv4 告警的 `ipv6` 参数为 `entry`，Telegram 消息会加上「有 IPv6 的用户通过 IPv6 入口连接。」；否则由 IPv6 告警来说明 IPv6 的情况，参数为空。
- **有入口时的地址。** 节点的 IPv6 入口开启期间，IPv6 检测轮次会测量入口的地址，即用户连接的那个，先于节点自己的地址和上行地址。只有当节点的 Agent 报告出站 IPv6 可用时，才会测量该节点。
- **IPv4 被封而 IPv6 通。** 节点的 IPv4 在该国家被封锁、而 IPv6 能通，这正是 [IPv6 入口](../guide/nodes.md#ipv6-入口)的适用情形：目前它需通过 MCP 开启，开启之前先做入口自己的检测（从外部，由另一个节点发起）。不会自动开启任何东西。

如果只有部分网络失去某个节点，可以经由这些网络能够访问的另一个节点，用[中转](../guide/relays.md)把该节点的服务器带给他们。中转的检测以及对话框里的提示会用到本页的结论和 TSPU 探测。
