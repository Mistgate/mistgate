[可达性](reachability.md)里的公共检测通过别人的探测点查看你的节点。**自有探测点**是一个小脚本，由你（或朋友）在国境内的路由器或服务器上运行：它从那个网络检查你的节点，也就是真实家庭或移动连接所看到的情况。它的结果与其他来源一起合成每个节点的结论。一个探测点只是一个很窄的观察点，所以它单独只能触发*部分*封锁的告警，作为提示。

它**默认关闭**，Cloudflare 版没有它。它属于所有者：列表、安装命令和所有更改都只有所有者可用，创建、吊销、切换和断开都需要重新验证。API 令牌和 MCP 无法访问它。

## 在管理后台

**可达性 → 来源 → 自有探测点**。开关打开这个来源；列表里每个探测点显示它的状态：

- **等待安装**：命令已生成但还没执行（24 小时内有效，之后需要重新生成）。
- **工作中**：它在最近一小时内联系过面板。这一行显示最近联系的时间、它的运营商和你填写的城市，以及 24 小时内的检测次数。
- **失联**：超过一小时没有联系（路由器关机、U 盘被拔出、没有网络）。
- **网络已变化**：探测点现在从另一家运营商的网络联系面板，不是安装时的那家。在你点**确认网络**之前它保持暂停：搬到你不知道的地方的探测点，不是你选的那个探测点。
- **已过时**：面板的脚本比探测点运行的更新。点**更新命令**。
- **路径上没有过滤**：探测点的参照地址（被过滤器封锁的地址）能打开。这样的网络（例如国外的路由器）看不到封锁，所以它能连上的节点说明不了什么，它的「可达」只算不确定。对于国境外的探测点这是正确的状态，而且在第一个结果出现之前就能看到。
- 一行里也可能提示**无法试探参照地址**（探测点自己没有网络，或其配置里设置了 `ref=off`）：这时它的结果说明不了什么。

**立即检测**请探测点在下次联系时进行一轮，大约 15 分钟内。**吊销**不可撤销；底部的**断开**会关闭这个来源并保留探测点（再次打开时它们会恢复）。

## 需要什么

**Keenetic** 路由器需要：

1. 在路由器网页界面里安装 KeeneticOS 组件**开放软件包支持 (OPKG)** 和 **Ext 文件系统**。
2. **Entware**：装在 ext4 格式的 U 盘上（1 GB 就够），或装在带 NAND 的型号的内置存储里，KeeneticOS 3.7 或更新。路由器的架构无关紧要，探测点是 shell 脚本。
3. **SSH 登录 Entware**（端口 `222`，不是路由器自己的 SSH）。请先修改 Entware 中 `root` 账户的默认密码。

**服务器**需要使用 systemd 的 Linux，以及 `curl`、`sha256sum` 和 `sudo`。

面板需要它的公网 HTTPS 地址（**设置**）：命令由它生成，没有它面板不会给出命令。

## 安装

1. **添加探测点**：名称（你在列表里认出它的方式）、城市（由你填写：面板不保存设备的地址）和它所在的位置：*家庭*、*移动网络*或*数据中心*。
2. 窗口只显示**一条命令**，只显示一次。它 24 小时内有效，之后无法再次显示；如果没来得及复制，请重新生成（等待中的探测点会被吊销，再生成一个新的）。**Keenetic (Entware)** 与 **服务器（VPS）** 是两条不同的命令，可以切换。
3. 在设备上打开 SSH，粘贴命令并回车。窗口会等待**已连接**。

命令从你的面板下载脚本，把它的 **sha256** 与面板算出的值核对，通过后才带着一次性令牌运行。在 Keenetic 上它会先安装 `curl`、`ca-bundle` 和 `coreutils-sha256sum`；在服务器上脚本放进一个私有临时文件，通过 `sudo` 运行（以 root 运行时去掉 `sudo`）。重复运行是安全的：已注册的探测点只会被刷新。

脚本用令牌注册（令牌在请求体里发送，不会出现在命令行里），把自己的密钥放在其他用户无法读取的文件里，然后启动。在 Keenetic 上它成为 `/opt/etc/init.d/S99mistgate-probe`，随 Entware 一起启动；在服务器上是 systemd 服务 `mistgate-probe`。

## 检查

- 在设备上：`/opt/etc/init.d/S99mistgate-probe status`（Keenetic）或 `systemctl status mistgate-probe`（服务器）。
- 在面板里：探测点*工作中*，运营商正确；点**立即检测**，大约 15 分钟后结果会出现在可达性的节点行里。

路由器重启后，Entware 和 OPKG 仍在，探测点会自己启动。重启后 `/tmp` 是空的，这是正常的。拔掉 U 盘，探测点就沉默（面板显示*失联*）；插回去它就恢复。

## 更新

出现**已过时**时，点**更新命令**。命令由面板生成：与安装命令相同的下载和 sha256 核对，然后执行 `upgrade`，不含令牌。选择 **Keenetic** 或**服务器**，在设备上运行。密钥和设置保持不变，探测点会重启。

## 删除

在设备上：`sh /opt/sbin/mistgate-probe uninstall`（Keenetic）或 `sh /usr/local/sbin/mistgate-probe uninstall`（服务器）。它会删除程序、服务、配置和状态。

面板里的**吊销**不需要设备：探测点的两个凭据立即失效，它的结果从节点行中消失，仍在运行的探测点只会收到伪装页面并随后沉默。删除之前，或够不到设备时，请先吊销。

## 探测点在路由器上做什么、不做什么

**会做：**

- 向面板询问要检查什么，通常每 12 到 18 分钟一次。它只按面板设定的间隔测量（30 到 240 分钟，默认 60），且最多每 30 分钟一次。
- 每一轮最多检查你节点的 32 个地址，每次两个连接，每分钟最多 20 个连接，每天 600 个，每天最多 64 个不同地址。一个连接是一次 TLS 握手，或一个不超过 64 KiB 的页面。报告里只有时间和代码（「重置」「超时」），没有地址。
- 两次询问之间休眠，中间没有任何唤醒。它以两个 shell 进程（看守和工作进程）运行，优先级最低，有 `nobody` 用户时以它运行，可用内存少于 16 MB 时跳过这一轮。
- 只写内存（`/tmp/mistgate-probe`）。配置在 `/opt/etc/mistgate-probe/conf`（其他用户不可读），安装后不再被改写。不会写 U 盘，也不会往 U 盘上写日志；syslog 里只有不含密钥的简短行。

**不会做：**

- 不打开任何端口：没有任何监听套接字。
- 不改路由器的设置：防火墙、路由、DNS、Wi-Fi、计划任务、密码。它自己不安装软件包（运行那一行安装命令时才会安装）。
- 不执行面板发来的任何东西：回复按文本读取，每一行都按严格的模式检查，有一行不对就丢弃整条回复。没有 `eval`，不加载文件，不自我更新（更新是你运行的那条命令）。
- 只访问你的面板和这一轮的地址；不跟随重定向，也不使用环境里的代理。

**数字**。它们是在 x86 上用 busybox `ash` 在实验室里测的；真实路由器会不同（很多是 32 位且更小，但只有在真机上才知道：对看守和工作进程执行 `grep -E 'VmRSS|Pss' /proc/<pid>/status`）。目标是脚本设计时的指标。

| | 目标 | 实验室测得 |
|---|---|---|
| 脚本大小 | 不超过 32 KiB | 31.8 KiB |
| 空闲内存 | 不超过 2 MB | 2.3 MB（PSS） |
| 一轮峰值内存 | 不超过 12 MB | 10.8 MB（PSS） |
| 处理器 | 很小一部分 | 每天约 3 秒（0.003 %），空闲时为零 |
| 流量 | 每月约 150 MB | 每月约 180 MB（两个会读取页面的目标） |
| 内存之外的写入 | 无 | 无 |
| 监听端口 | 无 | 无 |

## 网络服务商能看到什么

给同意放置探测点的人，用大白话说：

- 大约每 15 分钟，设备向你的面板域名发一次普通的 HTTPS 请求（看起来像任何网站）；大约每小时，它向你服务器的地址和一个早已被封锁的地址打开短连接：一次握手和不超过 64 KB 的页面。
- 家里其他人的流量不经过探测点，探测点也不读取。它不碰 DNS。
- 在网络服务商看来，这像是有人在用 VPN。如果它哪天对 VPN 用户采取行动，这条连接也可能被算进去。
- 一条命令就能删除它。请先问这个人，不要装在经不起任何关注的人那里。

## 面板保存什么

探测点的名称和城市（你填的）、运营商和 ASN（由请求的地址得出，随后丢弃该地址）、脚本版本和联系时间。绝不保存设备的地址；令牌和密钥只保存哈希。
