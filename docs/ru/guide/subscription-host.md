Публичный адрес нужен панели для двух вещей: люди забирают с него подписки, а каждый агент подключается к нему для связи. У панели дома, за NAT роутера или CGNAT провайдера, такого адреса нет. Эту задачу решает **хост подписок**: одна из ваших нод держит адрес подписки на поддомене, например `sub.example.com`, и передаёт запросы панели.

Соединение открывает сама панель: она подключается к порту 443 хоста и держит один зашифрованный туннель, поэтому до домашней сети ничего снаружи доходить не должно. TLS поддомена заканчивается в панели: сертификат и его ключ хранятся у неё. Нода только пересылает зашифрованные байты и не хранит ни подписок, ни токенов, ни ключей. Админка через хост никогда не ходит: она остаётся на собственном адресе панели или на локальном адресе. Устройство описано в `design/adr/0018-panel-behind-nat.md`.

Только VPS-версия. У Cloudflare-версии публичный адрес уже есть, и этой карточки в ней нет.

## Что нужно

- **Порт 443 хоста принадлежит собственному сайту ноды.** Подходит один из вариантов:
  - профиль Hysteria2, у которого сайт на TCP 443;
  - профиль VLESS REALITY, целью которого служит сама нода (собственный сайт ноды, с PROXY protocol);
  - свободный порт 443: тогда агент поднимает на нём свой сайт.

  Профиль REALITY с чужим сайтом в роли цели отклоняется с текстом *REALITY-профиль на ней уже отдаёт порт 443 другому сайту*.
- **Все агенты умеют работать через связь.** На всех нодах должен стоять агент с `ws-link/1` и `panel-link/1`. Если у какой-то ноды их нет, панель отказывается включать хост и показывает такие ноды с пометкой *обнови агент*. Сначала обновите их ([Обновления](../operations/updates.md)).
- **DNS-запись.** A-запись поддомена на адрес ноды и AAAA-запись, если у ноды есть IPv6. Перед включением панель проверяет записи.
- Нода-хост должна быть в сети и не выведена из работы.

## Новая панель дома

1. Установите панель без `--public-url`, с админкой на локальном адресе:

   ```sh
   mistgate setup --admin-listen 127.0.0.1:8081
   ```

   Админка открывается по `http://localhost:8081/` на этой машине или через SSH-туннель. Остальные шаги — в [Установке панели](../getting-started/install-panel.md).
2. Создайте A-запись поддомена (и AAAA, если у ноды есть IPv6) на сервер, который станет первой нодой.
3. Откройте **Ноды → Добавить ноду** и установите ноду по SSH ([Установка ноды по SSH](../getting-started/ssh-install.md)). На шаге с данными ноды отметьте **Эта нода — хост подписок** и укажите **Поддомен**.

   До этого момента нода не может достучаться до панели за NAT, поэтому панель регистрирует её прямо в SSH-сессии. Когда нода заработает, панель перенесёт адрес подписки на поддомен. Если запись ещё не указывает на ноду, установка остановится с ошибкой DNS. **Всё равно продолжить** продолжает без проверки, например при проксируемом DNS.

## Включение на работающей панели

Откройте **Настройки → Домены**, карточку **Хост подписок**:

1. Выберите **Ноду** и укажите **Поддомен**.
2. **Проверить запись** показывает, куда домен ведёт сейчас и куда должен вести.
3. Нажмите **Включить**. Если запись не указывает на ноду, панель откажет и предложит **Всё равно сохранить**. Пользуйтесь этим, только если уверены в записи, например за DNS-прокси.

Панель переключается на ходу, без перезапуска. Агенты получают новый адрес связи по текущему соединению. Каждый держит старый адрес, пока не подключится по новому. Строка **Основа ссылок подписки** после этого помечена *через хост подписок*.

Пока хост включён, карточка показывает домен, ноду, состояние туннеля (*туннель работает* или *туннель не работает*, и с какого момента) и CAA-запись. Если туннель долго не работает, панель записывает событие `sub_host_tunnel_down`, а когда он восстанавливается — `sub_host_tunnel_up`.

## CAA-запись

Карточка показывает CAA-запись, по которой сертификаты для домена может получать только аккаунт этой панели. Опубликуйте её в DNS. Строка под ней говорит, есть ли она в DNS: *Опубликована в DNS*, *В DNS её пока нет*, *Появится, когда у панели будет аккаунт для сертификатов* или *Не удалось проверить DNS*.

## Перенос на другую ноду

Перенос и отключение идут в две фазы, и каждую вы завершаете сами.

1. В разделе **Перенести на другую ноду** выберите ноду и нажмите **Начать перенос**. Новая нода получает свой туннель, и карточка показывает оба.
2. Смените A-запись (и AAAA) домена на адрес новой ноды. Карточка показывает, куда запись ведёт сейчас.
3. Когда запись указывает на новую ноду и её туннель работает, нажмите **Завершить**. **Отменить** отменяет перенос, и хост остаётся на прежней ноде.

## Отключение

1. В поле **Адрес, на который вернётся панель** укажите `https://хост[:порт]`. Оставьте пустым, если у панели нет своего публичного адреса.
2. Нажмите **Отключить**. Панель возвращается на этот адрес, и агенты переносят связь туда.
3. Карточка показывает ноды, которые **Ещё не перешли на новый адрес**. Когда список опустеет, нажмите **Завершить**. Если какие-то ноды так и не перешли, панель спросит, завершить ли всё равно. Эти ноды потеряют панель, пока не получат её новый адрес (см. [Ноды, которые были не в сети](#ноды-которые-были-не-в-сети)). **Отменить** оставляет хост включённым.

## Перенос публичной панели домой

1. На публичной панели включите хост подписок, как описано выше, чтобы люди и агенты пользовались поддоменом.
2. Дождитесь, пока ни одна нода не будет ходить на собственный адрес панели: тогда всё идёт через поддомен.
3. Сделайте [зашифрованный бэкап](../operations/backups.md).
4. Дома восстановите его в новый каталог данных командой `mistgate backup restore` ([восстановление на новой панели](../operations/backups.md)).
5. Перенесите админку на локальный адрес и запустите панель с тем же флагом:

   ```sh
   mistgate admin-address --admin-listen 127.0.0.1:8081 --data-dir NEW-DIR
   ```

6. Остановите старую панель. Домашняя панель подключается к хосту, и ноды доходят до неё через туннель.

Passkey привязаны к адресу админки и на новом адресе перестают работать. Войдите по паролю и коду из приложения-аутентификатора, затем добавьте passkey заново ([Безопасность](../operations/security.md)).

## Ноды, которые были не в сети

Нода, которая была не в сети во время смены адреса, не получила новый адрес связи. Выполните на ней:

```sh
mistgate-node set-panel --link-url wss://sub.example.com/<secret-prefix>/
systemctl restart mistgate-node
```

Агент по очереди пробует новый и текущий адрес и оставляет новый, как только сессия через него состоится ([CLI](../reference/cli.md)).

## MCP

Токен профиля «Админ» читает состояние через `subscription_host_get`. Менять хост он может через `subscription_host_set`, `subscription_host_move` (`start`, `finish`, `cancel`) и `subscription_host_disable`. Каждое изменение — это план, который владелец одобряет со свежим входом. Для первого хоста `node_install` принимает `subscription_host_domain` и `skip_dns_check`. См. [MCP](../reference/mcp.md).
