![Предложение поставить профиль рядом с другим на порту 443, затем карточка общего порта со счётчиками](../../images/readme/shared-dark-en.webp)

Многие сети пропускают только TCP 443. На нём нода может держать сразу несколько TCP-сервисов: VLESS REALITY, VLESS по TLS, TrustTunnel и MTProto. Агент ноды читает **имя**, которое клиент называет в первых байтах соединения (SNI, имя хоста в TLS-приветствии), и передаёт соединение сервису, который это имя занимает. По дороге ничего не расшифровывается, а сам фронт никому ничего не отвечает. На этой странице: кто может делить порт, что видит посторонний, что нужно подготовить (имя и DNS-запись для каждого сервиса) и как это настроить.

![Один TCP 443, несколько сервисов](../diagrams/shared-443.svg)

Если на порту один сервис, всё работает как раньше: дополнительный слушатель агент поднимает, только когда на одном TCP-порту стоят два сервиса или больше.

## Кто может делить порт

| Сервис | Имя, на которое он отвечает | На общем порту |
|:--|:--|:--|
| VLESS REALITY, сайт ноды | **Домен (SNI)** сервера, по умолчанию имя ноды | Да. Показывает собственный сайт ноды, поэтому может быть сервисом по умолчанию |
| VLESS REALITY, чужой сайт | Имена этого сайта (**Имена сервера** или хост цели) | Да, если другой сервис показывает сайт ноды. Пришедший с этим именем увидит чужой сайт |
| VLESS по TLS (XHTTP, WebSocket) | **Домен (SNI)**, а за CDN ещё и хост CDN | Да. Показывает сайт ноды |
| TrustTunnel, HTTP/2 | **Домен (SNI)** | Да. Показывает сайт ноды |
| MTProto, **Имя этой ноды** | Его домен: имя ноды или **Домен (SNI)** | Да. Показывает собственную заглушку ноды |
| MTProto, **Другой сайт** | Домен этого сайта | Да, если другой сервис показывает сайт ноды. Пришедший с этим именем увидит чужой сайт |
| Hysteria2, его HTTPS-сайт на TCP | Нет | Нет. Сайт по-прежнему уступает свой TCP-порт любому TCP-профилю: [VLESS и Hysteria2 на одной ноде](vless-and-hysteria2.md) |
| Hysteria2, AmneziaWG, TrustTunnel с HTTP/3 | Нет (UDP) | Нет. UDP-порт не делится никогда: TrustTunnel с HTTP/3 рядом с Hysteria2 на UDP 443 по-прежнему нельзя |

Что панель проверяет при сохранении:

- **У каждого сервиса своё имя.** Панель сравнивает имена точно, в нижнем регистре, без точки на конце. Одно имя у двух сервисов — отказ (`sni_taken`). Выключенные профили тоже учитываются, чтобы включение такого профиля потом не сломало порт. Имя — это имя хоста латиницей, с точкой, без `*` и не IP-адрес: клиент никогда не кладёт IP-адрес в SNI. Сервис, у которого такого имени нет (например, REALITY с чужим сайтом, чья цель — IP-адрес, и без **Имён сервера**), порт делить не может (`share_unsupported`).
- **Хотя бы один сервис показывает сайт ноды.** Из таких сервис с наименьшим id становится сервисом **по умолчанию**: он получает всех, кто не назвал сервис. Два сервиса, которые оба показывают чужой сайт, порт делить не могут (`share_needs_site`).
- **Участвуют только VLESS, TrustTunnel и MTProto.** Вход ретрансляции и мост — не сервисы порта: их порты панель считает как раньше.
- **Агент должен объявлять `tcp-share/1`.** Что делает старый агент, написано ниже в разделе «Что происходит на ноде».

## Что видит приходящий

| Что прислал приходящий | Кто отвечает |
|:--|:--|
| Имя сервиса | Этот сервис, как будто он один на порту |
| Без имени (проверка по IP-адресу) или с именем, которое никто не занимает | Сервис по умолчанию, сайт ноды |
| Не TLS (обычный запрос `http://`, мусор), битое приветствие, приветствие больше 16 КиБ | Сервис по умолчанию, вместе с байтами, которые уже пришли |
| Имя сервиса, который не запущен или не берёт соединение 5 секунд (он перезапускается) | Сервис по умолчанию |
| Нет полного приветствия за 10 секунд | Соединение закрывается |

Сервисы видят настоящий адрес пришедшего, а не `127.0.0.1`: соединение передаётся внутри агента, без протокола PROXY.

Для ваших сервисов с вашими именами порт выглядит как обычный хост с несколькими сайтами. Сервис, который показывает чужой сайт, даёт два лица: пришедший с его именем видит тот сайт, пришедший без имени — сайт сервиса по умолчанию, и тот, кто переберёт много имён, отличит одно от другого. Панель предупреждает об этом (`share_two_faces`).

## Имена, DNS-записи и сертификаты

Каждому сервису на порту нужно имя, которое ведёт на ноду. Панель предлагает `<слово>.<адрес ноды>`: первое из `cdn`, `static`, `media`, `assets`, `files`, `img`, `edge`, `app`, которое не занято, то есть нейтральное имя обычного сайта. Ноде, известной по IP-адресу, предложения нет: впишите домен, которым вы управляете. Существующие сервисы свои имена сохраняют, поэтому ссылки `tg://` и подписки не меняются.

Рядом с именем панель показывает DNS-запись: тип, имя и значение, с кнопкой **Копировать запись**. Добавьте её там, где хранится DNS домена, **без проксирования** (на Cloudflare — серое облако):

| Запись | Когда |
|:--|:--|
| `A` | Нода известна по IPv4-адресу: значение — этот адрес |
| `CNAME` | Нода известна по имени хоста: значение — это имя. Если ваш DNS не принимает здесь CNAME, поставьте запись `A` с IPv4-адресом ноды |
| `AAAA` | Нода известна по IPv6-адресу |

Панель запись не ищет и её не ждёт: вы добавляете запись, а сертификат для имени нода запросит у Let's Encrypt сама, когда имя начнёт вести на неё. Пока его нет, сервис показывает то, что написано на его странице про ещё не выданный сертификат. Let's Encrypt проверяет и по TCP 443 (TLS-ALPN-01), и по TCP 80: запрос на имя сервиса попадает к этому сервису, а запрос на любое другое имя ноды — к сервису по умолчанию, который на него отвечает. Достаточно, чтобы имя было без проксирования и вело на ноду.

Каждое новое имя — это сертификат. Let's Encrypt ограничивает новые сертификаты на зарегистрированный домен (около 50 в неделю) и записывает каждый в публичные журналы сертификатов, поэтому держите имена нейтральными и немногочисленными.

## Поставить сервис рядом с другим

### В админке

1. На вкладке **Профили** ноды выберите **Добавить профиль**, или **Изменить** у сервера, или нажмите **Поставить на ноды** на странице профиля. Выберите порт, который уже занимает другой сервис (443).
2. Панель проверяет выбор (см. [Профили](profiles.md)). Новый сервис обычно начинает с имени самой ноды, а оно у первого сервиса уже занято, поэтому панель отвечает, что имя занято (`sni_taken`). Если порт можно делить, ответ такой: **Поставить рядом с «Main» на порту 443**, поле с предложенным именем и кнопка **Поставить рядом на 443**, а рядом — **Взять 8443**, старый выход. У сервиса, который показывает чужой сайт, своего имени нет, поэтому он получает только отказ. Сервис со свободным именем не получает отказа вовсе: диалог просто говорит, что порт общий (шаг 3).
3. **Поставить рядом на 443** записывает имя в поле **Домен (SNI)** и запускает проверку заново. Если она проходит (или имя было свободным с самого начала), диалог говорит, кто перезапустится (сервис, который стоял на порту один; его открытые соединения переподключатся), на какое имя отвечает новый сервис, и показывает DNS-запись.
4. Добавьте запись, затем нажмите **Добавить** или **Сохранить**.

Предупреждения, которые можно увидеть до нажатия: `tcp_port_shared` (порт общий, кто по умолчанию, кто перезапустится) и `share_two_faces`. Отказы: `sni_taken`, `share_needs_site`, `share_unsupported` и `share_agent_old`; диалог объясняет каждый и предлагает свободный порт, если он есть.

### Через MCP

`profile_create` и `profile_deploy` принимают `sni_overrides` — соответствие «id ноды → имя, которое получит новый сервер на этой ноде» — рядом с `port_overrides`. Назвать можно только выбранные ноды, а имя должно быть именем хоста с точкой, не IP-адресом. План показывает порт, `sni` и предупреждения — ту же проверку, что и диалог; отказ приходит как `sni_taken: name=de1.example.com&node=de1&port=443&profile=Main&share=1&suggest=cdn.de1.example.com`, а `suggest` есть, когда у ноды есть домен. План не называет DNS-запись и не проверяет её: скажите владельцу, какую запись добавить. Для применения нужно одобрение владельца, как для любого изменения профиля. В MCP нет инструмента, который меняет порт или **Домен (SNI)** одного сервера, уже стоящего на ноде; это делается в админке. См. [MCP](../reference/mcp.md).

## Карточка общего порта

Когда на одном TCP-порту стоят два сервиса или больше, на вкладке **Профили** ноды появляется карточка **TCP 443: общий порт**. У каждого сервиса своя строка: профиль, имя и сколько соединений он получил; пометка **По умолчанию** показывает сервис по умолчанию. Под строками — счётчики, которые агент ведёт с запуска:

| Счётчик | Что считает |
|:--|:--|
| **Принято** | Соединения, которые принял порт |
| **Ушло по умолчанию** | Пришедшие без имени, с неизвестным именем, не по TLS, с битым или слишком большим приветствием, а также те, чей сервис лежал |
| **Отказано** | Закрыто, потому что сервис не принял соединение вовремя или отправить его было некуда |
| **Сервис лежал** | Имя принадлежало сервису, который не работал: пришедший ушёл к сервису по умолчанию |
| **Молчали 10 с** | Ничего не прислали за 10 секунд и были закрыты |
| **Вытеснено** | Незаконченные рукопожатия, сброшенные, чтобы освободить место, когда порт засыпали |

«Отказано», «Сервис лежал» и «Вытеснено» желтеют, когда больше нуля. Под счётчиками — до пяти самых частых имён, которые просили пришедшие и которые никто не занимает (только имена хостов, без адресов), и время последнего отчёта агента. Агент присылает снимок со своей статистикой, а панель записывает его, когда меняется состав порта, и не реже чем раз в 5 минут, поэтому счётчики отстают на несколько минут. Порт, о котором агент ещё не сообщал, карточка так и называет.

Засыпание незаконченными рукопожатиями — это ещё и событие `front_overloaded`, не чаще раза в час на ноду. Сервисы порта продолжают работать; агент сбрасывает самые старые незаконченные соединения.

## Что происходит на ноде

- **Перезапуски.** Порт становится общим или перестаёт им быть — сервисы, которые стояли на нём одни, перезапускаются: их открытые соединения переподключатся. Когда к порту, где уже два сервиса или больше, добавляется ещё один, запускается только новый. Когда один сервис уходит и остаётся один, перезапускается оставшийся. Перезапуск агента перезапускает все сервисы, общий порт или нет. Пришедшие к перезапускающемуся сервису ждут до 5 секунд, потом уходят к сервису по умолчанию.
- **Старый агент.** Агент без `tcp-share/1` порт делить не умеет. Если возможности ноды известны, сохранить второй сервис на порту не дадут (`share_agent_old`). Ноду, которая ещё не сообщала о себе, не отказывают: при развёртывании панель отправляет старому агенту только сервис по умолчанию, а остальные остаются неотправленными с пометкой `share_agent_old`. Карточка пишет **Эта нода пока не умеет делить порт** и показывает кнопку **Открыть обновления**. После обновления они запустятся сами.
- **Порт занят другой программой.** Агент не может его взять, ни один сервис порта не работает, а карточка пишет **Нода не смогла занять порт 443** и ошибку. Агент пробует снова сам.
- **Имена потом совпали.** Например, вы сменили адрес ноды, и имя, построенное от него, теперь равно имени другого сервиса. Одно имя остаётся у одного, второй не запускается и пишет `sni_shadowed`. Задайте ему своё имя.
- **Сервис упал.** Его имя уходит к сервису по умолчанию, пока он снова не заработает; остальные не затронуты.

## Ограничения

- Имена сравниваются точно. Масок нет, а одно имя не может вести к двум сервисам: цепочка вроде REALITY, потом MTProto, потом сайт не строится.
- Фронт не ограничивает по адресу пришедшего: за ретрансляцией, мостом или мобильной сетью много людей сидят на одном адресе. Он держит не больше 1024 незаконченных рукопожатий на порт и сбрасывает самые старые, а приветствие читает до 16 КиБ.
- Нода, известная только по IP-адресу, порт делить не может: для своего имени нужен домен.
- UDP не делится. Hysteria2 и AmneziaWG держат свои UDP-порты; HTTP/3 у TrustTunnel нужен свой UDP-порт.
- Счётчики обнуляются при перезапуске агента.
