Mistgate выпускается в ранних версиях; текущая — `v0.1.32`. Автор использует его в работе, но до 1.0 API, хранимые настройки и протокол ноды ещё могут меняться. Остальная документация описывает только то, что код умеет сегодня.

## Готово

### Флот

- Панель и агент ноды, которые общаются по взаимному TLS; нода подключается по одноразовому токену, входящий порт управления ей не нужен. См. [Архитектуру](../reference/architecture.md).
- [Hysteria2](../guide/hysteria2.md) на официальном ядре с Salamander и [AmneziaWG](../guide/amneziawg.md) 2.0 и 3.1 в userspace или модулем ядра, несколько профилей на ноду.
- [Выход через WARP](../guide/warp.md), который закрывается, если связь с WARP пропала.
- Одна [ссылка подписки](../guide/subscriptions.md) на человека с форматом под каждое приложение, [страница пользователя](../guide/user-page.md) и [DNS-пресеты](../guide/dns.md).
- [Здоровье](../operations/health.md): проверки глазами клиента, доктор нод с безопасными исправлениями и алерты.
- [Защита от торрентов](../guide/torrent-protection.md) на каждой ноде.

### Установка и восстановление

- [Установка по SSH](../getting-started/ssh-install.md) из админки и через MCP с одобрением владельца: root или `sudo -n`, закреплённый host key, проверки до любых изменений, подготовка firewall сервера.
- Задания установки, которые можно отменить, повторить и продолжить после обрыва.
- Сохранённый SSH-доступ, зашифрованный, с проверенной сменой пароля; доступ переживает вывод ноды, пока владелец его не забудет.
- [Зашифрованные бэкапы](../operations/backups.md) в Cloudflare R2 по расписанию, со сроком хранения и паузами после ошибок, и офлайн-восстановление.
- [Алерты в Telegram](../operations/telegram-alerts.md): алерты здоровья, новые версии, сбои бэкапа, планы, ждущие решения, и безопасность входа приходят админам, которые привязали чат.

### Обновления

- [Подписанные обновления агентов нод](../operations/updates.md) по одной ноде, сейчас или по расписанию, с проверкой здоровья и автоматическим откатом; подписанные пакеты сами скачиваются с GitHub.
- Самообновление панели из подписанных релизов GitHub с откатом, если новая панель не удержалась.
- Воспроизводимые релизы, подписанные офлайн из тега: см. [Релизы и подпись](../operations/releases.md).

### Доступ

- Админка на русском и английском; вход по passkey или паролю с кодом из приложения-аутентификатора, по желанию Cloudflare Turnstile, журнал аудита. См. [Безопасность](../operations/security.md).
- [API-токены](../reference/api.md) с профилями readonly, operator и admin и [MCP-сервер](../reference/mcp.md) со схемой «план → применить» и одобрениями владельца; готовые промпты — в [инструкции для AI-агента](../getting-started/ai-agents.md).

## Сейчас

- Проверка текущих релизов в боевой работе: защита от торрентов, установка по SSH и восстановление, подписанные релизы панели и нод.
- VLESS REALITY с RAW + Vision и с XHTTP: движок на ноде (на xray-core) уже в основной ветке; профили и подписки VLESS в панели: **Планируется**.
- Бесплатная версия панели, которая работает на Cloudflare Workers: в разработке, в релизы пока не входит.

## Дальше

- Telegram-бот сверх алертов: для флота и для пользователей.
- Новые форматы подписок (Xray JSON, sing-box) и зеркала подписок.
- Установка одной командой.

## Известные ограничения

- Установка по SSH входит только по паролю; вход по ключу не поддерживается. Для таких серверов используйте [ручную установку](../getting-started/add-node.md).
- API-токены и MCP не умеют создавать профили и группы и ставить профиль на ноду: это делает владелец в админке.
- Бэкапы идут только в Cloudflare R2, а восстановление — шаг в командной строке в новый каталог данных.
- Панель не создаёт аккаунт Cloudflare, бакет или токен: вы даёте токен на один бакет с правами на чтение, запись и удаление.
- Часть настроек по умолчанию рассчитана на пользователей в России (Яндекс DNS для нод в России, контрольные домены доктора, пресеты split-DNS); всё это меняется в настройках.
